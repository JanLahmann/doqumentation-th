อัลกอริทึมของ Simon

อัลกอริทึมของ Simon คืออัลกอริทึม query เชิงควอนตัมสำหรับปัญหาที่เรียกว่า ปัญหาของ Simon นี่เป็น promise problem ที่มีรสชาติคล้ายกับปัญหา Deutsch-Jozsa และ Bernstein-Vazirani แต่มีรายละเอียดที่แตกต่างกัน

อัลกอริทึมของ Simon มีความสำคัญเพราะให้ข้อได้เปรียบแบบ exponential ของควอนตัมเหนืออัลกอริทึมคลาสสิก (รวมถึง probabilistic) และเทคนิคที่ใช้เป็นแรงบันดาลใจให้ Peter Shor ค้นพบอัลกอริทึมควอนตัมที่มีประสิทธิภาพสำหรับการแยกตัวประกอบจำนวนเต็ม

ปัญหาของ Simon​

ฟังก์ชันอินพุตสำหรับปัญหาของ Simon อยู่ในรูปแบบ

f:Σn→Σmf:\Sigma^n \rightarrow \Sigma^mf:Σn→Σm

สำหรับจำนวนเต็มบวก nnn และ mmm เราอาจจำกัดความสนใจไว้ที่กรณี m=nm = nm=n เพื่อความเรียบง่าย แต่ไม่ได้ให้ประโยชน์มากในการตั้งสมมติฐานนี้ — อัลกอริทึมของ Simon และการวิเคราะห์ก็เหมือนกันไม่ว่าจะเป็นแบบใด

ปัญหาของ Simon

อินพุต: ฟังก์ชัน f:Σn→Σmf:\Sigma^n \rightarrow \Sigma^mf:Σn→Σm
Promise: มีสตริง s∈Σns\in\Sigma^ns∈Σn ที่ [f(x)=f(y)]⇔[(x=y)∨(x⊕s=y)][f(x) = f(y)] \Leftrightarrow [(x = y) \vee (x \oplus s = y)][f(x)=f(y)]⇔[(x=y)∨(x⊕s=y)] สำหรับทุก x,y∈Σnx,y\in\Sigma^nx,y∈Σn
เอาต์พุต: สตริง sss

เราจะอธิบาย promise อย่างละเอียดเพื่อทำความเข้าใจสิ่งที่มันบอกในไม่ช้า แต่ก่อนอื่นขอยืนยันว่ามันกำหนดให้ fff มีโครงสร้างพิเศษมาก — ดังนั้นฟังก์ชันส่วนใหญ่จะไม่ตอบสนอง promise นี้ นอกจากนี้ยังเหมาะสมที่จะรับรู้ว่าปัญหานี้ไม่ได้มีความสำคัญในทางปฏิบัติ แต่มันเป็นปัญหาที่ถูกสร้างขึ้นอย่างประดิษฐ์บางส่วน ออกแบบมาเพื่อให้คอมพิวเตอร์ควอนตัมทำได้ง่ายและคอมพิวเตอร์คลาสสิกทำได้ยาก

มีสองกรณีหลัก: กรณีแรกคือ sss เป็นสตริงที่มีแต่ศูนย์ 0n0^n0n และกรณีที่สองคือ sss ไม่ใช่สตริงที่มีแต่ศูนย์

  • กรณีที่ 1: s=0ns=0^ns=0n ถ้า sss เป็นสตริงที่มีแต่ศูนย์ เราสามารถลดรูปข้อความ if and only if ใน promise เพื่อให้อ่านว่า [f(x)=f(y)]⇔[x=y][f(x) = f(y)] \Leftrightarrow [x = y][f(x)=f(y)]⇔[x=y] ซึ่งเทียบเท่ากับ fff เป็นฟังก์ชันแบบ one-to-one

  • กรณีที่ 2: s≠0ns\neq 0^ns=0n ถ้า sss ไม่ใช่สตริงที่มีแต่ศูนย์ promise ที่ถูกตอบสนองสำหรับสตริงนี้บ่งชี้ว่า fff เป็น two-to-one หมายความว่าสำหรับทุกสตริงเอาต์พุตที่เป็นไปได้ของ fff มีสตริงอินพุตสองตัวที่ทำให้ fff แสดงผลสตริงนั้น นอกจากนี้ สองสตริงอินพุตนี้ต้องอยู่ในรูปแบบ www และ w⊕sw \oplus sw⊕s สำหรับสตริงบางตัว www

สำคัญมากที่ต้องตระหนักว่ามีเพียงสตริง sss เดียวที่ใช้ได้ถ้า promise ถูกปฏิบัติตาม ดังนั้นจึงมีคำตอบที่ถูกต้องเพียงหนึ่งเดียวสำหรับฟังก์ชันที่ตอบสนอง promise เสมอ

คำอธิบายอัลกอริทึม​

นี่คือแผนภาพวงจรควอนตัมที่แสดงอัลกอริทึมของ Simon

ชัดเจนว่ามี nnn Qubit อยู่ด้านบนที่ถูกกระทำโดย Hadamard Gate และ mmm Qubit อยู่ด้านล่างที่เข้าสู่ query gate โดยตรง มันดูคล้ายมากกับอัลกอริทึมที่เราพูดถึงแล้วในบทเรียน แต่คราวนี้ไม่มี phase kickback; mmm Qubit ล่างทั้งหมดเข้าสู่ query gate ในสถานะ ∣0⟩\vert 0\rangle∣0⟩

การแก้ปัญหาของ Simon โดยใช้วงจรนี้จะต้องใช้หลายรอบอิสระตามด้วยขั้นตอนการประมวลผลหลังคลาสสิก ซึ่งจะอธิบายในภายหลังหลังจากวิเคราะห์พฤติกรรมของวงจรแล้ว

  • กรณีที่ 1: s=0ns = 0^ns=0n ในกรณีนี้ฟังก์ชัน fff เป็น one-to-one ดังนั้นมีสตริง z∈range⁡(f)z\in\operatorname{range}(f)z∈range(f) จำนวน 2n2^n2n ตัว และเราได้

การประมวลผลหลังคลาสสิก​

ตอนนี้เรารู้แล้วว่าความน่าจะเป็นเป็นอย่างไรสำหรับผลการวัดที่เป็นไปได้เมื่อเรารันวงจรควอนตัมสำหรับอัลกอริทึมของ Simon ข้อมูลนี้เพียงพอที่จะหาค่า sss หรือไม่?

คำตอบคือใช่ ตราบใดที่เรายินดีที่จะทำซ้ำกระบวนการหลายครั้งและยอมรับว่ามันอาจล้มเหลวด้วยความน่าจะเป็นบางอย่าง ซึ่งเราสามารถทำให้น้อยมากได้โดยการรันวงจรให้มากพอ ความคิดสำคัญคือแต่ละครั้งที่รันวงจรให้หลักฐานทางสถิติเกี่ยวกับ sss แก่เรา และเราสามารถใช้หลักฐานนั้นเพื่อหาค่า sss ด้วยความน่าจะเป็นสูงมากถ้าเรารันวงจรให้มากพอ

สมมติว่าเรารันวงจรอิสระ kkk ครั้ง สำหรับ k=n+10k = n + 10k=n+10 ไม่มีอะไรพิเศษเกี่ยวกับจำนวนการวนซ้ำนี้ — เราอาจเลือก kkk ให้มากขึ้น (หรือน้อยลง) ขึ้นอยู่กับความน่าจะเป็นของความล้มเหลวที่เรายอมรับได้ ดังที่เราจะเห็น การเลือก k=n+10k = n + 10k=n+10 จะทำให้มั่นใจได้ว่าเรามีโอกาสมากกว่า 99.999.999.9% ในการกู้คืน sss

โดยการรันวงจร kkk ครั้ง เราได้สตริง y1,...,yk∈Σny^1,...,y^{k} \in \Sigma^ny1,...,yk∈Σn ชัดเจนว่า superscript ที่นี่เป็นส่วนหนึ่งของชื่อของสตริงเหล่านี้ ไม่ใช่เลขชี้กำลังหรือดัชนีของบิต ดังนั้นเรามี

y1=yn−11⋯y01y2=yn−12⋯y02    ⋮yk=yn−1k⋯y0k\begin{aligned} y^1 & = y^1_{n-1} \cdots y^1_{0}\\[1mm] y^2 & = y^2_{n-1} \cdots y^2_{0}\\[1mm] & \;\; \vdots\\[1mm] y^{k} & = y^{k}_{n-1} \cdots y^{k}_{0} \end{aligned}y1y2yk​=yn−11​⋯y01​=yn−12​⋯y02​⋮=yn−1k​⋯y0k​​

ตอนนี้เราสร้างเมทริกซ์ MMM ที่มี kkk แถวและ nnn คอลัมน์โดยนำบิตของสตริงเหล่านี้เป็นสมาชิกค่าไบนารี

M=(yn−11⋯y01yn−12⋯y02⋮⋱⋮yn−1k⋯y0k)M = \begin{pmatrix} y^1_{n-1} & \cdots & y^1_{0}\\[1mm] y^2_{n-1} & \cdots & y^2_{0}\\[1mm] \vdots & \ddots & \vdots \\[1mm] y^{k}_{n-1} & \cdots & y^{k}_{0} \end{pmatrix}M=​yn−11​yn−12​⋮yn−1k​​⋯⋯⋱⋯​y01​y02​⋮y0k​​​

ตอนนี้เราไม่รู้ว่า sss คืออะไร — เป้าหมายของเราคือการหาสตริงนี้ แต่จินตนาการสักครู่ว่าเรารู้สตริง sss และเราสร้างเวกเตอร์คอลัมน์ vvv จากบิตของสตริง s=sn−1⋯s0s = s_{n-1} \cdots s_0s=sn−1​⋯s0​ ดังนี้

v=(sn−1⋮s0)v = \begin{pmatrix} s_{n-1}\\ \vdots\\ s_0 \end{pmatrix}v=​sn−1​⋮s0​​​

ถ้าเราทำการคูณเวกเตอร์เมทริกซ์ MvM vMv แบบโมดูลัส 222 — หมายความว่าเราทำการคูณตามปกติแล้วนำเศษของสมาชิกของผลลัพธ์หลังหารด้วย 222 — เราจะได้เวกเตอร์ที่มีแต่ศูนย์

Mv=(y1⋅sy2⋅s⋮yk⋅s)=(00⋮0)M v = \begin{pmatrix} y^1 \cdot s\\ y^2 \cdot s\\ \vdots\\[1mm] y^{k} \cdot s \end{pmatrix} = \begin{pmatrix} 0\\ 0\\ \vdots\\[1mm] 0 \end{pmatrix}Mv=​y1⋅sy2⋅s⋮yk⋅s​​=​00⋮0​​

กล่าวคือ เมื่อถือเป็นเวกเตอร์คอลัมน์ vvv ตามที่อธิบายไว้ สตริง sss จะเป็นสมาชิกของ null space ของเมทริกซ์ MMM เสมอ ตราบใดที่เราทำเลขคณิตแบบโมดูลัส 222 สิ่งนี้เป็นจริงทั้งในกรณีที่ s=0ns = 0^ns=0n และ s≠0ns\neq 0^ns=0n พูดอย่างแม่นยำมากขึ้น เวกเตอร์ที่มีแต่ศูนย์อยู่ใน null space ของ MMM เสมอ และมีเวกเตอร์ที่มีสมาชิกเป็นบิตของ sss ร่วมด้วยในกรณีที่ s≠0ns\neq 0^ns=0n

คำถามที่เหลืออยู่คือจะมีเวกเตอร์อื่น ๆ ใน null space ของ MMM นอกจากเวกเตอร์ที่สอดคล้องกับ 0n0^n0n และ sss หรือไม่ คำตอบคือสิ่งนี้มีโอกาสน้อยลงเรื่อย ๆ เมื่อ kkk เพิ่มขึ้น — และถ้าเราเลือก k=n+10k = n + 10k=n+10 null space ของ MMM จะไม่มีเวกเตอร์อื่นนอกจากที่สอดคล้องกับ 0n0^n0n และ sss ด้วยโอกาสมากกว่า 99.999.999.9% โดยทั่วไป ถ้าเราแทน k=n+10k = n + 10k=n+10 ด้วย k=n+rk = n + rk=n+r สำหรับการเลือกจำนวนเต็มบวก rrr ใด ๆ ความน่าจะเป็นที่เวกเตอร์ที่สอดคล้องกับ 0n0^n0n และ sss อยู่คนเดียวใน null space ของ MMM มีค่าอย่างน้อย 1−2−r1 - 2^{-r}1−2−r

โดยใช้พีชคณิตเชิงเส้น เป็นไปได้ที่จะคำนวณคำอธิบายของ null space ของ MMM แบบโมดูลัส 222 ได้อย่างมีประสิทธิภาพ โดยเฉพาะ สามารถทำได้โดยใช้ Gaussian elimination ซึ่งทำงานในลักษณะเดียวกันเมื่อทำเลขคณิตแบบโมดูลัส 222 เหมือนกับเมื่อใช้จำนวนจริงหรือจำนวนเชิงซ้อน ตราบใดที่เวกเตอร์ที่สอดคล้องกับ 0n0^n0n และ sss อยู่คนเดียวใน null space ของ MMM ซึ่งเกิดขึ้นด้วยความน่าจะเป็นสูง เราสามารถหาค่า sss จากผลของการคำนวณนี้

ความยากของคลาสสิก​

อัลกอริทึม query คลาสสิก ต้องการ query กี่ครั้งเพื่อแก้ปัญหาของ Simon? คำตอบคือ: มาก โดยทั่วไป

มีข้อความที่แม่นยำที่แตกต่างกันที่สามารถกล่าวเกี่ยวกับความยากของคลาสสิกของปัญหานี้ และนี่คือหนึ่งในนั้น ถ้าเรามีอัลกอริทึม query แบบ probabilistic ใด ๆ และอัลกอริทึมนั้นทำ query น้อยกว่า 2n/2−1−12^{n/2 - 1} - 12n/2−1−1 ครั้ง ซึ่งเป็นจำนวน query ที่เป็น exponential ใน nnn ดังนั้นอัลกอริทึมนั้นจะล้มเหลวในการแก้ปัญหาของ Simon ด้วยความน่าจะเป็นอย่างน้อย 1/21/21/2

บางครั้ง การพิสูจน์ผลลัพธ์ด้านความเป็นไปไม่ได้เช่นนี้อาจเป็นเรื่องที่ท้าทายมาก แต่อันนี้ไม่ยากเกินไปที่จะพิสูจน์ผ่านการวิเคราะห์ความน่าจะเป็นเบื้องต้น อย่างไรก็ตาม ที่นี่เราจะตรวจสอบแค่สัญชาตญาณพื้นฐานเท่านั้น

เรากำลังพยายามหาสตริงที่ซ่อนอยู่ sss แต่ตราบใดที่เราไม่ทำ query ฟังก์ชันบนสองสตริงที่มีค่าเอาต์พุตเดิม เราจะได้ข้อมูลเกี่ยวกับ sss น้อยมาก พูดอย่างสัญชาตญาณ สิ่งที่เราจะเรียนรู้คือสตริงที่ซ่อนอยู่ sss ไม่ใช่ exclusive-OR ของสองสตริงที่แตกต่างกันที่เราทำ query และถ้าเราทำ query น้อยกว่า 2n/2−1−12^{n/2 - 1} - 12n/2−1−1 สตริง ยังคงมีทางเลือกมากมายสำหรับ sss ที่เรายังไม่ได้ตัดออก เพราะไม่มีคู่สตริงเพียงพอสำหรับทำสิ่งนี้ นี่ไม่ใช่การพิสูจน์อย่างเป็นทางการ มันแค่เป็นความคิดพื้นฐาน

ดังนั้น โดยสรุป อัลกอริทึมของ Simon ให้ข้อได้เปรียบที่โดดเด่นของควอนตัมเหนืออัลกอริทึมคลาสสิกภายในโมเดล query โดยเฉพาะอย่างยิ่ง อัลกอริทึมของ Simon แก้ปัญหาของ Simon ด้วยจำนวน query ที่เป็น linear ในจำนวนบิตอินพุต nnn ของฟังก์ชันเรา ในขณะที่อัลกอริทึมคลาสสิกใด ๆ แม้แต่ probabilistic ต้องทำ query จำนวนที่เป็น exponential ใน nnn เพื่อแก้ปัญหาของ Simon ด้วยความน่าจะเป็นของความสำเร็จที่เหมาะสม
