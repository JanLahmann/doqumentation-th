Classical linear codes​

โค้ดแก้ไขข้อผิดพลาดแบบคลาสสิกได้รับการศึกษาครั้งแรกในทศวรรษ 1940 และปัจจุบันรู้จักโค้ดจำนวนมาก โดยโค้ดที่ศึกษาและใช้กันมากที่สุดอยู่ในหมวดหมู่ที่เรียกว่า linear codes เราจะเห็นในอีกสักครู่ว่าคำว่า "linear" หมายถึงอะไรในบริบทนี้ แต่วิธีง่าย ๆ ในการอธิบาย linear codes ณ จุดนี้คือ พวกมันคือ stabilizer codes ที่บังเอิญเป็นแบบคลาสสิก CSS codes โดยพื้นฐานแล้วคือ คู่ ของ classical linear codes ที่รวมเข้าด้วยกันเพื่อสร้างโค้ดแก้ไขข้อผิดพลาดเชิงควอนตัม ดังนั้นเพื่อการอภิปรายต่อไปนี้ เราต้องเข้าใจพื้นฐานบางอย่างเกี่ยวกับ classical linear codes

ให้ Σ\SigmaΣ เป็น binary alphabet สำหรับการอภิปรายทั้งหมดนี้ เมื่อเราอ้างถึง classical linear code เราหมายถึงชุดที่ไม่ว่าง C⊆Σn\mathcal{C}\subseteq\Sigma^nC⊆Σn ของ binary strings ที่มีความยาว nnn สำหรับจำนวนเต็มบวกบางตัว nnn ซึ่งต้องตอบสนองคุณสมบัติพื้นฐานเพียงหนึ่งอย่าง: ถ้า uuu และ vvv เป็น binary strings ใน C\mathcal{C}C แล้ว string u⊕vu\oplus vu⊕v ก็อยู่ใน C\mathcal{C}C ด้วย ที่นี่ u⊕vu\oplus vu⊕v หมายถึง bitwise exclusive-OR ของ uuu และ vvv ดังที่เราพบหลายครั้งใน คอร์ส "Fundamentals of quantum algorithms"

โดยพื้นฐาน เมื่อเราอ้างถึง classical error correcting code ว่าเป็น linear เราคิดถึง binary strings ที่มีความยาว nnn ในฐานะ vectors nnn มิติ โดยที่ entries เป็น 000 หรือ 111 และต้องการให้โค้ดเองเป็น linear subspace แทนที่จะเป็น vector addition ธรรมดาบนจำนวนจริงหรือจำนวนเชิงซ้อน เราใช้การบวก modulo 222 ซึ่งก็คือ exclusive-OR กล่าวคือ ถ้ามี codewords สองตัว uuu และ vvv หมายความว่า uuu และ vvv เป็น binary strings ใน C\mathcal{C}C แล้ว u+vu + vu+v modulo 2 ซึ่งก็คือ u⊕vu\oplus vu⊕v ต้องเป็น codeword ใน C\mathcal{C}C ด้วย สังเกตโดยเฉพาะว่า implication นี้ต้องเป็นจริงแม้ u=vu = vu=v สิ่งนี้หมายความว่า C\mathcal{C}C ต้องรวม all-zero string 0n0^n0n เพราะ bitwise exclusive-OR ของ string ใด ๆ กับตัวมันเองคือ all-zero string

ตัวอย่าง: 3-bit repetition code​

3-bit repetition code เป็นตัวอย่างของ classical linear code โดยเฉพาะ เรามี C={000,111}\mathcal{C} = \{000,111\}C={000,111} ดังนั้นเทียบกับเงื่อนไข linearity มีเพียงสองทางเลือกสำหรับ uuu และสองทางเลือกสำหรับ vvv เป็นเรื่องง่ายที่จะตรวจสอบสี่คู่ที่เป็นไปได้เพื่อดูว่าเราได้ codeword เสมอเมื่อนำ bitwise exclusive-OR:

000⊕000=000,000⊕111=111,111⊕000=111,111⊕111=000.000 \oplus 000 = 000, \quad 000 \oplus 111 = 111, \quad 111 \oplus 000 = 111, \quad 111 \oplus 111 = 000.000⊕000=000,000⊕111=111,111⊕000=111,111⊕111=000.

มีตรรกะง่าย ๆ เบื้องหลังการเลือก strings เหล่านี้ แต่เป็นเรื่องรองจากบท และจะไม่อธิบายที่นี่ สำหรับตอนนี้ เพียงแค่สังเกตว่านี่คือ classical linear code: การ XOR strings สองตัวใด ๆ เข้าด้วยกันจะให้ string อื่นในโค้ดเสมอ

สัญกรณ์ [7,4,3][7,4,3][7,4,3] (ในวงเล็บเหลี่ยมเดี่ยว) หมายความคล้ายกับสัญกรณ์วงเล็บเหลี่ยมคู่สำหรับ stabilizer codes ที่กล่าวถึงในบทก่อนหน้า แต่ที่นี่สำหรับ classical linear codes โดยเฉพาะ codewords มี 777 bits เราสามารถ encode 444 bits โดยใช้โค้ด (เพราะมี 16=2416 = 2^416=24 codewords) และบังเอิญเป็น distance 333 code หมายความว่า codewords ที่ต่างกันสองอันต้องต่างกันในอย่างน้อย 333 ตำแหน่ง ดังนั้นต้อง flip อย่างน้อย 333 bits เพื่อเปลี่ยน codeword หนึ่งเป็นอีกอัน ข้อเท็จจริงที่ว่านี่คือ distance 333 code หมายความว่าสามารถแก้ไข bit-flip error ได้สูงสุดหนึ่งอย่าง

การอธิบาย classical linear codes​

ตัวอย่างที่กล่าวถึงเพิ่งเป็นตัวอย่างง่าย ๆ ของ classical linear codes แต่แม้แต่ [7,4,3][7,4,3][7,4,3]-Hamming code ก็ดูลึกลับบ้างเมื่อ codewords ถูกระบุไว้ง่าย ๆ มีวิธีที่ดีกว่าและมีประสิทธิภาพมากกว่าในการอธิบาย classical linear codes รวมถึงสองวิธีต่อไปนี้

  1. Generators วิธีหนึ่งในการอธิบาย classical linear code คือด้วยรายการ codewords ขั้นต่ำที่ generates โค้ด หมายความว่าโดยการนำ subsets ทั้งหมดที่เป็นไปได้ของ codewords เหล่านี้และ XOR เข้าด้วยกัน เราได้โค้ดทั้งหมด

    โดยละเอียดยิ่งขึ้น strings u1,…,um∈Σnu_1,\ldots,u_m\in\Sigma^nu1​,…,um​∈Σn generates classical linear code C\mathcal{C}C ถ้า

    C={α1u1⊕⋯⊕αmum : α1,…,αm∈{0,1}},\mathcal{C} = \bigl\{\alpha_1 u_1 \oplus \cdots \oplus \alpha_m u_m\,:\,\alpha_1,\ldots,\alpha_m\in\{0,1\}\bigr\},C={α1​u1​⊕⋯⊕αm​um​:α1​,…,αm​∈{0,1}},

    โดยเข้าใจว่า αu=u\alpha u = uαu=u เมื่อ α=1\alpha = 1α=1 และ αu=0n\alpha u = 0^nαu=0n เมื่อ α=0\alpha = 0α=0 และเราบอกว่ารายการนี้ minimal ถ้าการลบ string หนึ่งออกสร้างโค้ดที่เล็กลง วิธีธรรมชาติในการคิดถึงคำอธิบายดังกล่าวคือ ชุด {u1,…,um}\{u_1,\ldots,u_m\}{u1​,…,um​} เป็น basis ของ C\mathcal{C}C ในฐานะ subspace โดยที่เราคิดถึง strings ในฐานะ vectors ที่มี entries เป็น binary โดยจำไว้ว่าเราทำงานใน vector space ที่คณิตศาสตร์ทำ modulo 222

  2. Parity checks อีกวิธีธรรมชาติในการอธิบาย classical linear code คือด้วย parity checks — หมายความว่ารายการ binary strings ขั้นต่ำที่ strings ในโค้ดคือตัวที่ binary dot product กับทุก parity check string เป็นศูนย์ (คล้ายกับ bitwise exclusive-OR binary dot product ปรากฏหลายครั้งใน "Fundamentals of quantum algorithms")

    กล่าวคือ strings v1,…,vr∈Σnv_1,\ldots,v_r\in\Sigma^nv1​,…,vr​∈Σn เป็น parity check strings สำหรับ classical linear code C\mathcal{C}C ถ้า

    C={u∈Σn : u⋅v1=⋯=u⋅vr=0},\mathcal{C} = \bigl\{ u\in \Sigma^n\,:\, u\cdot v_1 = \cdots = u \cdot v_r = 0 \bigr\},C={u∈Σn:u⋅v1​=⋯=u⋅vr​=0},

    และชุดของ strings นี้ minimal ถ้าการลบหนึ่งออกให้โค้ดที่ใหญ่ขึ้น เรียกว่า parity check strings เพราะ uuu มี binary dot product เท่ากับศูนย์กับ vvv ถ้าและเฉพาะถ้า bits ของ uuu ในตำแหน่งที่ vvv มี 1 มี parity คู่ ดังนั้น เพื่อดูว่า string uuu อยู่ใน code C\mathcal{C}C หรือไม่ ก็เพียงพอที่จะตรวจสอบ parity ของ subsets บางอย่างของ bits ของ uuu

    สิ่งสำคัญที่ต้องสังเกตที่นี่คือ binary dot product ไม่ใช่ inner product ในความหมายเป็นทางการ โดยเฉพาะ เมื่อ strings สองตัวมี binary dot product เท่ากับศูนย์ ไม่ได้หมายความว่าพวกมัน orthogonal ในทิศทางที่เรามักคิดถึง orthogonality ตัวอย่างเช่น binary dot product ของ string 111111 กับตัวมันเองเป็นศูนย์ ดังนั้นเป็นไปได้ที่ parity check string สำหรับ classical linear code อยู่ในโค้ดเอง

Classical linear codes บน binary alphabet มักรวม strings จำนวนหนึ่งที่เป็น power ของ 222 — และสำหรับ classical linear code เดี่ยวที่อธิบายด้วยสองวิธีที่เพิ่งอธิบาย มักเป็นจริงว่า n=m+rn = m + rn=m+r โดยเฉพาะ ถ้ามี generators ขั้นต่ำ mmm ตัว โค้ดจะ encode mmm bits และจะมี 2m2^m2m codewords และถ้ามี parity check strings ขั้นต่ำ rrr ตัว จะมี 2n−r2^{n-r}2n−r codewords ดังนั้น generator แต่ละตัวทำให้ code space เป็นสองเท่า ขณะที่ parity check string แต่ละตัวทำให้ครึ่งหนึ่ง

ตัวอย่างเช่น 3-bit repetition code เป็น linear code ดังนั้นสามารถอธิบายได้ทั้งสองวิธีนี้ โดยเฉพาะ มีเพียงหนึ่งทางเลือกสำหรับ generator ที่ใช้ได้: 111111111 เราสามารถอธิบายโค้ดด้วย parity check strings สองตัวแทน เช่น 110110110 และ 011011011 — ซึ่งน่าจะดูคุ้นเคยจากการอภิปรายก่อนหน้าของโค้ดนี้ — หรือเราอาจนำ parity check strings เป็น 110110110 และ 101101101 หรือ 101101101 และ 011011011 แทนก็ได้ (Generators และ parity check strings โดยทั่วไปไม่ unique สำหรับ classical linear code ที่กำหนด)

สำหรับตัวอย่างที่สอง พิจารณา [7,4,3][7,4,3][7,4,3]-Hamming code นี่คือทางเลือกหนึ่งสำหรับรายการ generators ที่ใช้ได้

และนี่คือทางเลือกสำหรับรายการ parity checks สำหรับโค้ดนี้

111100011001101010101\begin{array}{c} 1111000\\[1mm] 1100110\\[1mm] 1010101 \end{array}111100011001101010101​

ที่นี่ นอกจากนี้ เราเห็นว่า ทั้งหมด ของ parity check strings ของเรานั้นอยู่ในโค้ดเอง

ข้อสังเกตสุดท้ายเกี่ยวกับ classical linear codes ซึ่งเชื่อมโยงพวกมันกับ stabilizer formalism คือ parity check strings เทียบเท่ากับ stabilizer generators ที่ประกอบด้วยเฉพาะ ZZZ และ identity Pauli matrices ตัวอย่างเช่น parity check strings 110110110 และ 011011011 สำหรับ 3-bit repetition code สอดคล้องกับ stabilizer generators Z⊗Z⊗IZ\otimes Z\otimes \mathbb{I}Z⊗Z⊗I และ I⊗Z⊗Z\mathbb{I}\otimes Z\otimes ZI⊗Z⊗Z พอดี ซึ่งสอดคล้องกับการอภิปรายของ Pauli observables จากบทก่อนหน้า

นิยามของ CSS codes​

CSS codes คือ stabilizer codes ที่ได้จากการรวม คู่ ของ classical linear codes บางอย่างเข้าด้วยกัน สิ่งนี้ใช้ไม่ได้กับ classical linear codes สองตัวใด ๆ — โค้ดสองตัวต้องมีความสัมพันธ์บางอย่าง อย่างไรก็ตาม construction นี้เปิดความเป็นไปได้มากมายสำหรับโค้ดแก้ไขข้อผิดพลาดเชิงควอนตัม อาศัยส่วนหนึ่งจาก classical coding theory กว่า 75 ปี

ใน stabilizer formalism stabilizer generators ที่มีเฉพาะ ZZZ และ identity Pauli matrices เทียบเท่ากับ parity checks ดังที่เราเพิ่งสังเกตสำหรับ 3-bit repetition code สำหรับตัวอย่างอื่น พิจารณา parity check strings ต่อไปนี้สำหรับ [7,4,3][7,4,3][7,4,3]-Hamming code

การตรวจจับและแก้ไขข้อผิดพลาด​

เกี่ยวกับการตรวจจับและแก้ไขข้อผิดพลาด CSS codes โดยทั่วไปมีลักษณะคล้ายกับ 9-qubit Shor code กล่าวคือ XXX และ ZZZ errors สามารถตรวจจับและแก้ไขได้อย่างอิสระโดยสมบูรณ์ โดยที่ ZZZ stabilizer generators อธิบายโค้ดที่ป้องกัน bit flips และ XXX stabilizer generators อธิบายโค้ดที่ป้องกัน phase flips อย่างอิสระ สิ่งนี้ทำงานได้เพราะ ZZZ stabilizer generators commute กับ ZZZ errors อย่างจำเป็น รวมถึง ZZZ operations ที่นำไปใช้เป็น corrections ดังนั้นพวกมันมองไม่เห็นทั้งสองอย่างโดยสมบูรณ์ และเช่นเดียวกันสำหรับ XXX stabilizer generators, errors และ corrections

เป็นตัวอย่าง มาพิจารณา 7-qubit Steane code

แนวคิดพื้นฐานสำหรับโค้ดนี้ชัดเจนแล้วในตอนนี้: มันเป็น [7,4,3][7,4,3][7,4,3]-Hamming code สำหรับ bit-flip errors และ [7,4,3][7,4,3][7,4,3]-Hamming code สำหรับ phase-flip errors ข้อเท็จจริงที่ XXX และ ZZZ stabilizer generators commute กันอาจเป็นความโชคดี เพราะนี่จะไม่เป็น valid stabilizer code หากไม่ได้เป็นเช่นนั้น แต่อันที่จริง มีตัวอย่างที่รู้จักมากมายของ classical linear codes ที่ให้ valid stabilizer code เมื่อใช้ในลักษณะที่คล้ายกัน

โดยทั่วไป สมมติว่ามี CSS code ที่ ZZZ stabilizer generators อนุญาตให้แก้ไข bit-flip errors สูงสุด jjj อย่าง และ XXX stabilizer generators อนุญาตให้แก้ไข phase-flip errors สูงสุด kkk อย่าง ตัวอย่างเช่น j=1j = 1j=1 และ k=1k = 1k=1 สำหรับ Steane code เนื่องจาก [7,4,3][7,4,3][7,4,3]-Hamming code สามารถแก้ไข bit flip หนึ่งอย่างได้ จากนั้นตามมาว่า จาก discretization of errors CSS code นี้สามารถแก้ไข ข้อผิดพลาดใด ๆ บน qubits จำนวนหนึ่งสูงสุดถึง minimum ของ jjj และ kkk เพราะเมื่อวัด syndrome ข้อผิดพลาดใด ๆ บน qubit จำนวนนั้นจะ collapse อย่าง probabilistic เป็น combination บางอย่างของ XXX errors, ZZZ errors หรือทั้งสอง — แล้ว XXX errors และ ZZZ errors จะถูกตรวจจับและแก้ไขอย่างอิสระ

สรุปได้ว่า ถ้ามี classical linear codes สองตัว (หรือสำเนาสองตัวของ classical linear code เดียวกัน) ที่เข้ากันได้ ในแง่ที่กำหนด XXX และ ZZZ stabilizer generators ที่ commute กัน CSS code ที่ได้จากการรวมพวกมันจะรับทอดคุณสมบัติการแก้ไขข้อผิดพลาดของโค้ดทั้งสองนั้น ในแง่ที่เพิ่งอธิบาย

สังเกตว่ามีราคาที่ต้องจ่ายด้วย กล่าวคือเราไม่สามารถ encode qubits ได้มากเท่ากับที่เราสามารถ encode bits ด้วย classical codes สองตัว เพราะจำนวนรวมของ stabilizer generators สำหรับ CSS code คือ ผลรวม ของจำนวน parity checks สำหรับ classical linear codes สองตัว และ stabilizer generator แต่ละตัวลด dimension ของ code space ลงครึ่งหนึ่ง ตัวอย่างเช่น [7,4,3][7,4,3][7,4,3]-Hamming code อนุญาตให้ encode classical bits สี่อย่าง เพราะมีเพียง parity check strings สามตัวสำหรับโค้ดนี้ ในขณะที่ 7-qubit Steane code encode เพียงหนึ่ง qubit เพราะมี stabilizer generators หกตัว

Code spaces ของ CSS codes​

สิ่งสุดท้ายที่เราจะทำในการอภิปราย CSS codes นี้คือพิจารณา code spaces ของโค้ดเหล่านี้ สิ่งนี้จะให้โอกาสตรวจสอบความสัมพันธ์ที่ต้องมีระหว่าง classical linear codes สองตัวเพื่อให้เข้ากันได้ ในแง่ที่สามารถรวมเข้าด้วยกันเพื่อเป็น CSS code

พิจารณา CSS code ใด ๆ บน nnn qubits และให้ z1,…,zs∈Σnz_1, \ldots, z_s \in \Sigma^nz1​,…,zs​∈Σn เป็น nnn-bit parity check strings ที่สอดคล้องกับ ZZZ stabilizer generators ของโค้ดนี้ หมายความว่า classical linear code ที่อธิบายด้วยเฉพาะ ZZZ stabilizer generators ซึ่งเราจะตั้งชื่อว่า CZ\mathcal{C}_ZCZ​ มีรูปแบบต่อไปนี้

CZ={u∈Σn : u⋅z1=⋯=u⋅zs=0}\mathcal{C}_Z = \bigl\{ u \in \Sigma^n \,:\, u \cdot z_1 = \cdots = u \cdot z_s = 0 \bigr\}CZ​={u∈Σn:u⋅z1​=⋯=u⋅zs​=0}

พูดเป็นคำพูด classical linear code CZ\mathcal{C}_ZCZ​ มีทุก string ที่ binary dot product กับทุก parity check strings z1,…,zsz_1, \ldots, z_sz1​,…,zs​ เป็นศูนย์

ในทิศทางเดียวกัน ให้นำ x1,…,xt∈Σnx_1,\ldots,x_t\in\Sigma^nx1​,…,xt​∈Σn เป็น nnn-bit parity check strings ที่สอดคล้องกับ XXX stabilizer generators ของโค้ดของเรา ดังนั้น classical linear code ที่สอดคล้องกับ XXX stabilizer generators มีรูปแบบนี้

CX={u∈Σn : u⋅x1=⋯=u⋅xt=0}\mathcal{C}_X = \bigl\{ u \in \Sigma^n \,:\, u \cdot x_1 = \cdots = u \cdot x_t = 0 \bigr\}CX​={u∈Σn:u⋅x1​=⋯=u⋅xt​=0}

XXX stabilizer generators เพียงอย่างเดียวจึงอธิบายโค้ดที่คล้ายกับโค้ดนี้ แต่ใน {∣+⟩,∣−⟩}\{\vert {+}\rangle,\vert {-}\rangle\}{∣+⟩,∣−⟩} basis แทน standard basis

ตอนนี้เราจะแนะนำ classical linear codes ใหม่สองตัวที่ได้มาจากทางเลือกเดียวกันของ strings z1,…,zsz_1,\ldots,z_sz1​,…,zs​ และ x1,…,xtx_1,\ldots,x_tx1​,…,xt​ แต่เราถือว่า strings เหล่านี้เป็น generators แทนที่จะเป็น parity check strings โดยเฉพาะ เราได้โค้ดสองตัวนี้

DZ={α1z1⊕⋯⊕αszs : α1,…,αs∈{0,1}}DX={α1x1⊕⋯⊕αtxt : α1,…,αt∈{0,1}}\begin{aligned} \mathcal{D}_Z & = \bigl\{ \alpha_1 z_1 \oplus \cdots \oplus \alpha_s z_s \,:\, \alpha_1,\ldots,\alpha_s \in \{0,1\} \bigr\}\\[1mm] \mathcal{D}_X & = \bigl\{ \alpha_1 x_1 \oplus \cdots \oplus \alpha_t x_t \,:\, \alpha_1,\ldots,\alpha_t \in \{0,1\} \bigr\} \end{aligned}DZ​DX​​={α1​z1​⊕⋯⊕αs​zs​:α1​,…,αs​∈{0,1}}={α1​x1​⊕⋯⊕αt​xt​:α1​,…,αt​∈{0,1}}​

สิ่งเหล่านี้เรียกว่า dual codes ของโค้ดที่นิยามก่อนหน้า: DZ\mathcal{D}_ZDZ​ คือ dual code ของ CZ\mathcal{C}_ZCZ​ และ DX\mathcal{D}_XDX​ คือ dual code ของ CX\mathcal{C}_XCX​ อาจไม่ชัดเจนในจุดนี้ว่า dual codes เหล่านี้เกี่ยวข้องอย่างไร แต่มันเกี่ยวข้องอย่างมากด้วยหลายเหตุผล รวมถึงสองเหตุผลที่อธิบายในย่อหน้าต่อไปนี้

ประการแรก เงื่อนไขที่ต้องมีสำหรับ classical linear codes CZ\mathcal{C}_ZCZ​ และ CX\mathcal{C}_XCX​ สองตัวเพื่อให้เข้ากันได้ ในแง่ที่สามารถจับคู่กันเพื่อเป็น CSS code สามารถอธิบายได้ในคำพูดง่าย ๆ โดยอ้างถึง dual codes โดยเฉพาะ ต้องเป็นว่า DZ⊆CX\mathcal{D}_Z\subseteq\mathcal{C}_XDZ​⊆CX​ หรือเทียบเท่าคือ DX⊆CZ\mathcal{D}_X\subseteq\mathcal{C}_ZDX​⊆CZ​ พูดเป็นคำพูด dual code DZ\mathcal{D}_ZDZ​ รวม strings ที่สอดคล้องกับ ZZZ stabilizer generators และการที่พวกมันอยู่ใน CX\mathcal{C}_XCX​ เทียบเท่ากับ binary dot product ของแต่ละ string เหล่านี้กับตัวที่สอดคล้องกับ XXX stabilizer generators เป็นศูนย์ สิ่งนั้น ในทางกลับกัน เทียบเท่ากับ ZZZ stabilizer generator แต่ละตัว commute กับ XXX stabilizer generator แต่ละตัว หรือโดยสลับบทบาทของ XXX และ ZZZ stabilizer generators และเริ่มจากการบรรจุ DX⊆CZ\mathcal{D}_X\subseteq\mathcal{C}_ZDX​⊆CZ​ เราสามารถสรุปผลเดียวกันได้

ประการที่สอง โดยอ้างถึง dual codes เราสามารถอธิบาย code spaces ของ CSS code ที่กำหนดได้ง่าย โดยเฉพาะ code space ถูก span ด้วย vectors ของรูปแบบต่อไปนี้

∣u⊕DX⟩=12t∑v∈DX∣u⊕v⟩(for all u∈CZ)\vert u \oplus \mathcal{D}_X\rangle = \frac{1}{\sqrt{2^t}} \sum_{v\in\mathcal{D}_X} \vert u \oplus v\rangle \qquad \text{(for all $u\in\mathcal{C}_Z$)}∣u⊕DX​⟩=2t​1​v∈DX​∑​∣u⊕v⟩(for all u∈CZ​)

พูดเป็นคำพูด vectors เหล่านี้คือ uniform superpositions บน strings ใน dual code DX\mathcal{D}_XDX​ ของโค้ดที่สอดคล้องกับ XXX stabilizer generators ที่ถูก shift ด้วย (กล่าวคือ bitwise XORed กับ) strings ใน code CZ\mathcal{C}_ZCZ​ ที่สอดคล้องกับ ZZZ stabilizer generators เพื่อให้ชัดเจน ทางเลือกต่าง ๆ สำหรับ shift — แทนด้วย string uuu ใน expression นี้ — อาจให้ vector เดียวกัน ดังนั้น states เหล่านี้ไม่ได้แตกต่างกันทั้งหมด แต่รวมกันแล้ว span code space ทั้งหมด

นี่คือคำอธิบายเชิงสัญชาตญาณว่าทำไม vectors ดังกล่าวถึงทั้งอยู่ใน code space และ span มัน พิจารณา nnn-qubit standard basis state ∣u⟩\vert u\rangle∣u⟩ สำหรับ nnn-bit string uuu ใด ๆ และสมมติว่าเรา project state นี้ลงบน code space กล่าวคือ ให้ Π\PiΠ แทน projection ลงบน code space ของ CSS code ของเรา พิจารณา vector Π∣u⟩\Pi\vert u\rangleΠ∣u⟩ มีสองกรณี:

  • กรณีที่ 1: u∈CZu\in\mathcal{C}_Zu∈CZ​ สิ่งนี้หมายความว่า ZZZ stabilizer generator แต่ละตัวของ CSS code ของเราทำงาน trivially บน ∣u⟩\vert u\rangle∣u⟩ ในทางกลับกัน XXX stabilizer generators แต่ละตัว flip bits บางส่วนของ ∣u⟩\vert u\rangle∣u⟩ โดยเฉพาะ สำหรับ generator vvv ของ DX\mathcal{D}_XDX​ แต่ละตัว XXX stabilizer generator ที่สอดคล้องกับ vvv แปลง ∣u⟩\vert u\rangle∣u⟩ เป็น ∣u⊕v⟩\vert u\oplus v\rangle∣u⊕v⟩ โดยระบุ projection Π\PiΠ เป็น ค่าเฉลี่ย บน elements ของ stabilizer (ดังที่เราเห็นในบทก่อนหน้า) เราได้สูตรนี้:

    Π∣u⟩=12t∑v∈DX∣u⊕v⟩=12t∣u⊕DX⟩.\Pi \vert u \rangle = \frac{1}{2^t} \sum_{v\in\mathcal{D}_{X}} \vert u \oplus v\rangle = \frac{1}{\sqrt{2^t}} \vert u \oplus \mathcal{D}_X\rangle.Π∣u⟩=2t1​v∈DX​∑​∣u⊕v⟩=2t​1​∣u⊕DX​⟩.

  • กรณีที่ 2: u∉CZu\notin\mathcal{C}_Zu∈/CZ​ สิ่งนี้หมายความว่า parity checks อย่างน้อยหนึ่งอันที่สอดคล้องกับ ZZZ stabilizer generators ล้มเหลว ซึ่งก็คือ ∣u⟩\vert u\rangle∣u⟩ ต้องเป็น −1-1−1 eigenvector ของ ZZZ stabilizer generators อย่างน้อยหนึ่งตัว code space ของ CSS code คือ intersection ของ +1+1+1 eigenspaces ของ stabilizer generators ดังนั้น ในฐานะ −1-1−1 eigenvector ของ ZZZ stabilizer generators อย่างน้อยหนึ่งตัว ∣u⟩\vert u\rangle∣u⟩ จึง orthogonal กับ code space:

    Π∣u⟩=0.\Pi\vert u\rangle = 0.Π∣u⟩=0.

และตอนนี้ เมื่อเราวนซ้ำบน nnn-bit strings uuu ทั้งหมด ทิ้งตัวที่ Π∣u⟩=0\Pi\vert u\rangle = 0Π∣u⟩=0 และ normalize ตัวที่เหลือ เราได้ vectors ที่อธิบายก่อนหน้า ซึ่งแสดงว่าพวกมัน span code space

เรายังสามารถใช้ความสมมาตรระหว่าง XXX และ ZZZ stabilizer generators เพื่ออธิบาย code space ในทิศทางที่คล้ายกันแต่แตกต่าง โดยเฉพาะ มันคือ space ที่ span ด้วย vectors ที่มีรูปแบบต่อไปนี้

H⊗n∣u⊕DZ⟩=12s∑v∈DZH⊗n∣u⊕v⟩(for u∈CX)H^{\otimes n} \vert u \oplus \mathcal{D}_Z\rangle = \frac{1}{\sqrt{2^s}} \sum_{v\in\mathcal{D}_Z} H^{\otimes n}\vert u \oplus v\rangle \qquad \text{(for $u\in\mathcal{C}_X$)}H⊗n∣u⊕DZ​⟩=2s​1​v∈DZ​∑​H⊗n∣u⊕v⟩(for u∈CX​)

โดยพื้นฐาน XXX และ ZZZ ถูกสลับในทุก instance ที่ปรากฏ — แต่เราต้องสลับ standard basis สำหรับ {∣+⟩,∣−⟩}\{\vert+\rangle,\vert-\rangle\}{∣+⟩,∣−⟩} basis ด้วย ซึ่งเป็นเหตุผลที่ Hadamard operations รวมอยู่

เป็นตัวอย่าง มาพิจารณา 7-qubit Steane code parity check strings สำหรับทั้ง XXX และ ZZZ stabilizer generators เหมือนกัน: 1111000,1111000,1111000, 1100110,1100110,1100110, และ 101010110101011010101 ดังนั้น codes CX\mathcal{C}_XCX​ และ CZ\mathcal{C}_ZCZ​ เหมือนกัน ทั้งสองเท่ากับ [7,4,3][7,4,3][7,4,3]-Hamming code

CX=CZ={0000000,0000111,0011001,0011110,0101010,0101101,0110011,0110100,1001011,1001100,1010010,1010101,1100001,1100110,1111000,1111111}\mathcal{C}_X = \mathcal{C}_Z = \{0000000, 0000111, 0011001, 0011110, 0101010, 0101101, 0110011, 0110100, 1001011, 1001100, 1010010, 1010101, 1100001, 1100110, 1111000, 1111111\}CX​=CZ​={0000000,0000111,0011001,0011110,0101010,0101101,0110011,0110100,1001011,1001100,1010010,1010101,1100001,1100110,1111000,1111111}

ดังนั้น dual codes DX\mathcal{D}_XDX​ และ DZ\mathcal{D}_ZDZ​ ก็เหมือนกันด้วย เรามี generators สามตัว ดังนั้นเราได้ strings แปดตัว

DX=DZ={0000000,0011110,0101101,0110011,1001011,1010101,1100110,1111000}\mathcal{D}_X = \mathcal{D}_Z = \{0000000, 0011110, 0101101, 0110011, 1001011, 1010101, 1100110, 1111000\}DX​=DZ​={0000000,0011110,0101101,0110011,1001011,1010101,1100110,1111000}

strings เหล่านี้อยู่ใน [7,4,3][7,4,3][7,4,3]-Hamming code ทั้งหมด ดังนั้นเงื่อนไข CSS จึงตอบสนอง: DZ⊆CX\mathcal{D}_Z \subseteq \mathcal{C}_XDZ​⊆CX​ หรือเทียบเท่าคือ DX⊆CZ\mathcal{D}_X \subseteq \mathcal{C}_ZDX​⊆CZ​

เนื่องจาก DX\mathcal{D}_XDX​ มีครึ่งหนึ่งของ strings ทั้งหมดใน CZ\mathcal{C}_ZCZ​ จึงมีเพียง vectors ∣u⊕DX⟩\vert u\oplus \mathcal{D}_X\rangle∣u⊕DX​⟩ สองตัวที่แตกต่างที่ได้จากการเลือก u∈CZu\in\mathcal{C}_Zu∈CZ​ สิ่งนี้คาดหวังได้ เพราะ 7-qubit Steane code มี code space สองมิติ เราสามารถใช้สอง states ที่เราได้ในลักษณะนี้เพื่อ encode logical state ∣0⟩\vert 0\rangle∣0⟩ และ ∣1⟩\vert 1\rangle∣1⟩ ดังนี้

∣0⟩↦∣0000000⟩+∣0011110⟩+∣0101101⟩+∣0110011⟩+∣1001011⟩+∣1010101⟩+∣1100110⟩+∣1111000⟩8∣1⟩↦∣0000111⟩+∣0011001⟩+∣0101010⟩+∣0110100⟩+∣1001100⟩+∣1010010⟩+∣1100001⟩+∣1111111⟩8\begin{aligned} \vert 0\rangle & \mapsto \frac{ \vert 0000000\rangle + \vert 0011110\rangle + \vert 0101101\rangle + \vert 0110011\rangle + \vert 1001011\rangle + \vert 1010101\rangle + \vert 1100110\rangle + \vert 1111000\rangle }{\sqrt{8}}\\[4mm] \vert 1\rangle & \mapsto \frac{ \vert 0000111\rangle + \vert 0011001\rangle + \vert 0101010\rangle + \vert 0110100\rangle + \vert 1001100\rangle + \vert 1010010\rangle + \vert 1100001\rangle + \vert 1111111\rangle }{\sqrt{8}} \end{aligned}∣0⟩∣1⟩​↦8​∣0000000⟩+∣0011110⟩+∣0101101⟩+∣0110011⟩+∣1001011⟩+∣1010101⟩+∣1100110⟩+∣1111000⟩​↦8​∣0000111⟩+∣0011001⟩+∣0101010⟩+∣0110100⟩+∣1001100⟩+∣1010010⟩+∣1100001⟩+∣1111111⟩​​

ตามปกติ ทางเลือกนี้ไม่ได้บังคับ เราเป็นอิสระในการใช้ code space เพื่อ encode qubits อย่างไรก็ได้ตามที่เลือก อย่างไรก็ตาม encoding นี้สอดคล้องกับตัวอย่างของ encoding circuit สำหรับ 7-qubit Steane code ในบทก่อนหน้า
