ความรู้พื้นฐานที่ต้องมี

บทเรียนนี้ต่อยอดจากภาษา stabilizer-check ที่แนะนำไว้ใน การแก้ไขข้อผิดพลาด I โดยสมมติว่าคุณคุ้นเคยกับ Pauli check, syndrome, code distance และแนวคิดที่ว่า check ของ surface code เป็นแบบ local บน layout 2 มิติ การอธิบายอย่างเป็นทางการเต็มรูปแบบของ stabilizer code มีอยู่ในคอร์ส Foundations of quantum error correction ของ John Watrous บน IBM Quantum® Learning แต่เนื้อหาหลักต้องการเพียงแนวคิดพื้นฐานที่สรุปไว้ในส่วนทบทวนเสริมด้านล่าง เราจะอยู่ในระดับของการ ใช้ formalism ไม่ใช่การพิสูจน์ที่มาของมัน

บทเรียนนี้ไม่ได้ถามว่า quantum error correction (QEC) คืออะไร แต่ถามว่า เมื่อไหร่ที่มันเป็นเครื่องมือที่เหมาะสมสำหรับ quantum advantage เพื่อตอบคำถามนี้ เราจะติดตามว่าต้นทุนมาจากไหน (Part 1 และ 2) ลดได้อย่างไร (Part 3) และต้นทุนนั้น ย้ายไป อยู่ที่ใดแทนที่จะหายไป (Part 4 และ 5) จากนั้นเรารวมทั้งหมดเข้าสู่การตัดสินเรื่อง advantage (Part 6)

บทเรียนก่อนหน้าได้แนะนำหลายวิธีในการรักษาความแม่นยำของการคำนวณควอนตัม เราได้เห็นว่าข้อผิดพลาดทางกายภาพเกิดและสะสมอย่างไร บางครั้งสามารถลดหรือปรับรูปร่างได้อย่างไร และผลกระทบของมันบรรเทาได้อย่างไรผ่านการรันเพิ่มและ post-processing แบบคลาสสิก บทเรียนก่อนหน้าเพิ่มแนวคิดอีกอย่าง คือสร้าง check ไว้ในการคำนวณเพื่อให้ระบุและทิ้งการรันที่เสียหายได้ syndrome post-selection แบบอิงโค้ดของมัน รวมถึง spacetime check เป็นรูปแบบหนึ่งของ post-selected quantum error correction (บล็อก Qiskit Paulice) วิธีนี้ปรับปรุงคุณภาพของข้อมูลที่เก็บไว้ แต่ก็ยังมีข้อจำกัด ข้อผิดพลาดบางอย่างผ่านไปโดยไม่ถูกตรวจพบ check ที่ถูกกระตุ้นอาจบอกว่ามีบางอย่างผิดพลาดแต่ไม่ระบุความผิดพลาดที่น่าจะเป็นไปได้มากที่สุด และวิธีนี้ได้ผลดีที่สุดกับ circuit ที่โครงสร้างรองรับ check แบบ overhead ต่ำ การแก้ไขแบบอิงการ decode สร้างบนข้อมูล check เดียวกัน แทนที่จะถามว่าควรเก็บหรือทิ้งการรัน มันถามว่าข้อผิดพลาดแบบไหนสอดคล้องกับรูปแบบที่สังเกตได้มากที่สุด และควรกู้คืนข้อมูลที่ encode อย่างไร ความแตกต่างตรงนี้คือระหว่าง syndrome-based post-selection กับการ decode พร้อม recovery ซึ่งเป็นสองแนวทางบน QEC continuum เดียวกัน (บล็อก QEC continuum) พลังที่เพิ่มขึ้นนี้เปลี่ยน trade-off ของทรัพยากร การแก้ไขแบบอิงการ decode ย้ายต้นทุนไปทาง qubit กายภาพ, syndrome extraction, การ decode, connectivity และสถาปัตยกรรมมากขึ้น นี่เป็นการแลกต้นทุนการสุ่มตัวอย่างกับ qubit และทรัพยากรฮาร์ดแวร์เพิ่มเติมตาม QEC continuum (บล็อก QEC continuum) และกลายเป็นหัวใจสำคัญเมื่อวิธีที่เบากว่ารองรับความลึกหรือความน่าเชื่อถือที่งานต้องการไม่ได้

บทเรียนนี้เริ่มด้วยการเชื่อมโยงการ decode และ recovery เข้ากับวิธี post-selection ของบทเรียนก่อนหน้า จากนั้นหันไปที่วิธีที่ได้รับการยอมรับมากที่สุดในการปกป้องข้อมูลควอนตัมที่เก็บไว้ และเหตุใดจึงแพงมาก จากนั้นถามว่าจะลดต้นทุนนั้นได้อย่างไร และตรวจสอบข้อเสนอล่าสุดที่เป็นรูปธรรมเป็นกรณีศึกษา แล้วอธิบายว่าเหตุใดการปกป้องข้อมูลที่เก็บไว้จึงไม่เพียงพอสำหรับการคำนวณที่มีประโยชน์ และอัลกอริทึมเต็มรูปแบบต้องการทรัพยากรเพิ่มเติมอะไร ต่อไปจะถอยออกมามองการแก้ไขข้อผิดพลาดเป็นระบบทั้งหมด รวมถึง decoder สถาปัตยกรรมแบบ modular และความท้าทายต่างๆ ที่แพลตฟอร์มฮาร์ดแวร์อื่นสืบทอดไป บทเรียนปิดท้ายด้วยคำถามหลักของ Lanes et al. ซึ่งถามว่าเมื่อไหร่การแก้ไขข้อผิดพลาดช่วยรักษา quantum advantage และเมื่อไหร่ที่ overhead ของมันลบล้างไปหมด

Quantum error correction เป็นปัญหาของทุกแพลตฟอร์มฮาร์ดแวร์ แต่รูปแบบที่ปรากฏต่างกัน บทเรียนนี้ใช้งานล่าสุดของ IBM® เกี่ยวกับสถาปัตยกรรม bivariate-bicycle และ gross-code เป็นกรณีศึกษาที่เป็นรูปธรรม โดยยังคงกรอบหลักจาก Lanes et al., 2025 ภายในขอบเขตนั้น เรามุ่งที่ stabilizer code บน transmon ตัวนำยิ่งยวด 2 มิติ (transmon คือ qubit ตัวนำยิ่งยวดชนิดที่พบบ่อยที่สุด) ซึ่งความท้าทายในการออกแบบคือการวาง check บนกริดแบนและรองรับ connectivity แบบ non-local ผ่านฮาร์ดแวร์แบบ modular แพลตฟอร์ม trapped-ion, neutral-atom, bosonic-mode และ topological-qubit สืบทอดความท้าทายที่ต่างออกไป ซึ่งเราจะกลับมาที่ Part 5 จนถึงตอนนั้น "qubit กายภาพ", "stabilizer check" และ "layout 2 มิติ" ควรอ่านว่าอธิบายสภาพแวดล้อมตัวนำยิ่งยวด

# Surface-code toy fit (Fowler and Gidney) and patch qubit count (Bravyi et al.).
def surface_logical_error(d, p=1e-3, p_th=1e-2, A=0.1):
    """Illustrative per-round logical-error fit for surface-code scaling."""
    return A * (p / p_th) ** ((d + 1) / 2)

    """Data and syndrome qubits in one bare rotated surface-code patch."""

# the 3-qubit repetition code

def syndrome(flip):
    qc = QuantumCircuit(5)  # q0,q1,q2 = data ; q3,q4 = syndrome ancillas

    if flip is not None:
        qc.x(flip)  # inject one bit-flip error
    qc.cx(0, 3)
    qc.cx(1, 3)  # ancilla q3 <- parity of (q0, q1) = Z1 Z0 check
    qc.cx(1, 4)
    qc.cx(2, 4)  # ancilla q4 <- parity of (q1, q2) = Z2 Z1 check
    sv = Statevector(qc)
    idx = int(np.argmax(np.abs(sv.data)))  # the state is a single basis ket
    bit = [(idx >> q) & 1 for q in range(5)]  # qiskit little-endian readout
    return (bit[3], bit[4])

# Build the syndrome table: each single-qubit-flip gives a DISTINCT syndrome.
table = {}
print("error    (Z1Z0, Z2Z1)")
for flip in [None, 0, 1, 2]:
    s = syndrome(flip)
    table[s] = flip
    print(f"  {('none' if flip is None else 'flip q'+str(flip)):8s} {s}")

# The decoder is just the inverse lookup: syndrome -> most-likely flip -> undo it.
def decode(s):
    return table[s]

คู่จุดปลายของ syndrome (กระเบื้องสีเทา) ที่เชื่อมด้วยการแก้ไขเส้นทางสั้นที่สุด (สีเหลือง) การ decode surface code ลดรูปเป็น minimum-weight matching ของจุดปลายเหล่านั้น ที่มา: บทเรียนเดียวกัน

รูปนี้เพิ่มส่วนที่ syndrome ทิ้งไว้ เนื่องจากมองเห็นเพียงจุดปลาย decoder จึงเห็นโซ่ข้อผิดพลาดจริง (สีม่วงแดง) ไม่ได้ มันทำได้เพียงเลือกโซ่ที่มีจุดปลายเดียวกัน และ minimum-weight matching เลือกโซ่ที่สั้นที่สุด (สีเหลือง) ในตัวอย่างนี้

เรขาคณิตของ lattice ยังเปลี่ยนว่า logical operator หน้าตาเป็นอย่างไร ใน code [[4,2,2]][[4,2,2]][[4,2,2]] จากบทเรียนก่อนหน้า logical operator เป็นสตริง Pauli สั้นๆ ที่มี weight เท่ากับ distance ที่นี่เป็น string operator ซึ่งเป็นโซ่ของ Pauli ตัวเดียวต่อ qubit ตามเส้นทางใน lattice โซ่ข้อผิดพลาดสั้นๆ สร้างสตริงที่มีจุดปลายสองจุด และ stabilizer ที่จุดปลายเหล่านั้นทำงาน syndrome เผยให้เห็น ที่ไหน ที่โซ่สิ้นสุด แม้โซ่เองจะไม่ถูกสังเกตโดยตรง เมื่อเห็นเพียงจุดปลาย decoder เลือกโซ่ที่สั้นที่สุดที่เชื่อมพวกมัน (สีเหลือง) ซึ่งไม่จำเป็นต้องเป็นโซ่จริง ไม่เป็นไร ข้อผิดพลาดจริงและการแก้ไขรวมกันปิดเป็นลูป และลูปที่หดเป็นจุดคือผลคูณของ stabilizer ดังนั้น qubit จึงถูกกู้คืนแม้เส้นทางที่เดาจะ "ผิด" ในทางตรงข้าม ข้อผิดพลาดเชิงตรรกะคือสตริงที่ไม่มีจุดปลาย ใน toric code มันพันรอบ torus ส่วนใน surface code ขอบเปิดที่เรามุ่งเน้น มันทอดจากขอบหนึ่งของ patch ไปอีกขอบหนึ่ง distance ddd คือความยาวของสตริงที่ไม่ trivial ที่สั้นที่สุดแบบนั้น และจำนวน qubit กายภาพใน patch ที่มี distance ddd แปรตาม d2d^2d2

2.3 Locality, rate และ distance: ขอบเขตของ Bravyi-Poulin-Terhal​

วิธีที่มีประโยชน์ในการเปรียบเทียบ code คือดูว่ามันอัด logical qubit ได้กี่ตัวใน physical qubit จำนวนหนึ่ง นี่คือ rate เขียนเป็น k/nk/nk/n โดย kkk คือจำนวน logical qubit ที่เข้ารหัส และ nnn คือจำนวน physical qubit ที่ใช้ surface code มี rate k/n=1/d2k/n = 1/d^2k/n=1/d2 logical qubit แต่ละตัวใช้ patch ขนาด d×dd \times dd×d ของตัวเอง และ rate จะหายไปเมื่อระยะเพิ่มขึ้น

2.4 ภูมิทัศน์ของ qLDPC​

quantum LDPC (qLDPC) code คือ stabilizer code ที่ parity-check matrix เป็นแบบ sparse parity-check matrix คืออาร์เรย์ฐานสองที่แถวคือการตรวจสอบของ stabilizer (หนึ่งแถวต่อหนึ่งการตรวจสอบ หนึ่งคอลัมน์ต่อหนึ่ง qubit และเป็น 1 ทุกที่ที่การตรวจสอบกระทำต่อ qubit) sparse หมายความว่าแต่ละแถวและคอลัมน์มี 1 เพียงจำนวนน้อยที่มีขอบเขต ไม่ว่า code จะใหญ่แค่ไหน ซึ่งคือความหมายของ "low-density" ตามนิยามนี้ surface code เองก็เป็น qLDPC code เพราะ stabilizer น้ำหนัก 4 ของมันไม่โตตาม nnn สิ่งที่ทำให้ qLDPC code ที่น่าสนใจในช่วงหลังต่างออกไปไม่ใช่ว่ามัน sparse กว่า surface code แต่คือมันผ่อนคลาย 2D-locality โดยยังคง sparsity นั่นคือวิธีที่มันหลุดจากเพดาน BPT ที่ตรวจสอบใน หัวข้อ 2.3

คำว่า "LDPC" มาจากทฤษฎีการเข้ารหัสแบบคลาสสิก ที่ low-density parity-check code เป็นที่รู้กันมานานว่ารวม rate ที่ดีเข้ากับการ decode ที่มีประสิทธิภาพ ภาคควอนตัมสืบทอดข้อได้เปรียบเชิงโครงสร้างของการตรวจสอบแบบ sparse พร้อมกับตัดสมมติฐาน geometric-locality ออก มีหลายตระกูลที่ทำให้เป็นจริงได้ ได้แก่ code แบบ hypergraph-product (Tillich and Zémor, 2009), lifted-product (Panteleev and Kalachev, 2022), quantum Tanner (Leverrier and Zémor, 2022) และ bivariate-bicycle (Bravyi et al., 2024) บางตระกูลเป็น asymptotically good คือคง rate คงที่และระยะเชิงเส้นเมื่อ code โตขึ้น ซึ่งเป็นสมบัติที่ surface code ทำไม่ได้

สำหรับบทเรียนนี้ case study เชิงรูปธรรมคือตระกูล bivariate-bicycle ซึ่งตรวจสอบรายละเอียดใน Part 3 เหตุผลที่เลือกไม่ใช่ข้อกล่าวอ้างทางคณิตศาสตร์ว่า bivariate-bicycle เป็นตระกูล qLDPC ที่แข็งแกร่งที่สุด แต่เป็นความสอดคล้องเชิงสถาปัตยกรรม roadmap superconducting ของ IBM ที่เผยแพร่แล้วเลือก code เหล่านี้ เพราะ check graph แบบ thickness-2 เข้ากับฮาร์ดแวร์ superconducting ที่เสนอ ภายใต้สถาปัตยกรรมแบบ modular ที่พูดถึงใน Part 5 ในขอบเขตนั้น ผลหลักคือ ในการจำลอง memory ระดับ circuit ที่รายงาน bivariate-bicycle code เทียบเท่าการกดข้อผิดพลาดของ surface code ได้ด้วย physical qubit ต่อ logical qubit น้อยลงราวหนึ่งลำดับขนาดที่ p=10−3p = 10^{-3}p=10−3 (Bravyi et al., 2024; ดู fault-tolerance roadmap ของ IBM ด้วย) ต้นทุนไม่ได้หายไป แต่ย้ายจากจำนวน physical qubit ไปที่ connectivity (check graph แยกเป็นสอง subgraph แบบระนาบและมีขอบระยะไกล), การ decode (minimum-weight matching ใช้ไม่ได้อีก และการ decode qLDPC เป็นงานวิจัยที่ยังเคลื่อนไหวอยู่) และ สถาปัตยกรรม (ฮาร์ดแวร์แบบ modular เพื่อรองรับทั้งสองอย่าง) Part 3 ต่อยอดแนวคิด qLDPC นี้เป็น case study BB/gross code ที่เป็นรูปธรรม

3.1 การสร้างแบบ bivariate-bicycle​

การสร้างแบบ bivariate-bicycle (BB) สร้าง stabilizer code ทั้งตัวจากพหุนามสั้น ๆ สองตัวคือ AAA และ BBB ขณะที่ surface code สร้างด้วยการวาด plaquette แบบ local บนกริด 2D BB สร้าง parity-check matrix ด้วย พีชคณิต: กฎเดียวผลิต X-check ทั้ง 72 ตัวและ Z-check ทั้ง 72 ตัวของ gross code จากคู่พหุนาม (A,B)(A, B)(A,B) การสร้างนี้รับประกันเองว่า X- และ Z-check ที่ได้ commute กัน (กล่าวคือผลลัพธ์เป็น CSS code ที่ถูกต้อง) โดยไม่ต้องบังคับเงื่อนไข commutation ด้วยมือ จากนั้นตรวจสอบเชิงตัวเลขว่า (A,B)(A,B)(A,B) ที่กำหนดให้ rate, ระยะ และสมบัติการ decode ที่มีประโยชน์หรือไม่ การออกแบบจึงเป็น การค้นหาพหุนาม ไม่ใช่การสร้างเชิงเรขาคณิต

สำหรับ gross code พหุนามคือ A=x3+y+y2A = x^3 + y + y^2A=x3+y+y2 และ B=y3+x+x2B = y^3 + x + x^2B=y3+x+x2 บนแลตทิซ torus ขนาด 12×612 \times 612×6 ที่มี data qubit 144 ตัว ตรงนี้ xxx และ yyy เป็นตัวดำเนินการ cyclic shift สองตัวของแลตทิซ ("ขยับหนึ่งก้าว" ตามแต่ละทิศของ torus) ไม่ใช่ตัวเลข ดังนั้นพจน์อย่าง x3x^3x3 หมายถึง "ขยับสามก้าว" (รายละเอียดจะตามมา) data qubit 144 ตัวแบ่งเป็นสอง register คือ q(L)q(L)q(L) และ q(R)q(R)q(R) แต่ละตัวมี 72 qubit การตรวจสอบน้ำหนัก 6 แต่ละตัวแตะสามqubit ในแต่ละ register สมบัติ biplanar หรือ thickness-2 หมายความว่า Tanner graph แยกเป็นสอง subgraph แบบระนาบที่ไม่มีขอบร่วมกัน ทำให้เดิน coupler เป็นสองชั้นได้ มันไม่ได้วาง data register ทั้งสองบนระนาบกายภาพที่แยกกัน (Bravyi et al., 2024) ภาพด้านล่างแสดง check matrix ที่ได้เทียบกับ code แบบ surface บนแลตทิซเดียวกัน แสดงว่าการเลือกพหุนามต่างกันภายในกรอบเดียวกันให้รูปแบบ parity-check ที่ต่างกันมาก ภาพแสดงว่าการตรวจสอบแต่ละตัวกระทำต่อ data qubit ตัวไหน ไม่ใช่แผนภาพการวางฮาร์ดแวร์

# Surface-like local checks versus Gross-code BB checks

from matplotlib.colors import ListedColormap

ell, m = 12, 6
S_l = np.roll(np.eye(ell, dtype=int), 1, axis=1)
S_m = np.roll(np.eye(m, dtype=int), 1, axis=1)
I_l, I_m, I_lm = (
    np.eye(ell, dtype=int),
    np.eye(m, dtype=int),
    np.eye(ell * m, dtype=int),
)
x = np.kron(S_l, I_m)
y = np.kron(I_l, S_m)

def mpow(M, p):
    out = np.eye(M.shape[0], dtype=int)
    for _ in range(p):
        out = (out @ M) % 2
    return out

# Toric (surface-like): A = 1 + x, B = 1 + y  →  weight 4 per row
H_toric = np.concatenate([(I_lm + x) % 2, (I_lm + y) % 2], axis=1)
# Gross: A = x^3 + y + y^2, B = y^3 + x + x^2  →  weight 6 per row
H_gross = np.concatenate(
    [
        (mpow(x, 3) + mpow(y, 1) + mpow(y, 2)) % 2,
        (mpow(y, 3) + mpow(x, 1) + mpow(x, 2)) % 2,
    ],
    axis=1,
)

สิ่งที่ยังไม่ได้พิสูจน์คือผลลัพธ์ที่สอดคล้องกันสำหรับ การคำนวณ บน qubit ที่ถูกเข้ารหัส ซึ่งต้องใช้ปฏิบัติการ Clifford และ non-Clifford เชิงตรรกะที่โปรโตคอลหน่วยความจำไม่ได้ใช้ ซึ่งเป็นหัวข้อของ Section 3.4 นอกจากนี้ยังไม่ได้พิสูจน์ความเป็นไปได้ด้านฮาร์ดแวร์ด้วย การจำลองสมมติให้มีรอบ syndrome เจ็ดชั้นบนกราฟการเชื่อมต่อที่ชิปตัวนำยิ่งยวดเชิงพาณิชย์ในปัจจุบันยังไม่รองรับ นี่คือเหตุผลของโปรแกรมสถาปัตยกรรมระดับชิป (c-coupler, เลย์เอาต์แบบ biplanar และโปรเซสเซอร์ Loon ที่แนะนำใน Section 5.3) ซึ่งจำเป็นต่อการเปลี่ยนโค้ดที่จำลองให้กลายเป็นการออกแบบที่สร้างได้จริง หัวข้อย่อยที่เหลือของ Part 3 จะไล่ดูชิ้นส่วนที่ขาดเหล่านี้ (การขยายขนาดใน 3.3 และการคำนวณใน 3.4) ส่วนการถอดรหัสและฮาร์ดแวร์แบบโมดูลาร์จะอภิปรายใน Part 5

3.3 การขยายขนาดกรณีศึกษา: two-gross​

โค้ด gross เป็นเพียงหนึ่งในสมาชิกของตระกูล BB ไม่ใช่จุดสิ้นสุดเดียว คำถามถัดไปที่ตามมาตามธรรมชาติคือ โครงสร้างเดียวกันนี้ขยายไปสู่ระยะทาง (distance) ที่สูงขึ้นได้หรือไม่โดยไม่ต้องเปลี่ยนสถาปัตยกรรมโดยรวม และการขยายนั้นมีต้นทุน qubit เท่าไร คำตอบของเปเปอร์คือ โค้ด two-gross [[288,12,18]][[288,12,18]][[288,12,18]] ซึ่งได้จากการเลือกพหุนามที่เกี่ยวข้องบนแลตทิซที่ใหญ่ขึ้นภายในกรอบ bivariate-bicycle เดียวกัน โค้ดนี้คงจำนวน logical qubit ไว้ที่ 12 ตัว เพิ่ม distance จาก 12 เป็น 18 และเพิ่มจำนวน data qubit เป็นสองเท่าจาก 144 เป็น 288 (โดยจำนวน physical qubit ทั้งหมดเพิ่มจาก 288 เป็น 576 เมื่อรวม syndrome ancilla)

ลองดูค่าอัตราส่วน BPT จาก Section 2.3 โค้ด gross อยู่ที่ k d2/n=12k\,d^2 / n = 12kd2/n=12 และ two-gross อยู่ที่ 12⋅182/288=13.512 \cdot 18^2 / 288 = 13.512⋅182/288=13.5 อัตราส่วนเหล่านี้แสดงถึงประโยชน์ของการผ่อนคลายความเป็นท้องถิ่น 2D แบบเคร่งครัด ขอบเขต BPT ไม่ได้ใช้กับการตรวจสอบแบบไม่ท้องถิ่นเหล่านี้ Gross และ two-gross เป็นจุดดำเนินงานที่ distance จำกัดสองจุด โดยแบบแรกใช้ qubit น้อยกว่า ส่วนแบบหลังใช้งบ data qubit ที่เพิ่มเป็นสองเท่าเพื่อให้ได้ distance ที่สูงขึ้น การไล่จาก gross ไปเป็น two-gross เพิ่มความต้องการด้าน qubit และการเชื่อมต่อ สถาปัตยกรรมโมดูลาร์ของ IBM (Section 5.3) ถูกออกแบบมาเพื่อเชื่อมต่อโมดูลหน่วยความจำ โมดูลประมวลผล และโมดูลอื่น ๆ เมื่อระบบขยายขนาดขึ้น

ขั้นตอนการขยายขนาดนี้แสดงว่าตระกูล BB ขยายได้โดย เปลี่ยนการเลือกพหุนามบนแลตทิซที่ใหญ่ขึ้น ไม่ใช่โดยการทำซ้ำบล็อกโค้ดอิสระ (อย่างที่หน่วยความจำ surface code ทำเมื่อขยายไปยัง logical qubit หลายตัว) กรอบพีชคณิตเดียวกัน รูปร่าง Circuit การสกัด syndrome เดียวกัน และคลาสของปัญหาการถอดรหัสเดียวกัน ใช้ได้ทั้งตระกูล ตัวอย่างขนาดจำกัดเหล่านี้ไม่ได้พิสูจน์ ความดีเชิงเส้นกำกับ (asymptotic goodness) ซึ่งต้องการอัตราจำกัดที่ไม่เป็นศูนย์และ distance ที่โตเชิงเส้นตามความยาวโค้ด ประเด็นของกรณีศึกษาคือ ภายใน ช่วง distance จำกัด ที่เกี่ยวข้องกับแผนที่นำทางความทนทานต่อความผิดพลาดระยะใกล้ ตระกูล BB มีจุดดำเนินงานที่เป็นรูปธรรมซึ่งประเมินต้นทุนได้พร้อมกับข้อกำหนดด้านตัวถอดรหัสและการเชื่อมต่อ

3.4 การคำนวณเพิ่มอะไรจากหน่วยความจำ​

ผลลัพธ์ด้านหน่วยความจำของ Section 3.2 ปกป้องสถานะเชิงตรรกะที่เข้ารหัสไว้ แต่ไม่ได้ทำปฏิบัติการใด ๆ กับสถานะเหล่านั้น การคำนวณที่มีประโยชน์ต้องมี Gate เชิงตรรกะ (อย่างน้อยต้องเป็นเซตสากลที่ประกอบด้วยปฏิบัติการ Clifford และ non-Clifford) และวิธีนำ Gate เหล่านั้นไปใช้ระหว่างบล็อกโค้ด ตระกูล BB มีความท้าทายเชิงโครงสร้างเพิ่มเติมตรงนี้ เนื่องจากการตรวจสอบพาดข้ามชิปแบบไม่ท้องถิ่น แม้แต่ปฏิบัติการง่าย ๆ ภายในบล็อก BB เดียวก็ต้องระมัดระวังเพื่อรักษาคุณสมบัติของโค้ด และปฏิบัติการ ระหว่าง บล็อก BB ต้องใช้ชิ้นส่วนเชิงสถาปัตยกรรม (coupler, adapter และโรงงาน magic-state) ที่ไม่ได้เป็นส่วนของโครงสร้างหน่วยความจำ

เป็นกรณีศึกษา ตอนนี้เราจะดู Tour de gross (Yoder et al., 2025) ซึ่งแนะนำ สถาปัตยกรรม bicycle คือ ระบบ ทนต่อความผิดพลาดที่ประกอบจากโมดูลที่ผลิตแยกกัน โมดูลโค้ดแต่ละตัวมีบล็อกโค้ดหน่วยความจำและ หน่วยประมวลผลเชิงตรรกะ (LPU) ที่ต่อพ่วงอยู่ ซึ่งทำปฏิบัติการเชิงตรรกะผ่าน lattice surgery แบบทั่วไป โมดูลโรงงาน magic-state แยกต่างหากจัดหาทรัพยากร non-Clifford และ universal adapter ทำปฏิบัติการเชิงตรรกะระหว่างโมดูล เปเปอร์เดียวกันประเมินสถาปัตยกรรมนี้ตามเกณฑ์การออกแบบหกข้อ: ทนต่อความผิดพลาด (ข้อผิดพลาดเชิงตรรกะถูกกดลงมากพอให้อัลกอริทึมที่ตั้งใจไว้ทำงานสำเร็จ), ระบุตำแหน่งได้ (เตรียมหรือวัด logical qubit แต่ละตัวได้ระหว่างการคำนวณ), สากล (มีเซต Gate เชิงตรรกะครบ คือ Clifford บวก Gate non-Clifford หนึ่งตัว), ปรับตัวได้ (adaptive), เป็นโมดูลาร์ (สร้างจากโมดูลที่ผลิตแยกกันและสลับแทนกันได้) และ มีประสิทธิภาพ (ภาระ physical qubit และเวลาต่อปฏิบัติการเชิงตรรกะต่ำ) ในความหมายของเปเปอร์ adaptive หมายความว่าผลการวัด syndrome ถูกถอดรหัสแบบเรียลไทม์ และเปลี่ยนคำสั่งควอนตัมที่ตามมาได้ ซึ่งก็คือ feedforward แบบเรียลไทม์ที่แท้จริง (ตลอดบทเรียนนี้ เรากลับมองการแก้ไขเป็น การอัปเดตเฟรมแบบออฟไลน์ ซึ่งเป็นความสะดวกด้านการจำลองและการสอนโดยตั้งใจ เพื่อให้เซลล์โค้ดสั้นและแม่นยำ การคำนวณที่ทนต่อความผิดพลาดจริงต้องใช้ความสามารถ feedforward แบบเรียลไทม์และปรับตัวได้ตามที่อธิบายไว้ก่อนหน้า การแก้ไข SSS หลังการฉีด TTT และผลพลอยได้จาก lattice surgery ใน Part 4 เป็นจุดที่ Gate ในภายหลังขึ้นกับผลการวัดก่อนหน้า จึงเลื่อนไปทำแบบออฟไลน์ทั้งหมดไม่ได้) เปเปอร์รายงานการประมาณทรัพยากรแบบครบวงจรที่ชี้ว่าสามารถรัน Circuit เชิงตรรกะที่ใหญ่กว่าได้ระดับหนึ่งลำดับขนาดภายใต้งบ physical qubit เท่ากัน เมื่อเทียบกับสถาปัตยกรรม surface code

สถาปัตยกรรม bicycle: ระบบโมดูลาร์ทนต่อความผิดพลาดที่อิงโค้ด bivariate-bicycle โมดูลโค้ดแต่ละตัวรวมบล็อกโค้ดหน่วยความจำกับหน่วยประมวลผลเชิงตรรกะ (LPU) สำหรับปฏิบัติการเชิงตรรกะผ่าน lattice surgery แบบทั่วไป โมดูลโรงงาน magic-state แยกต่างหากจัดหาทรัพยากร non-Clifford และ universal adapter เชื่อมต่อโมดูลเข้าด้วยกัน ที่มา: fault-tolerance roadmap รายละเอียดเชิงสถาปัตยกรรมใน Yoder et al., 2025 คำถามสำคัญคือ ข้อได้เปรียบระดับหน่วยความจำจาก Section 3.2 ยังคงอยู่หรือไม่เมื่อมีภาระเพิ่มจากการคำนวณ ซึ่งรวม Gate เชิงตรรกะ ทรัพยากร magic-state การจัดเส้นทางระหว่างโมดูล การถอดรหัส และเลย์เอาต์ฮาร์ดแวร์ ข้อโต้แย้งเชิงกรณีศึกษาใน Yoder et al. 2025 คือ สถาปัตยกรรมที่อิง BB ยังแข่งขันกับสถาปัตยกรรมที่อิง surface code ได้หลังรวมภาระเหล่านี้แล้ว โดยรักษาข้อได้เปรียบด้านหน่วยความจำไว้บางส่วน ส่วนต่างที่แน่นอนในระดับอัลกอริทึมทั้งตัวยังเป็นคำถามการประมาณทรัพยากรที่ยังอยู่ระหว่างศึกษา และหลักฐานที่สนับสนุนเป็นการวิเคราะห์เชิงสถาปัตยกรรม ไม่ใช่การสาธิตเชิงทดลอง Part 4 ของบทเรียนนี้ไล่ดูด้าน Gate สากลของการคำนวณที่ทนต่อความผิดพลาด รวมถึงโครงสร้าง Clifford ทรัพยากร non-Clifford และการกลั่น magic-state นอกจากนี้ยังครอบคลุมข้อเสนอ single-block distillation ของ Xu et al., 2026 ซึ่งรันโรงงาน magic-state ภายในบล็อกโค้ด BB เพียงบล็อกเดียว ข้อเสนอนั้นนำความจุเชิงตรรกะของบล็อกเองกลับมาใช้ผ่าน qubit recycling (นำ physical qubit ชุดเดิมมาใช้ซ้ำในขั้นตอนการกลั่นต่อเนื่อง) แทนที่จะแยกบล็อกโค้ดเฉพาะไว้

3.5 การศึกษานี้แสดงอะไรและไม่ได้พิสูจน์อะไร​

ตลอด Section 3.1 ถึง 3.4 เราได้ไล่ดูโครงสร้าง BB (3.1) เกณฑ์วัดหน่วยความจำที่วางโค้ด gross ไว้บนแผนที่นำทางของ IBM (3.2) พฤติกรรมการขยายขนาดของตระกูลไปสู่ distance ที่สูงขึ้น (3.3) และชิ้นส่วนเชิงสถาปัตยกรรมที่การคำนวณเพิ่มเข้ามาเหนือหน่วยความจำ (3.4) สิ่งที่กรณีศึกษานี้ แสดง โดยรวมคือเส้นทางข้ามหลายเปเปอร์ที่ต่อเนื่องกัน: ตระกูลโค้ด qLDPC ที่กำหนดครบถ้วน การบัญชีหน่วยความจำที่ตีพิมพ์แล้วภายใต้สัญญาณรบกวนระดับ Circuit ที่สมจริง ขั้นตอนการขยายขนาดสู่ distance ที่สูงขึ้นที่แสดงให้เห็นภายในโครงสร้างเดียวกัน และข้อเสนอสถาปัตยกรรมระดับระบบที่รองรับการคำนวณสากลบน qubit ที่เข้ารหัส

สิ่งที่การศึกษานี้ ไม่ได้ พิสูจน์:

  • ความเหมาะสมที่สุด (Optimality) โค้ด bivariate-bicycle ไม่จำเป็นต้องเป็นตัวเลือก qLDPC ที่ดีที่สุดสำหรับอัลกอริทึมหรือแพลตฟอร์มใดโดยเฉพาะ โค้ด hypergraph-product, lifted-product และ quantum Tanner ก็มีอยู่ และมีข้อได้เปรียบเชิงเส้นกำกับและขนาดจำกัดของตัวเอง การเลือก BB ในแผนที่นำทางของ IBM เป็น การสอดคล้องเชิงสถาปัตยกรรม เพราะกราฟการตรวจสอบความหนา 2 ของมันเหมาะกับฮาร์ดแวร์ตัวนำยิ่งยวดและสถาปัตยกรรมโมดูลาร์ที่เสนอ ไม่ใช่ข้ออ้างว่าเหมาะสมที่สุดทางคณิตศาสตร์

  • จำนวนทรัพยากรระดับอัลกอริทึม การลดทรัพยากร หน่วยความจำ ราวหนึ่งลำดับขนาดที่ Bravyi et al. รายงานนั้นเป็นของแบบจำลองสัญญาณรบกวนและเป้าหมายเฉพาะ อัลกอริทึมจริงมีความต้องการทรัพยากรเพิ่มเติม (Gate การกลั่น magic-state การจัดเส้นทาง และเวลาแฝงของตัวถอดรหัสแบบเรียลไทม์) ที่การบัญชีหน่วยความจำไม่ได้นับรวม สรุปที่ตรงไปตรงมาที่สุดคือ ลดลงหนึ่งลำดับขนาดในงานหน่วยความจำ โดยภาระด้านการคำนวณและระดับระบบยังอยู่ระหว่างการสำรวจ

  • การมีอยู่จริงของฮาร์ดแวร์ การเชื่อมต่อที่โค้ด gross ต้องการในขนาดเต็มยังไม่ได้ถูกสร้าง ณ เวลาที่เขียน แผนที่นำทางชิปของ IBM (ตารางสายวิวัฒนาการใน Section 5.3) คือเส้นทางที่เสนอเพื่อสร้างมัน ส่วนไทม์ไลน์จะเป็นไปตามนั้นหรือไม่เป็นเรื่องของการลงมือทางวิศวกรรม ไม่ใช่ผลทฤษฎีโค้ดที่ตีพิมพ์ใด ๆ

4.1 โครงสร้าง Clifford และความจำเป็นของทรัพยากร non-Clifford​

ก่อนลงรายละเอียด นี่คือภาพรวมของส่วนนี้ในตารางเดียว:

ปฏิบัติการทำไมจึงง่ายหรือยากบน stabilizer code
Gate Clifford (HHH, SSS, CNOT)จัดการได้ค่อนข้างเป็นธรรมชาติ เพราะรักษาโครงสร้าง Pauli
Gate TTTให้ทรัพยากร non-Clifford โดยในที่นี้ทำผ่าน magic state
การกลั่น magic-stateแปลง magic state ที่มีสัญญาณรบกวนจำนวนมากให้เป็นจำนวนน้อยลงแต่สะอาดขึ้น โดยมีต้นทุน

กลุ่ม Clifford C\mathcal{C}C คือเซตของยูนิทารีที่แมปตัวดำเนินการ Pauli ไปเป็นตัวดำเนินการ Pauli ภายใต้การสังยุค (conjugation) ตัวกำเนิดมาตรฐานคือ Gate Hadamard HHH, Gate เฟส S=diag(1,i)S = \mathrm{diag}(1, i)S=diag(1,i) และ CNOT\mathrm{CNOT}CNOT สองควิบิต ปฏิบัติการ Clifford รักษาโครงสร้าง Pauli ดังนั้นการเข้ารหัส Gate Clifford เชิงตรรกะ และการวัด stabilizer จึงอธิบายได้ภายในกรอบนี้ทั้งหมด สำหรับ surface code Clifford เชิงตรรกะทำผ่าน lattice surgery (การตัดและต่อแพตช์) ร่วมกับ Gate transversal ที่เลือกไว้ Gate แบบ transversal ถูกใช้กับแต่ละ qubit อย่างอิสระ โดยไม่มี qubit สองตัวของบล็อกมีปฏิสัมพันธ์กัน ดังนั้นข้อผิดพลาดทางกายภาพเพียงจุดเดียวจึงไม่ขยายเป็นข้อผิดพลาดน้ำหนักสูงภายในบล็อก นี่คือสิ่งที่ทำให้ Gate เช่นนี้ทนต่อความผิดพลาดโดยอัตโนมัติ สำหรับโค้ด BB สถาปัตยกรรม bicycle ใน Section 3.4 ใช้ lattice surgery แบบทั่วไปภายในหน่วยประมวลผลเชิงตรรกะ โดยมีโครงสร้างที่เป็นมิตรกับ Clifford แบบเดียวกันอยู่ข้างใต้

กลุ่ม Clifford เพียงอย่างเดียวไม่สากลสำหรับการคำนวณควอนตัม ทฤษฎีบท Gottesman-Knill ทำให้ข้อจำกัดนี้ชัดเจน Circuit ควอนตัมใด ๆ ที่ใช้เพียงการเตรียมสถานะในฐานคำนวณ Gate Clifford และการวัดในฐานคำนวณ สามารถจำลองด้วยคอมพิวเตอร์คลาสสิกได้อย่างมีประสิทธิภาพ (Gottesman, 1998) ดังนั้นการคำนวณสากลต้องมี Gate non-Clifford อย่างน้อยหนึ่งตัว ตัวเลือกมาตรฐานคือ Gate T=diag(1,eiπ/4)T = \mathrm{diag}(1, e^{i\pi/4})T=diag(1,eiπ/4) (Gate π/8\pi/8π/8) ซึ่งเมื่อรวมกับกลุ่ม Clifford จะก่อกำเนิดกลุ่มย่อยหนาแน่นของ SU(2n)\mathrm{SU}(2^n)SU(2n) การทำ TTT ให้ทนต่อความผิดพลาดเป็นขั้นที่ยากในการคำนวณสากลที่ทนต่อความผิดพลาด และส่วนที่เหลือของ Part นี้จะไล่ดูว่าทำได้อย่างไร

"lattice surgery" ทำอะไรกันแน่? (เจาะลึก)

Lattice surgery ทำการวัด Pauli เชิงตรรกะร่วมโดยเปลี่ยนการตรวจสอบข้ามแพตช์โค้ดชั่วคราว สำหรับ CNOT เชิงตรรกะของ surface code ที่มีตัวควบคุม CCC และเป้าหมาย TTT คำอธิบายแบบอิงการวัดแบบหนึ่งคือ เตรียม logical qubit ช่วย AAA ใน ∣+⟩L|+\rangle_L∣+⟩L​ วัด ZˉCZˉA\bar{Z}_C\bar{Z}_AZˉC​ZˉA​ แล้ววัด XˉAXˉT\bar{X}_A\bar{X}_TXˉA​XˉT​ และสุดท้ายวัด ZˉA\bar{Z}_AZˉA​ โดยการอัปเดตเฟรม Pauli ถูกกำหนดจากผลลัพธ์ทั้งสามค่า การวัด ZˉCZˉT\bar{Z}_C\bar{Z}_TZˉC​ZˉT​ ร่วมเพียงครั้งเดียวเป็นแค่การฉายลงบนสเปซย่อยพาริตี และไม่ใช่ CNOT การทำจริงทางกายภาพใช้การสกัด syndrome ซ้ำ ๆ และเลย์เอาต์ที่รักษาการป้องกันข้อผิดพลาดตลอดปฏิบัติการ ปฏิบัติการ Clifford เชิงตรรกะอื่น ๆ ต้องใช้เทคนิคการเปลี่ยนรูปโค้ดหรือสถานะช่วยที่เกี่ยวข้อง

ในสถาปัตยกรรม bicycle การผ่าตัด qLDPC แบบทั่วไปและหน่วยประมวลผลเชิงตรรกะ (LPU) ทำให้วัด Pauli เชิงตรรกะที่เลือกไว้ได้ เมื่อรวมกับคำสั่งอื่น ๆ ของสถาปัตยกรรม สิ่งเหล่านี้รองรับการคำนวณเชิงตรรกะ ส่วนการฉาย magic-state จัดหาทรัพยากร non-Clifford ที่จำเป็นต่อความเป็นสากล

4.2 Gate TTT ผ่านการฉาย magic-state​

Surface code ไม่รองรับ TTT เชิงตรรกะแบบ transversal สถาปัตยกรรม surface-code และ BB ที่อภิปรายตรงนี้ทำมันผ่านการฉาย magic-state แนวทางคือการใช้ magic state ซึ่งเป็น ∣A⟩=T∣+⟩=(∣0⟩+eiπ/4∣1⟩)/2|A\rangle = T|+\rangle = (|0\rangle + e^{i\pi/4}|1\rangle)/\sqrt{2}∣A⟩=T∣+⟩=(∣0⟩+eiπ/4∣1⟩)/2​ เชิงตรรกะที่เตรียมไว้ล่วงหน้า แล้วทำ Circuit ที่ใช้เพียง Clifford ซึ่งมีผลเท่ากับการใช้ TTT กับ data qubit Circuit แสดงด้านล่างเป็นแผนภาพคงที่ บทเรียนนี้มองการแก้ไข Clifford แบบมีเงื่อนไขที่ตามหลังการวัด ancilla เป็น การอัปเดตเฟรม Clifford ไม่ใช่การแก้ไขกลาง Circuit แบบแอคทีฟ

# Static T-gate teleportation / injection circuit.

inj = QuantumCircuit(2, 1)
# q0 = data |psi> (prepared elsewhere); q1 = ancilla magic state |A> = T|+>
inj.h(1)
inj.t(1)  # prepare |A> = T|+> on the ancilla (q1)
inj.barrier()
inj.cx(0, 1)  # CNOT: control = data (q0), target = ancilla (q1)
inj.measure(1, 0)  # measure ancilla; outcome 1 corresponds to an S-frame update on q0

inj.draw("mpl", style="iqp")

ตามทฤษฎีบท Gottesman-Knill Circuit ที่ใช้เพียง Gate ระดับ 2 กับการเตรียมและการวัดในฐานคำนวณ จำลองบนคอมพิวเตอร์คลาสสิกได้อย่างมีประสิทธิภาพ ดังนั้นการคำนวณควอนตัมสากลต้องมีทรัพยากร non-Clifford อย่างน้อยหนึ่งอย่าง Gate TTT เป็นตัวเลือกมาตรฐานเพราะเป็น Gate ที่ง่ายที่สุดในแบบนี้ และ {C,T}\{\mathcal{C}, T\}{C,T} หนาแน่นใน SU(2n)\mathrm{SU}(2^n)SU(2n) แต่ไม่มีอะไรในทฤษฎีที่บังคับให้ใช้ TTT แทน Toffoli หรือปฏิบัติการระดับสูงกว่า

ทฤษฎีบท Eastin-Knill ผลลัพธ์ข้อที่สองมีข้อจำกัดมากกว่า ทฤษฎีบท Eastin-Knill ระบุว่าโค้ดที่ตรวจจับข้อผิดพลาด qubit เดี่ยวใด ๆ ไม่สามารถมีเซตสากลของ Gate เชิงตรรกะแบบ transversal ได้ (Eastin and Knill, 2009) Gate ใดเป็น transversal ขึ้นกับโค้ด สถาปัตยกรรม surface-code และ BB ที่อภิปรายตรงนี้ใช้การฉาย magic-state สำหรับ TTT เชิงตรรกะ เซต transversal ไม่ใช่ กลุ่ม Clifford เสมอไป ตัวอย่างเช่น โค้ด Reed-Muller [[15,1,3]][[15,1,3]][[15,1,3]] ที่ใช้กลั่นใน Section 4.3 มี TTT แบบ transversal แทน ประเด็นของ Eastin-Knill คือข้อจำกัดต่อเซต transversal สากลสำหรับโค้ดที่กำหนด ต้องมีกลไกทนต่อความผิดพลาดเพิ่มเติม เช่นการฉาย magic-state เพื่อให้เป็นสากล

ทำไมการฉายจึงแก้ปัญหานี้ การฉายทำ TTT เชิงตรรกะโดยใช้ปฏิบัติการ Clifford การวัด และ magic state เชิงตรรกะ ∣A⟩|A\rangle∣A⟩ ที่จัดหามา การเตรียม magic state นั้นต้องใช้ทรัพยากร non-Clifford การเตรียมสถานะทำแบบ ออฟไลน์ แยกจากช่วงเวลาที่ใช้ได้ การกลั่นใน Section 4.3 ยกการเตรียมแบบออฟไลน์นั้นขึ้นสู่ความเที่ยงตรงระดับเชิงตรรกะ

วิธีการฉายที่คล้ายกันใช้ได้กับ Gate non-Clifford ตัวอื่น การประมาณทรัพยากรที่ทนต่อความผิดพลาดจำนวนมากใช้ magic state บางชนิด โดยทั่วไปคือ ∣A⟩|A\rangle∣A⟩ สำหรับ TTT, ∣CCZ⟩|\mathrm{CCZ}\rangle∣CCZ⟩ สำหรับ Toffoli หรือสถานะอันดับสูงกว่า การเลือก TTT ตลอดบทเรียนนี้เป็นข้อตกลงอ้างอิง

การแปลงจาก "ทำ TTT เชิงตรรกะ" ตอนนี้กลายเป็น "จัดหา magic state เชิงตรรกะ ∣A⟩|A\rangle∣A⟩ ที่มีความเที่ยงตรงสูง" ซึ่งเป็นปัญหาการจัดหาทรัพยากร ส่วนที่เหลือของ Part นี้จะกล่าวถึงการจัดหานั้น

4.3 การกลั่น magic-state​

ควรหยุดคิดสักครู่ว่า ทำไม จึงต้องมีขั้นตอนการทำให้บริสุทธิ์แยกต่างหาก ทุกอย่างที่คอมพิวเตอร์ทนต่อความผิดพลาดทำได้ในราคาถูก (Gate Clifford และการวัด stabilizer) ถูกโค้ดปกป้องโดยตรง ส่วนผสมที่ขาดไปคือ Gate non-Clifford TTT การฉาย magic-state หลบปัญหานี้โดยใช้สถานะ ∣A⟩|A\rangle∣A⟩ ที่ทำไว้ล่วงหน้าผ่าน Circuit ที่ใช้เพียง Clifford แต่ความยากเพียงแค่ย้ายที่ magic state ดิบที่ฉายเข้าไปรับข้อผิดพลาดระดับกายภาพมาด้วย และมีสัญญาณรบกวนมากเกินไปสำหรับ Circuit เชิงตรรกะที่ลึก Gate TTT ที่ใช้ผ่าน ∣A⟩|A\rangle∣A⟩ ดิบที่ความเที่ยงตรง 1−10−21 - 10^{-2}1−10−2 ใช้ไม่ได้เลยกับ Circuit เชิงตรรกะที่มุ่งข้อผิดพลาดเชิงตรรกะ 10−1210^{-12}10−12

การกลั่น (Distillation) คือทางออกมาตรฐาน มันรับ magic state ที่มีสัญญาณรบกวนจำนวนมากเป็นอินพุต และให้เอาต์พุตที่มีความเที่ยงตรงสูงจำนวนน้อยกว่า โดยใช้เพียงปฏิบัติการ Clifford และการวัดซึ่งโค้ดพื้นฐานรองรับโดยธรรมชาติ โปรโตคอลที่ศึกษากันมากที่สุดคือ การกลั่น 15-to-1 (Bravyi and Kitaev, 2005) magic state ที่มีสัญญาณรบกวนสิบห้าตัวที่ความน่าจะเป็นข้อผิดพลาด ppp ให้เอาต์พุตหนึ่งตัวที่ ∼35 p3\sim 35\,p^3∼35p3 โดยใช้โค้ด Reed-Muller [[15,1,3]][[15,1,3]][[15,1,3]] (ตัวเลข 353535 นับรูปแบบข้อผิดพลาดน้ำหนัก 3 ชั้นนำที่ตรวจไม่พบ) การกดแบบกำลังสาม p→35 p3p \to 35\,p^3p→35p3 ถูกทำซ้ำหลายรอบ เริ่มจากข้อผิดพลาดดิบ p=10−2p = 10^{-2}p=10−2 หนึ่งรอบให้ ∼3.5×10−5\sim 3.5 \times 10^{-5}∼3.5×10−5 และสองรอบให้ ∼1.5×10−12\sim 1.5 \times 10^{-12}∼1.5×10−12 แต่ละรอบคูณต้นทุนสถานะดิบด้วย 15 ดังนั้นการไปถึงเป้าหมายข้อผิดพลาดที่ลึกจึงแพงในแง่จำนวนสถานะอินพุตที่ต้องใช้

# Distillation rounds: error vs raw-state cost. Uses shared imports.
def distill_rounds(p_in, rounds):
    rows, p, raw = [], p_in, 1
    rows.append({"round": 0, "error_estimate": p, "raw_states_per_output": raw})
    for r in range(1, rounds + 1):
        p = 35 * p**3
        raw *= 15
        rows.append({"round": r, "error_estimate": p, "raw_states_per_output": raw})
    return pd.DataFrame(rows)

4.5 Part นี้พิสูจน์อะไรและไม่ได้พิสูจน์อะไร​

สถาปัตยกรรมที่อภิปรายตรงนี้รวมส่วนประกอบเดียวกัน: ปฏิบัติการ Clifford ที่ทนต่อความผิดพลาด ทรัพยากร non-Clifford (Gate TTT ผ่าน magic state) และโปรโตคอลการกลั่นเพื่อนำความเที่ยงตรงของ magic-state ไปถึงระดับที่การคำนวณเชิงตรรกะต้องการ Part 4 ไล่ดูส่วนประกอบพื้นฐานเหล่านี้ในรูปแบบทั่วไป พร้อมการเฉพาะทางหนึ่งอย่างสำหรับกรณีศึกษา BB (การกลั่นบนโค้ด BB อัตราสูง)

Part 3 และ 4 มอง QEC ในระดับโค้ดเป็นหลัก ครอบคลุมว่าโค้ดมีโครงสร้าง stabilizer แบบใด รองรับ Gate อะไร และปฏิบัติการของมันต้องมีภาระเท่าไร คอมพิวเตอร์ทนต่อความผิดพลาดจริงต้องทำมากกว่าตอบสนองข้อกำหนดระดับโค้ดเหล่านี้ มันต้องอ่าน syndrome แบบเรียลไทม์ ถอดรหัสบนฮาร์ดแวร์คลาสสิกให้เร็วพอตามรอบ QEC ทัน จัดเส้นทางปฏิบัติการเชิงตรรกะระหว่างบล็อกโค้ด และผสานทุกอย่างเข้าเป็นฮาร์ดแวร์โมดูลาร์ที่ผลิตได้ Part นี้ไล่ดูชิ้นส่วนระดับระบบ โดยใช้กรณีศึกษาตัวนำยิ่งยวดของ IBM เป็นตัวอย่างต่อเนื่อง การประหยัด qubit ของ Part 3 กลับมาปรากฏตรงนี้ในรูปต้นทุนการคำนวณคลาสสิก (การถอดรหัส) และฮาร์ดแวร์ (การเชื่อมต่อ สถาปัตยกรรม) บัญชีรวมตัวถอดรหัสและสายสัญญาณด้วย ไม่ใช่แค่โค้ด

5.1 ตัวถอดรหัสในฐานะครึ่งคลาสสิกของ QEC​

ตัวถอดรหัสแก้ปัญหาการอนุมานแบบคลาสสิก เมื่อได้ประวัติ syndrome ที่มีสัญญาณรบกวน มันอนุมานคลาสการกู้คืนที่น่าจะเป็นโดยไม่ได้เรียนรู้สถานะเชิงตรรกะที่ถูกปกป้อง

เมื่อวัดการตรวจสอบของ stabilizer code ผลที่ได้คือบิตสตริงคลาสสิกที่เรียกว่า syndrome ซึ่งบอกว่าการตรวจสอบใดทำงาน หน้าที่ของ ตัวถอดรหัส (decoder) คือรับ syndrome นี้และอนุมานว่าข้อผิดพลาดใดน่าจะเกิดขึ้นมากที่สุด เพื่อให้นำข้อผิดพลาดที่อนุมานได้ไปพิจารณาในการตีความเชิงตรรกะ โดยปกติด้วยการอัปเดตเฟรม Pauli/Clifford คลาสสิก แทนที่จะย้อนข้อผิดพลาดทางกายภาพใน notebook ตัวถอดรหัสจึงเป็น คลาสสิก มันรันบนฮาร์ดแวร์ทั่วไป เช่น field-programmable gate array (FPGA), application-specific integrated circuit (ASIC), GPU หรือ CPU และเป็นส่วนหนึ่งของลูปควอนตัม-คลาสสิกซึ่งถ้าไม่มี stabilizer code ก็ไม่ปกป้องข้อมูลใด ๆ

ตัวถอดรหัสที่ง่ายที่สุดเป็นไปได้คือ ตารางค้นหา (lookup table) ฟังก์ชันจาก syndrome (บิตสตริง) ไปเป็นข้อผิดพลาดที่น่าจะเป็นที่สุด (สตริง Pauli) สำหรับโค้ดที่มีการตรวจสอบน้อยมากสิ่งนี้เป็นเรื่องเล็ก แต่วิธีตารางค้นหาขยายขนาดไม่ได้ จำนวนรายการเพิ่มเป็น 2m2^{m}2m ตามจำนวนการตรวจสอบ mmm ดังที่เซลล์ถัดไปจะแสดง

5.2 กลุ่มตัวถอดรหัสในแต่ละกลุ่มโค้ด​

โค้ด surface ส่วนใหญ่ถอดรหัสด้วย minimum-weight perfect matching (MWPM) ข้อบกพร่องของซินโดรมเกิดเป็นคู่ที่ปลายของสายข้อผิดพลาด และการจับคู่ที่มีน้ำหนักน้อยที่สุดให้ผลการอนุมานข้อผิดพลาดที่น่าจะเป็นไปได้มากที่สุด MWPM ทำงานในเวลาพหุนาม (blossom algorithm for minimum-weight matching) ถูกพัฒนาเป็นการทำงานบน FPGA ที่ให้ค่าหน่วงเวลาแบบเรียลไทม์ และเป็นเกณฑ์อ้างอิงที่สมบูรณ์สำหรับต้นแบบทนข้อผิดพลาด

minimum-weight matching มาตรฐานใช้กับโค้ด bivariate-bicycle โดยตรงไม่ได้ ข้อผิดพลาด Pauli เพียงตัวเดียวสามารถกระตุ้นบิตซินโดรมได้มากกว่าสองบิต ปัญหาข้อผิดพลาดที่น่าจะเป็นไปได้มากที่สุดจึงไม่ใช่การจับคู่ธรรมดาอีกต่อไป ตัวถอดรหัส qLDPC มาตรฐานคือ belief propagation ร่วมกับ ordered-statistics decoding (BP + OSD) BP อนุมานข้อผิดพลาดที่เป็นไปได้โดยส่งข้อความบน Tanner graph ของโค้ด (กราฟสองส่วนที่มีโหนดสำหรับทุกคิวบิตและทุกการตรวจสอบ และมีเส้นเชื่อมเมื่อการตรวจสอบนั้นแตะคิวบิต) และ OSD จัดการกรณีที่ BP ไม่ลู่เข้า BP + OSD แม่นยำ แต่อาจช้าเกินไปสำหรับลูปแบบเรียลไทม์

Relay-BP (Müller et al., 2025) เป็นข้อเสนอล่าสุดของ IBM ที่เร่งการลู่เข้าของ BP เพื่อแก้ปัญหาค่าหน่วงเวลานี้ ความเร็วสำคัญเพราะรอบ QEC ของตัวนำยิ่งยวดสร้างซินโดรมใหม่ประมาณทุก 1 µs ถ้าตัวถอดรหัสตาม โดยเฉลี่ย ไม่ทัน ซินโดรมที่ยังไม่ได้ประมวลผลจะสะสม (backlog problem) และข้อผิดพลาดเชิงตรรกะจะเพิ่มขึ้น โค้ดที่ดีกว่าเพียงอย่างเดียวช่วยตัวถอดรหัสที่ตามไม่ทันไม่ได้ ข้อกำหนดที่เป็นตัวตัดสินจึงไม่ใช่แค่ความแม่นยำ แต่ต้องรักษาเวลาถอดรหัสเฉลี่ยให้อยู่ในงบต่อรอบ ค่าหน่วงเวลาของตัวถอดรหัสจึงเป็น ข้อกำหนดระดับระบบ ต้นแบบ FPGA ในเวลาต่อมาทำให้ค่าหน่วงเวลาถอดรหัสต่อรอบอยู่ภายใต้งบนี้ (Maurer et al., 2025)

5.3 สถาปัตยกรรมแบบโมดูลาร์: การเชื่อมต่อ ตัวคับเปลอร์ และสายวิวัฒนาการของชิป​

ตัวถอดรหัสเป็นครึ่งคลาสสิกของระบบ และ กราฟการเชื่อมต่อ ของคิวบิตทางกายภาพเป็นครึ่งควอนตัม ต้นทุนที่ย้ายออกจากจำนวนคิวบิตทางกายภาพใน ส่วนที่ 3.2 มาตกอยู่ที่นี่ การตรวจสอบน้ำหนัก 6 ของโค้ด BB มีเส้นเชื่อมระยะไกลที่ฮาร์ดแวร์เพื่อนบ้านใกล้สุด 2D ทั่วไปให้ไม่ได้ คำตอบระดับชิปคือคัปเปลอร์ที่เชื่อมข้ามชิป

C-coupler ซึ่งเชื่อมคิวบิตที่อยู่ไกลกว่าเพื่อนบ้านใกล้สุด ช่วยให้เกิดการเชื่อมต่อระยะไกลภายในชิปควอนตัมเดียว นี่คือคำตอบระดับฮาร์ดแวร์ต่อต้นทุนด้าน "การเชื่อมต่อ" ที่ระบุไว้ในย่อหน้าข้างต้น ขณะที่ surface code ต้องการเพียงคัปเปลอร์เพื่อนบ้านใกล้สุด โค้ดแบบ gross code ต้องการการเชื่อมต่อระยะไกลกว่าอีกไม่กี่เส้น กราฟการตรวจสอบเป็นผังดีกรี 6 ของกราฟย่อยระนาบสองกราฟที่ไม่มีเส้นเชื่อมร่วมกัน ส่วนใหญ่เป็นระยะใกล้และมีเส้นเชื่อมระยะไกลบางส่วน โปรเซสเซอร์ IBM Quantum Loon เป็นชิปทดลองที่ใช้ c-coupler สร้างขึ้นสำหรับการทดลองพิสูจน์แนวคิดกับโค้ด qLDPC อัตราสูงโดยเฉพาะ ที่มา: IBM fault-tolerance roadmap รูป c-coupler ข้างต้นแสดงการตอบสนองด้านฮาร์ดแวร์แบบหนึ่ง แพลตฟอร์มอื่นรับมือกับความท้าทายด้านการเชื่อมต่อเดียวกันด้วยวิธีต่างกัน ดังที่ ส่วนที่ 5.4 สรุปไว้ ในสถาปัตยกรรมแบบโมดูลาร์ของ IBM l-coupler ระหว่างโมดูลเชื่อมชิปที่ผลิตแยกกัน และรองรับอะแดปเตอร์สากลระหว่างโมดูล สิ่งนี้เป็นเส้นทางสู่การสเกลหน่วยความจำและการประมวลผลโดยไม่ต้องให้ทุกส่วนประกอบอยู่บนชิปเดียว หลักไมล์ด้านการทนข้อผิดพลาดใน IBM roadmap สรุปไว้ด้านล่าง

5.4 แพลตฟอร์มอื่น​

มุมมองระดับระบบยังอธิบายด้วยว่าทำไมแพลตฟอร์มฮาร์ดแวร์ที่ต่างกันจึงเอนเอียงไปทางกลุ่มโค้ดที่ต่างกันโดยธรรมชาติ

แพลตฟอร์มจุดแข็งแนวทาง QEC ตัวอย่าง
ตัวนำยิ่งยวดเกตเร็ว การควบคุมที่สมบูรณ์surface เป็นเกณฑ์พื้นฐาน; qLDPC ผ่าน c-coupler ระยะไกล
อะตอมเป็นกลางอาร์เรย์ขนาดใหญ่ เรขาคณิตปรับเปลี่ยนได้เหมาะกับผังแบบเบาบาง/ไม่เป็นท้องถิ่น (hypergraph-product, สไตล์ HGP)
ไอออนที่ถูกกักไว้ความเที่ยงตรงสูง การเชื่อมต่อยืดหยุ่นการสาธิตโค้ดขนาดเล็ก เส้นทางแบบโมดูลาร์
โฟโทนิกส์เครือข่าย อิงการวัดสถาปัตยกรรมทนข้อผิดพลาดแบบ fusion-based

การจับคู่นี้ไม่ใช่การจัดอันดับ แต่ละแพลตฟอร์มมีความสามารถด้านการเชื่อมต่อและกลไกข้อผิดพลาดหลักของตัวเอง และกลุ่มโค้ดที่เหมาะที่สุดก็สะท้อนความสามารถเหล่านั้น ระบบไอออนที่ถูกกักไว้รองรับเกตแบบทุกตัวต่อทุกตัวที่มีความเที่ยงตรงสูงภายในกับดักไอออนหนึ่งตัว ซึ่งช่วยให้การตรวจสอบที่ไม่เป็นท้องถิ่นทำได้ง่ายขึ้น การสเกลข้ามกับดักเพิ่มต้นทุนของการขนส่งไอออนหรือการเชื่อมโยงระหว่างโมดูล อะตอมเป็นกลางรองรับเรขาคณิตที่ปรับเปลี่ยนได้ (ย้ายอะตอมระหว่างการดำเนินการได้) ซึ่งเหมาะกับโค้ดไม่เป็นท้องถิ่นแบบเบาบาง รวมถึง hypergraph-product และโครงสร้างสไตล์ BB แนวทางโฟโทนิกส์รวมถึงโปรโตคอลแบบ fusion-based และอิงการวัด ซึ่งซินโดรมข้อผิดพลาดถูกสร้างขึ้นใหม่จากการรวมกันของผลการวัด รวมถึงผล fusion (Bartolucci et al., 2021)

ประเด็นไม่ใช่ว่าแพลตฟอร์มใดแพลตฟอร์มหนึ่งเป็นแพลตฟอร์มที่ "ถูกต้อง" แต่คือการออกแบบการทนข้อผิดพลาดปรับ สามส่วน โค้ด-ตัวถอดรหัส-ฮาร์ดแวร์ ให้เหมาะสมที่สุด และจุดที่ต่างกันในพื้นที่นั้นนำไปสู่ทางเลือกโค้ดที่สมเหตุสมผลต่างกัน คอขวดของการทนข้อผิดพลาดเคลื่อนที่ไปมา แต่โครงสร้างระดับระบบไม่ขึ้นกับแพลตฟอร์ม

5.5 สรุป​

QEC ต้องมีตัวถอดรหัสคลาสสิก กราฟการเชื่อมต่อที่การตรวจสอบของโค้ดนำไปใช้ได้ และสถาปัตยกรรมระบบที่รวมทั้งสองอย่างเข้ากับฮาร์ดแวร์ควอนตัม กรณีศึกษาตัวนำยิ่งยวดของ IBM (สายวิวัฒนาการชิปที่จัดเป็นตารางใน ส่วนที่ 5.3) ให้ลำดับหลักไมล์ที่เป็นรูปธรรมสำหรับการรวมนี้บนแพลตฟอร์มหนึ่ง

นี่ไม่ได้หมายความว่าเราบรรลุการคำนวณควอนตัมทนข้อผิดพลาดในระดับใหญ่แล้ว ยังต้องการนวัตกรรมฮาร์ดแวร์อีก ดังที่ระบุไว้ใน IBM Quantum Roadmap นอกจากนี้ คำถามเกี่ยวกับความซับซ้อนและความเร็วของตัวถอดรหัสยังเป็นหัวข้อของงานวิจัยปัจจุบัน โชคดีที่เราไม่ต้องรอ เราใช้การกดข้อผิดพลาดควอนตัม การลดผลกระทบ และการแก้ไขพื้นฐานได้ตั้งแต่วันนี้ ขณะที่มุ่งสู่การคำนวณควอนตัมทนข้อผิดพลาดขนาดใหญ่

ตรวจสอบความเข้าใจของคุณ​

การถอดรหัสด้วย lookup table สเกลเป็น 2(number of checks)2^{(\text{number of checks})}2(number of checks) ซึ่งใช้ได้กับโค้ดการทำซ้ำสามคิวบิต (การตรวจสอบสองตัว) ทำไมมันจึงใช้ไม่ได้กับ gross code (การตรวจสอบ ∼144\sim 144∼144 ตัว) และอะไรมาแทนที่?

คำตอบ

gross code จะต้องมีรายการในตาราง 2144≈10432^{144} \approx 10^{43}2144≈1043 รายการ ซึ่งเกินกว่าตารางใดๆ ที่จะเก็บได้จริงอย่างมาก ตัวถอดรหัสที่ใช้งานได้จริงจึง อนุมาน ข้อผิดพลาดที่น่าจะเป็นไปได้มากที่สุดด้วยอัลกอริทึมแทนการไล่นับซินโดรม โดยใช้ MWPM สำหรับ surface code, BP+OSD สำหรับโค้ด BB และ Relay-BP สำหรับการถอดรหัส qLDPC แบบเรียลไทม์ (ซินโดรมยังคงเป็นบิตสตริงคลาสสิก อุปสรรคคือ ขนาด ที่เพิ่มแบบเอกซ์โพเนนเชียลของปริภูมิซินโดรม ไม่ใช่ชนิดของมัน)

ลองพิจารณารอบ QEC ของตัวนำยิ่งยวดที่ให้ซินโดรมใหม่ทุก 1 µs ทำไมตัวถอดรหัสต้องตาม โดยเฉลี่ย ให้ทัน และจะเกิดอะไรขึ้นถ้าตามไม่ทัน?

คำตอบ

ตัวถอดรหัสต้องประมวลผลข้อมูลซินโดรมอย่างน้อยเร็วเท่ากับที่ข้อมูลเข้ามา มิฉะนั้น backlog จะเพิ่มขึ้นและการดำเนินการที่ขึ้นกับผลที่ถอดรหัสแล้วต้องรอ throughput ควบคุม backlog นี้ ขณะที่ค่าหน่วงเวลาการถอดรหัสก็สำคัญสำหรับ feedforward แบบเรียลไทม์ด้วย Relay-BP ออกแบบมาสำหรับการทำงานแบบขนานที่รวดเร็วบน FPGA หรือ ASIC (Müller et al., 2025) และงาน FPGA ต่อมาแสดงให้เห็นการถอดรหัสหน่วยความจำ gross-code แบบเรียลไทม์ (Maurer et al., 2025) การถอดรหัสเลื่อนไปทำตอนท้ายเสมอไม่ได้ เพราะคำสั่งควอนตัมที่ตามมาอาจขึ้นกับผลการวัดก่อนหน้า

ส่วนที่ 6: การแก้ไขข้อผิดพลาดควอนตัมในกรอบของความได้เปรียบเชิงควอนตัม​

Lanes et al., 2025 วางรากฐานความได้เปรียบบนสองเกณฑ์ ผลลัพธ์ต้องได้รับการ ตรวจสอบ อย่างเข้มงวด และต้องแสดง ความแยกเชิงควอนตัม ที่แท้จริงเหนือวิธีคลาสสิก ในทางปฏิบัติ สเปกตรัมความแม่นยำช่วยให้เราแปลงสองเกณฑ์นั้นเป็นสี่คำถามที่เป็นรูปธรรมสำหรับข้อกล่าวอ้างใดๆ

  1. งานคืออะไร? ปัญหาการสุ่มตัวอย่าง การคำนวณค่าคาดหมาย การค้นหา การจำลองเชิงโครงสร้าง และปัญหาแอนะล็อก ล้วนมีเกณฑ์ความถูกต้องต่างกัน

  2. ตรวจสอบความถูกต้องอย่างไร? ต้องตรวจสอบความถูกต้องอย่างเข้มงวด ขณะที่ประสิทธิภาพประเมินเทียบกับวิธีคลาสสิกที่ดีที่สุดที่มีอยู่ การตรวจสอบอาจใช้การตรวจสอบแบบคลาสสิก การตรวจสอบข้ามระหว่างวิธีต่างๆ หรือสมบัติเชิงโครงสร้าง เช่น peakedness ในการสุ่มตัวอย่าง

  3. จ่ายทรัพยากรอะไร? ตัวอย่าง คิวบิต การคำนวณถอดรหัส เวลารัน การเชื่อมต่อ เวลาปรับเทียบ หรือการประมวลผลหลังคลาสสิก เครื่องมือแต่ละอย่างบนสเปกตรัมจ่ายทรัพยากรต่างกัน

  4. QEC รักษาหรือลบความแยกเชิงควอนตัมหลังจากค่าโสหุ้ยหรือไม่? แม้ QEC จะทำงานตามที่ตั้งใจ ค่าโสหุ้ยที่มันเพิ่มอาจลดความแยกระหว่างอัลกอริทึมควอนตัมกับคลาสสิกมากกว่าที่การเร่งความเร็วเชิงอัลกอริทึมได้มา สำหรับวงจรลึกที่มีเป้าหมายข้อผิดพลาดเชิงตรรกะเข้มงวด QEC เป็นเส้นทางมาตรฐานสู่การควบคุมข้อผิดพลาดที่สเกลได้ สำหรับวงจรตื้นหรือช่วงความได้เปรียบระยะใกล้ การกดข้อผิดพลาดร่วมกับการลดผลกระทบ หรือการตรวจจับแบบ post-selected อาจให้ความแยกที่มีประสิทธิผลดีกว่า

เครื่องมือเหล่านี้เป็นเมนูทรัพยากร ไม่ใช่สูตรเชิงเส้น งานจริงเลือกเซตย่อยของเมนู และการวิเคราะห์การตรวจสอบและความแยกบอกเราว่าเซตย่อยนั้นปิดช่องว่างสู่ความได้เปรียบหรือไม่

จุดตัดของต้นทุน​

รูปทรงต้นทุนของเครื่องมือต่างๆ บนสเปกตรัมความแม่นยำต่างกันเชิงคุณภาพ สำหรับแผนที่เน้นในบทเรียนก่อนหน้า การลดผลกระทบและการตรวจจับแบบ post-selected อาจมีต้นทุนที่เพิ่มแบบเอกซ์โพเนนเชียลตามปริมาตรวงจรหรืออัตราข้อผิดพลาดรวม ค่าโสหุ้ยการสุ่มตัวอย่างใน probabilistic error cancellation (PEC) เพิ่มประมาณ exp⁡(c⋅V⋅p)\exp(c \cdot V \cdot p)exp(c⋅V⋅p) และอัตราการยอมรับของการตรวจจับแบบ post-selected ลดลงประมาณ exp⁡(−c′⋅V⋅p)\exp(-c' \cdot V \cdot p)exp(−c′⋅V⋅p) โดย VVV คือปริมาตรวงจร และ ppp คืออัตราข้อผิดพลาดทางกายภาพ แบบจำลองเชิงแผนภาพนี้สมมติว่าความผิดพลาดเป็นอิสระต่อกันโดยประมาณ และค่าคงที่ขึ้นกับโปรโตคอลและความครอบคลุมของการตรวจสอบ การแก้ไขที่ทนข้อผิดพลาดพร้อมการถอดรหัสมีรูปทรงต่างออกไป มันจ่ายค่าโสหุ้ยเชิงสถาปัตยกรรมก้อนใหญ่ล่วงหน้า (แพตช์โค้ด โรงงาน magic-state ตัวถอดรหัส และฮาร์ดแวร์แบบโมดูลาร์) จากนั้นสเกลตามปริมาตรวงจรได้ควบคุมได้ดีกว่าเมื่อข้อผิดพลาดเชิงตรรกะถูกกดลงแล้ว รูปทรงต้นทุนเหล่านี้เป็นเพียงแผนภาพ โดยจุดตัดที่แน่นอนขึ้นกับอัตราข้อผิดพลาดทางกายภาพ ความเที่ยงตรงเชิงตรรกะเป้าหมาย และอัลกอริทึมเฉพาะ ประเด็นเชิงคุณภาพคือ การลดผลกระทบและการตรวจจับอาจเป็นตัวเลือกที่เหมาะสมที่ปริมาตรเล็กกว่า ขณะที่การแก้ไขอาจได้เปรียบเมื่อปริมาตรวงจรและเป้าหมายความน่าเชื่อถือทำให้แนวทางที่เบากว่าเหล่านั้นแพงเกินไป จุดตัดนี้กำหนด ช่วง ที่ข้อกล่าวอ้างความได้เปรียบใดๆ ตั้งอยู่

สำหรับการสาธิตความได้เปรียบระยะใกล้ การลดผลกระทบและ post-selection มีประโยชน์เมื่อต้นทุนยังจัดการได้ที่ปริมาตรที่ฮาร์ดแวร์ปัจจุบันรันได้ สำหรับการคำนวณทนข้อผิดพลาดขนาดใหญ่ การแก้ไขแบบอาศัยการถอดรหัสกลายเป็นศูนย์กลาง เพราะค่าโสหุ้ยของการลดผลกระทบอย่างเข้มงวดหรือการตรวจจับแบบ post-selected เพียงอย่างเดียวอาจสูงเกินรับไหว วิธีเหล่านี้ยังรวมกันได้ตาม QEC continuum (ดู QEC continuum blog)

ตรวจสอบความเข้าใจของคุณ​

ในแบบจำลองเชิงแผนภาพข้างต้น PEC, post-selection และการแก้ไขที่ทนข้อผิดพลาดพร้อมการถอดรหัสมีรูปทรงต้นทุนที่ ต่างกันเชิงคุณภาพ เป็นฟังก์ชันของปริมาตรวงจร VVV จงอธิบายแต่ละรูปทรง และสิ่งที่บ่งบอกว่าเครื่องมือแต่ละอย่างชนะเมื่อใด

คำตอบ

ในแบบจำลองนี้ PEC และ post-selection มีต้นทุนแบบเอกซ์โพเนนเชียลตามปริมาตร โดยค่าโสหุ้ยการสุ่มตัวอย่างของ PEC เป็น ∼ecVp\sim e^{cVp}∼ecVp และอัตราการยอมรับของ post-selection เป็น ∼e−c′Vp\sim e^{-c'Vp}∼e−c′Vp ส่วนการแก้ไขที่ทนข้อผิดพลาดพร้อมการถอดรหัสจ่ายต้นทุนเชิงสถาปัตยกรรมก้อนใหญ่ ล่วงหน้า (แพตช์โค้ด โรงงาน magic-state ตัวถอดรหัส ฮาร์ดแวร์แบบโมดูลาร์) แล้วเพิ่ม อย่างนุ่มนวล เมื่อข้อผิดพลาดเชิงตรรกะถูกกดลงแล้ว ต้นทุนสัมพัทธ์อาจตัดกัน วงจรเล็กเหมาะกับการลดผลกระทบและการตรวจจับ วงจรลึกเหมาะกับการแก้ไข และจุดตัดนั้นกำหนด ช่วง ของข้อกล่าวอ้างความได้เปรียบใดๆ (แบบจำลองต้นทุนจริงยุ่งเหยิงกว่านี้ และประเด็นที่หนักแน่นคือความต่างของรูปทรง ไม่ใช่จุดตัดที่แน่นอน โปรดสังเกตว่าต้นทุนของ PEC และ post-selection ในแบบจำลองนี้ ไม่ คงที่ตาม VVV เพราะการพุ่งขึ้นของมันคือหัวใจสำคัญ และการแก้ไข ไม่ เป็นเอกซ์โพเนนเชียลใน VVV โดยเฉพาะ)

คำถาม "เมื่อไร" จบลงตรงไหน​

บทสรุปที่ตรงไปตรงมาไม่ใช่ว่าการแก้ไข ชนะ หรือการลดผลกระทบหรือการตรวจจับชนะ แต่คือเราสามารถชั่งน้ำหนัก ว่าเครื่องมือแต่ละอย่างเหมาะกับข้อกล่าวอ้างความได้เปรียบหนึ่งๆ เพียงใด เทียบกับปัจจัยต่อไปนี้ คืองาน วิธีตรวจสอบความถูกต้อง และงบทรัพยากร กรณีศึกษาในส่วนที่ 3-5 เป็นความพยายามที่เป็นรูปธรรมอย่างหนึ่งในการผลักปลายด้านการแก้ไขของสเปกตรัมจนจุดตัดของต้นทุนเคลื่อนมาเข้าข้างมัน และมันยังเคลื่อนอยู่ ก้าวล่าสุดคือ code concatenation ซึ่งสร้างโค้ดที่ใหญ่ขึ้นโดยเข้ารหัสคิวบิตเชิงตรรกะของโค้ด ชั้นใน ลงในช่องข้อมูลของโค้ด ชั้นนอก วิธีนี้ผ่อนคลายการแลกเปลี่ยนระหว่างค่าโสหุ้ย การกดข้อผิดพลาด และการเชื่อมต่อไปอีกขั้น โดยให้ความไม่เป็นท้องถิ่นผ่านการดำเนินการ เชิงตรรกะ ของโค้ดชั้นใน แทนที่จะผ่านฮาร์ดแวร์ มีรายงานว่าบรรลุช่วง teraquop สำหรับหน่วยความจำด้วยค่าโสหุ้ยด้านพื้นที่ต่ำกว่าโค้ด two-gross ที่มี 288 คิวบิตข้อมูลในการวิเคราะห์ของผู้เขียน (Wills et al., 2026) สถาปัตยกรรม BB ขนาดใหญ่ยังได้รับการสนับสนุนหลักจากการจำลองระดับวงจรและการวิเคราะห์เชิงสถาปัตยกรรม แยกต่างหาก IBM และพันธมิตรรายงานการสาธิตความได้เปรียบเชิงควอนตัมเมื่อวันที่ 30 กรกฎาคม 2026 (quantum-advantage announcement) พร้อมการเปรียบเทียบอย่างต่อเนื่องกับวิธีคลาสสิกผ่าน Quantum Advantage Tracker การทดลองโดย IBM และ University of Chicago ใช้ spacetime-code post-selection ซึ่งเป็นแนวทางที่แนะนำในบทเรียนก่อนหน้า และรายงานการลดข้อผิดพลาดเกตที่มีประสิทธิผลประมาณ 10×10\times10× (quantum-advantage announcement) อินสแตนซ์ 70 คิวบิตแรกของมันถูกจำลองแบบคลาสสิกในเวลาต่อมา (Manabe et al., 2026) และการทดลองฉบับแก้ไขใช้วงจร 64 คิวบิตที่เข้ารหัสใน 76 คิวบิตทางกายภาพ (Martiel et al., 2026) หลักไมล์การทนข้อผิดพลาดขนาดใหญ่ของ Starling ยังคงเป็นเป้าหมายปี 2029 (fault-tolerance roadmap) สิ่งนี้ตรงกับที่ Lanes et al., 2025 คาดไว้ คือความได้เปรียบไม่ได้มาในรูปหลักไมล์เดียว แต่เป็น ลำดับ ของการสาธิตที่แข็งแกร่งขึ้นเรื่อยๆ แต่ละครั้งตรวจสอบเทียบกับเกณฑ์คลาสสิกที่ดีที่สุดและสรุปผลอย่างเปิดเผย

การประเมินผลลัพธ์ใหม่​

การเลือกกลยุทธ์จัดการข้อผิดพลาดเริ่มจากงาน วิธีตรวจสอบความถูกต้อง และต้นทุนทรัพยากรทั้งหมด ตัวอย่างโค้ด ตัวถอดรหัส และฮาร์ดแวร์ในบทเรียนนี้ช่วยประเมินว่าการแก้ไขข้อผิดพลาดตอบสนองข้อกำหนดเหล่านั้นได้หรือไม่ ขณะที่ยังคงความได้เปรียบเชิงการคำนวณไว้ การลดผลกระทบและ post-selection เสริมการแก้ไขข้อผิดพลาดได้ รวมถึงบนวงจรเชิงตรรกะ (QEC continuum blog)

Quantum Advantage Tracker สนับสนุนการเปรียบเทียบอย่างเปิดเผยระหว่างการคำนวณควอนตัมที่เป็นตัวเลือกกับวิธีคลาสสิกชั้นนำ เมื่อทั้งสองฝ่ายพัฒนาขึ้น การเปรียบเทียบประสิทธิภาพและการประมาณทรัพยากรต้องถูกทบทวนใหม่ สำหรับผลลัพธ์ใหม่แต่ละอย่าง ให้ถามว่าแสดงความแม่นยำระดับใด นับทรัพยากรใดบ้าง และการเปรียบเทียบใช้วิธีคลาสสิกที่ดีที่สุดที่มีอยู่หรือไม่ ใช้คำถามเหล่านี้เมื่อคุณประเมินหรือออกแบบเวิร์กโฟลว์จัดการข้อผิดพลาด
