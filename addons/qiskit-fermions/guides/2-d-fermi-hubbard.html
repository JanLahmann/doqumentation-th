ดูเพิ่มเติม

อ่านคู่มือ flow set 1 มิติก่อน คู่มือนี้เป็นภาคต่อสองมิติของมัน และไม่ทวนข้อมูลที่พัฒนาไว้ที่นั่น: ตัวดำเนินการถ่ายโอนและจุดยอด flow set คืออะไร groups อยู่รอดเข้าไปในวงจรอย่างไร และการเข้ารหัสแบบกำหนดเองถูกเชื่อมเข้ากับ Transpiler ผ่าน MapperFnEvolutionSynthesis อย่างไร

ดูคู่มือ transpilation สำหรับขั้นตอนของ Transpiler ที่อ้างถึงตลอด และคู่มือ mappers สำหรับสูตรทั่วไปในการเขียน mapper แบบกำหนดเอง

คู่มือ 1 มิติปิดท้ายด้วยการกล่าวว่าต้องใช้การเข้ารหัสแบบท้องถิ่นเมื่อทำงานกับสองมิติ คู่มือนี้ก้าวต่อไปในขั้นนั้น สำหรับแบบจำลอง Fermi-Hubbard สองมิติบนแลตทิซสี่เหลี่ยมจัตุรัส โดยใช้การเข้ารหัส Verstraete-Cirac (VC) [2]

มีความแตกต่างสามข้อจากปัญหา 1 มิติ ซึ่งเป็นพื้นฐานของงานนี้:

  • flow set เพิ่มขึ้นหลายเท่า โซ่มีทิศทางลูกศรสองแบบ แลตทิซสี่เหลี่ยมจัตุรัสมีสี่แบบ (ตะวันออก ตะวันตก เหนือ ใต้) และแต่ละแบบเป็นการรวมกันของเส้นทางมีทิศทางที่ไม่มีจุดยอดร่วม (หนึ่งเส้นต่อแถวหรือคอลัมน์ของแลตทิซ) ไม่ใช่เส้นทางเดียว

  • การเข้ารหัสได้ ancilla เพิ่มต่อไซต์ ไม่ใช่หนึ่งตัวสำหรับทั้งระบบ ทำให้ได้​

    อัตราส่วน Qubit ต่อโหมดเท่ากับ 222 ตัวดำเนินการถ่ายโอนกลายเป็นเพาลีน้ำหนัก 3 (แนวนอน) และน้ำหนัก 4 (แนวตั้ง) และแต่ละใน flow set ทั้งสี่แมปไปยังรูปร่างเพาลีของตัวเอง ดังนั้นแต่ละชุดต้องมี Clifford ที่ทำให้เป็นแนวทแยงของตัวเอง

  • แฮมิลโทเนียนที่เข้ารหัสซื่อตรงเฉพาะบนปริภูมิย่อย: ปริภูมิไอเกน +1+1+1 ร่วม​

    ของข้อจำกัด plaquette ที่ทุกการเข้ารหัสท้องถิ่นแบบ 2 มิติมี [2] [3] ใน 1 มิติ การเข้ารหัสเป็นไอโซเมทรีธรรมดาและการตรวจสอบคือการเช็กสเปกตรัม ที่นี่ การเปรียบเทียบต้องถูกฉาย ดังที่ขั้นตอนที่ 9 แสดง

ผลตอบแทนมีรูปแบบเดียวกับใน 1 มิติ: ความลึกสองคิวบิตของหนึ่งขั้น Trotter คงที่ไม่ขึ้นกับขนาดแลตทิซ ที่ 242424 (161616 สำหรับ hopping ตรงกับเอกสารอ้างอิง [1] บวก 888 สำหรับอันตรกิริยา) ขณะที่การทำ Trotterization ทีละพจน์ของแฮมิลโทเนียนที่เข้ารหัสเดียวกันโตเชิงเส้น แน่นอนว่าจำนวนเกตยังโตตามจำนวนพันธะ สิ่งที่ไม่ขึ้นกับขนาดคือจำนวนเลเยอร์ที่เกตเหล่านั้นครอบครอง ความลึกทั้งหมดนับบนรีจิสเตอร์นามธรรมที่เชื่อมต่อกันเต็มที่ การแมปการเข้ารหัสลงบน coupling map ที่จำกัดของอุปกรณ์เป็นปัญหาในตัวเอง ซึ่งจะกล่าวถึงตอนท้าย

การเข้ารหัส Verstraete-Cirac​

Verstraete-Cirac (VC) จับคู่ทุกโหมดเฟอร์มิออน jjj กับ Qubit ช่วยของมันเอง เมื่อมีไซต์แลตทิซ NNN ไซต์ โหมด jjj อยู่บน Qubit jjj และ ancilla ของมันอยู่บน Qubit N+jN + jN+j ดังนั้นรีจิสเตอร์มี 2N2N2N Qubit ตัวดำเนินการจุดยอดเรียบง่ายที่สุดเท่าที่จะเป็นได้

Vj=Zj ,V_j = Z_j \, ,Vj​=Zj​,

ซึ่งทำให้อ่านค่าการครอบครองได้โดยตรงในภายหลัง ตัวดำเนินการถ่ายโอนขึ้นกับทิศทางของเส้นเชื่อม สำหรับเส้นเชื่อมแนวนอน j→kj \to kj→k โดย jjj เป็นไซต์ตะวันตก และเส้นเชื่อมแนวตั้งที่ jjj เป็นไซต์เหนือ

Tjkhorizontal=12XjXkZN+j ,Tjkvertical=12XjYkXN+jYN+k ,T_{jk}^{\text{horizontal}} = \tfrac{1}{2} X_j X_k Z_{N+j} \, , \qquad T_{jk}^{\text{vertical}} = \tfrac{1}{2} X_j Y_k X_{N+j} Y_{N+k} \, ,Tjkhorizontal​=21​Xj​Xk​ZN+j​,Tjkvertical​=21​Xj​Yk​XN+j​YN+k​,

“สามเหลี่ยม” น้ำหนัก 3 และ “สี่เหลี่ยม” น้ำหนัก 4 การระบุลูกศรแต่ละตัวมีความสำคัญ: เมื่อ jjj เป็นไซต์ตะวันตก j→kj \to kj→k ชี้ไปทางตะวันออก แต่เมื่อ jjj เป็นไซต์เหนือ มันชี้ไปทางใต้ ทิศทางตรงข้ามได้จากเอกลักษณ์ Tkj=−VjVkTjkT_{kj} = -V_j V_k T_{jk}Tkj​=−Vj​Vk​Tjk​ ซึ่งเปลี่ยนสามเหลี่ยม XXZ เป็น YYZ และสี่เหลี่ยม XYXY เป็น YXXY ป้ายที่ต่างกันสี่ป้ายนั้นคือ flow set ทั้งสี่ และส่วนที่เหลือของคู่มือนี้ติดตามพวกมัน

1. Hamiltonian บนแลตทิซสี่เหลี่ยม​

การสร้างเหมือนกับกรณี 1D แต่ใช้รายการ edge แบบสองมิติ site ใช้การนับเลขแบบ row-major เหมือนในรูปด้านบน site(r, c) = r * cols + c ดังนั้นพันธะแนวนอนเชื่อมดัชนีที่ต่อเนื่องกัน ส่วนพันธะแนวตั้งเชื่อมดัชนีที่ต่างกัน cols:

>>> from collections import defaultdict
>>> from qiskit_fermions.operators import TransferVertexOperator
>>>
>>> def fermi_hubbard_2d(rows, cols, tunneling, interaction):
...     site = lambda r, c: r * cols + c
...     edges = [(site(r, c), site(r, c + 1)) for r in range(rows) for c in range(cols - 1)]
...     edges += [(site(r, c), site(r + 1, c)) for r in range(rows - 1) for c in range(cols)]
...     data: defaultdict[tuple[tuple[int, int], ...], complex] = defaultdict(complex)
...     for j, k in edges:
...         # hopping: -t (a^dag_j a_k + a^dag_k a_j) = t (T_jk + T_kj)
...         data[((j, k),)] += tunneling
...         data[((k, j),)] += tunneling
...         # interaction: U n_j n_k with n_j = (1 - V_j) / 2
...         data[()] += interaction / 4
...         data[((j, j),)] -= interaction / 4
...         data[((k, k),)] -= interaction / 4
...         data[((j, j), (k, k))] += interaction / 4
...     return TransferVertexOperator.from_dict(data)
>>>
>>> rows, cols = 3, 3
>>> num_sites = rows * cols
>>> hamiltonian = fermi_hubbard_2d(rows, cols, tunneling=1.0, interaction=2.0)
>>> print(f"Number of terms: {len(hamiltonian)}")
Number of terms: 46

ข้อตกลงเรื่องทิศทาง ชื่อเหล่านี้อ่านจากรูปด้านบนตรง ๆ: ลูกศรเป็น east หรือ west ตามที่ชี้ไปทางขวาหรือซ้ายตามแถว และเป็น north หรือ south ตามที่ชี้ขึ้นหรือลงตามคอลัมน์ เนื่องจากการนับเลขเป็นแบบ row-major ทิศ east และ south จึงเป็นทิศที่ดัชนีเพิ่มขึ้น ขั้นตอนถัด ๆ ไปไม่ได้พึ่งชื่อเหล่านี้ (มันเป็นแค่ป้ายของกลุ่ม) แต่สับสนกันง่าย จึงควรยึดให้ตรงกับรูป Ref. [1] ตั้งชื่อ flow set ของแลตทิซสี่เหลี่ยมแบบเดียวกัน

>>> EAST, WEST, NORTH, SOUTH, DIAGONAL = range(5)
>>>
>>> def flow_set_groups(operator, cols):
...     groups = []
...     for terms, _ in operator.iter_terms():
...         if len(terms) == 1 and terms[0][0] != terms[0][1]:
...             j, k = terms[0]
...             row_j, col_j = divmod(j, cols)
...             row_k, col_k = divmod(k, cols)
...             if row_j == row_k:
...                 groups.append(EAST if col_k > col_j else WEST)
...             else:
...                 groups.append(SOUTH if row_k > row_j else NORTH)
...         else:
...             groups.append(DIAGONAL)
...     return groups
>>>
>>> hamiltonian.groups = flow_set_groups(hamiltonian, cols)
>>>
>>> names = ["east", "west", "north", "south", "diagonal"]
>>> for index, name in enumerate(names):
...     count = sum(1 for group in hamiltonian.groups if group == index)
...     print(f"{name:9s} {count:2d}")
east       6
west       6
north      6

3. เข้ารหัส operator​

การเข้ารหัสคือฟังก์ชันเดียวที่แมป generalized transfer operator หนึ่งตัวไปเป็น Pauli string ซึ่งส่งให้ map_transfer_vertex_generators() เมื่อเทียบกับเวอร์ชัน 1D ตัวฟังก์ชันมีกรณีมากขึ้น: แนวทแยง แนวนอน แนวตั้ง และทิศตรงข้ามผ่าน Tkj=−VjVkTjkT_{kj} = -V_j V_k T_{jk}Tkj​=−Vj​Vk​Tjk​

มีปัญหาอยู่อย่างหนึ่ง map_transfer_vertex_generators() เรียกกลับมาพร้อมกับ generator เท่านั้น แต่การตัดสินใจว่า Pauli string ของพันธะหนึ่งคืออะไรยังต้องใช้ cols เพื่อกู้พิกัดแถวและคอลัมน์จากดัชนีของ mode ด้วย แทนที่จะซ้อนฟังก์ชันเพื่อให้จับค่านั้นไว้ เราใช้ functools.partial() ผูกค่าไว้ ซึ่งทำให้ทั้งสองฟังก์ชันอยู่ระดับบนสุดและเรียกใช้แยกกันได้

>>> from functools import partial
>>>
>>> from qiskit.quantum_info import SparseObservable
>>> from qiskit_fermions.mappers import map_transfer_vertex_generators
>>>
>>> def ancilla_qubit(mode, num_sites):
...     """The auxiliary qubit paired with fermionic mode `mode`."""
...     return num_sites + mode
>>>
>>> def vc_action(generator, width, cols):
...     """Map one generalized transfer operator to its Verstraete-Cirac Pauli."""
...     num_sites = width // 2
...     ancilla = partial(ancilla_qubit, num_sites=num_sites)
...     j, k = generator
...     if j == k:  # vertex operator V_j = Z_j
...         return SparseObservable.from_sparse_list([("Z", [j], 1.0)], num_qubits=width)
...     row_j, col_j = divmod(j, cols)
...     row_k, col_k = divmod(k, cols)
...     if row_j == row_k:  # horizontal: weight-3 triangle
...         left, right = (j, k) if col_j < col_k else (k, j)
...         operator = SparseObservable.from_sparse_list(
...             [("XXZ", [left, right, ancilla(left)], 0.5)], num_qubits=width
...         )
...         forward = (j, k) == (left, right)
...     else:  # vertical: weight-4 square
...         up, down = (j, k) if row_j < row_k else (k, j)
...         operator = SparseObservable.from_sparse_list(
...             [("XYXY", [up, down, ancilla(up), ancilla(down)], 0.5)], num_qubits=width
...         )
...         forward = (j, k) == (up, down)
...     if forward:
...         return operator
...     # reverse orientation: T_kj = -V_j V_k T_jk
...     v_j = SparseObservable.from_sparse_list([("Z", [j], 1.0)], num_qubits=width)
...     v_k = SparseObservable.from_sparse_list([("Z", [k], 1.0)], num_qubits=width)
...     return (-1.0 * v_j.compose(v_k).compose(operator)).simplify()
>>>
>>> def vc_encoding(operator, width, cols):
...     """Map a TransferVertexOperator to a qubit observable, Verstraete-Cirac style."""
...     return map_transfer_vertex_generators(
...         operator,
...         partial(vc_action, width=width, cols=cols),
...         identity=lambda: SparseObservable.identity(width),
...         compose=SparseObservable.compose,
...     ).simplify()
>>>
>>> # bind the lattice width once; the transpiler only ever passes (operator, width)
>>> encoding = partial(vc_encoding, cols=cols)
>>> num_qubits = 2 * num_sites
>>> num_qubits

5. Clifford ความลึก 2 ต่อ flow set​

กลไกเหมือนกับใน 1D: คอนจูเกต flow set ที่คอมมิวต์กันทั้งชุดด้วย Clifford ที่แมปแต่ละ term ไปเป็น Pauli น้ำหนัก 1 ที่ต่างกัน เพื่อให้การวิวัฒน์ของทั้งชุดใช้เพียงการหมุน qubit เดี่ยว ใน 1D ชั้นอิฐของ Gate CZ ชั้นเดียวทำสิ่งนี้ได้

ใน 2D แต่ละ flow set ต้องมีวงจรของตัวเอง ตามหัวข้อ IV C และรูปที่ 7 ของ Ref. [1] ทั้งสี่ทำงานกับเส้นหนึ่งของแลตทิซทีละเส้น (แถวสำหรับ east/west คอลัมน์สำหรับ north/south) พร้อมกับ ancilla ของเส้นนั้น และทั้งสี่มีรูปแบบสามส่วนเหมือนกัน:

  • ชั้นของการหมุน qubit เดี่ยว ที่ใส่แต่ละ qubit ไว้ใน basis ที่ flow set ของมันต้องการ

  • ชั้น CX ชั้นแรก ซึ่งเป็น site-ไป-ancilla บน site เดียวกันเสมอ

  • ชั้น CX ชั้นที่สอง ซึ่งเชื่อมเพื่อนบ้านตามแนวเส้น

ขั้นตอนที่ 2 และ 3 เป็นสองชั้นสอง qubit เพียงชั้นเดียวที่มี ดังนั้นความลึกสอง qubit คือ 222 ไม่ว่าเส้นจะยาวเท่าใด ด้านล่างเขียนออกมาเป็นหนึ่งฟังก์ชันต่อ flow set การหมุนเป็นแบบนั้นเพราะมันถูกค้นพบโดยการคอนจูเกต term ของแต่ละ flow set และกำหนดให้ภาพที่ได้เป็นน้ำหนัก 1 ที่ต่างกัน ดังนั้นให้ถือว่าเป็นค่าที่กำหนดให้ และพึ่งการตรวจสอบที่ตามมา

สองชุดแนวนอนง่ายที่สุด term ของมันมีน้ำหนัก 3 คือ XXZ และ YYZ และต่างกันเพียง SSS เพิ่มเติมที่เปลี่ยน XXX เป็น YYY บน site:

>>> from qiskit.quantum_info import Clifford, SparsePauliOp
>>>
>>> def clifford_supports(clifford, pauli, line, ancilla, num_qubits):
...     """Conjugate a flow set's terms to find which qubit each one lands on.
...
...     `pauli` is the flow set's Pauli string, as printed in step 3. Its letters apply
...     to the i-th term's qubits in the order below: the two sites of the bond, then
...     their ancillas.
...
...     This is the one check that needs SparsePauliOp: Clifford conjugation wants a
...     `Pauli` and its symplectic bits, and SparseObservable exposes neither -- its own
...     `evolve` conjugates by a Pauli, not by a Clifford.
...     """
...     supports = []
...     for i in range(len(line) - 1):
...         qubits = [line[i], line[i + 1], ancilla(line[i]), ancilla(line[i + 1])]
...         term = SparsePauliOp.from_sparse_list(
...             [(pauli, qubits[: len(pauli)], 1.0)], num_qubits=num_qubits
...         )
...         image = term.paulis[0].evolve(clifford, frame="s")
...         # a weight-1 image has exactly one qubit with an X and/or Z bit set
...         (support,) = np.nonzero(image.x | image.z)
...         assert len(support) == 1, f"term {i} is not weight-1"
...         supports.append((int(support[0]), image[support].to_label()))
...     return supports

6. การสังเคราะห์ที่รับรู้ flow set​

การสังเคราะห์ได้ตัวช่วยเริ่มต้นที่ดี เพราะ Evolution แยกตัวเองทีละกลุ่ม synthesize จึงถูกเรียกหนึ่งครั้งต่อ flow set (ห้าครั้งในที่นี้ คือสี่ชุด hopping บวกกลุ่มแนวทแยง) ดังนั้นทุก hopping term ที่มันเห็นมีรูปร่าง Pauli เดียวกัน และ Clifford ตัวเดียวทำให้ทั้งหมดเป็นแนวทแยง มันเพียงอ่านรูปร่างนั้นจาก term แรกและเรียงที่เหลือตามเส้นที่มันอยู่ แล้วก็มาถึงข้อสังเกตที่ทำให้สองมิติถูกกว่าที่คิดไว้:

สำคัญ

ส่วนประกอบของ flow set เดียวไม่มีจุดยอดร่วมกัน: แถวของชุด west ไม่ใช้ qubit ร่วมกัน ดังนั้น Clifford ทั้งหมดของ flow set จึงปล่อยออกมาพร้อมกันได้ และใช้สองชั้นสอง qubit ชุดเดียวกัน แทนที่จะต่อคิวทีละแถว flow set หนึ่งจึงมีต้นทุนเป็นจำนวนชั้นคงที่ (สองสำหรับ Clifford และสองสำหรับอินเวอร์ส) ไม่ว่าแลตทิซจะมีกี่แถวหรือกี่คอลัมน์ ซึ่งเป็นเหตุผลที่ความลึกรวมคงที่

>>> from qiskit.synthesis.evolution import EvolutionSynthesis
>>>
>>> # The interaction couples nearest neighbors only, so every interior site carries four
>>> # Rzz gates -- one per bond -- and can only do one at a time: four layers is the best
>>> # any schedule can achieve. Horizontal bonds split by column parity, vertical ones by
>>> # row parity, which achieves it.
>>> def rzz_layers(circuit, angles, cols):
...     """Emit the diagonal Rzz gates in four layers of disjoint qubit pairs."""
...     horizontal = [(j, k) for j, k in angles if k - j == 1]
...     vertical = [(j, k) for j, k in angles if k - j == cols]
...     schedule = [
...         [(j, k) for j, k in horizontal if (j % cols) % 2 == 0],
...         [(j, k) for j, k in horizontal if (j % cols) % 2 == 1],
...         [(j, k) for j, k in vertical if (j // cols) % 2 == 0],
...         [(j, k) for j, k in vertical if (j // cols) % 2 == 1],
...     ]
...     # emit layer by layer, since Qiskit's depth follows the order gates were added
...     for layer in schedule:
...         for j, k in layer:
...             circuit.rzz(angles[j, k], j, k)
>>>
>>> class FlowSetSynthesis(EvolutionSynthesis):
...     """Synthesize one 2D line flow set at a time, via its depth-2 Clifford."""
...
...     preserve_order = True
...
...     def __init__(self, rows, cols):
...         self.rows, self.cols = rows, cols
...
...     def rows_of_lattice(self):
...         return [[r * self.cols + c for c in range(self.cols)] for r in range(self.rows)]
...
...     def columns_of_lattice(self):
...         return [[r * self.cols + c for r in range(self.rows)] for c in range(self.cols)]
...
...     def synthesize(self, evolution):
...         num_qubits = 2 * self.rows * self.cols
...         ancilla = partial(ancilla_qubit, num_sites=self.rows * self.cols)
...         circuit = QuantumCircuit(evolution.operator.num_qubits)
...         terms = [
...             (label, indices, 2 * evolution.time * coeff.real)
...             for label, indices, coeff in evolution.operator.to_sparse_list()
...         ]
...
...         # `Evolution.decompose()` hands us one gate per flow set, so every hopping term
...         # here shares a single Pauli shape and one Clifford diagonalizes all of them
...         shapes = tuple({label for label, _, _ in terms} - {"", "Z", "ZZ"})
...         match shapes:
...             case ("XXZ",):
...                 clifford_function, lines = east_clifford, self.rows_of_lattice()
...                 along_rows = True
...             case ("YYZ",):
...                 clifford_function, lines = west_clifford, self.rows_of_lattice()
...                 along_rows = True
...             case ("XYXY",):
...                 clifford_function, lines = south_clifford, self.columns_of_lattice()
...                 along_rows = False
...             case ("YXXY",):
...                 clifford_function, lines = north_clifford, self.columns_of_lattice()
...                 along_rows = False
...             case ():  # the diagonal group: no conjugation needed
...                 self.diagonal(circuit, terms)
...                 return circuit
...             case _:
...                 raise ValueError(f"expected one known flow set per gate, got {shapes}")
...
...         # a term's line is the row it sits in and its slot the column, or vice versa
...         rotations: dict[int, list] = defaultdict(list)
...         for _, indices, angle in terms:
...             row, col = divmod(indices[0], self.cols)
...             line, slot = (row, col) if along_rows else (col, row)
...             rotations[line].append((slot, angle))
...
...         active = sorted(rotations)
...         # the lines of one flow set are vertex-disjoint, so all of their Cliffords
...         # are emitted together and share the same two two-qubit layers
...         conjugation = QuantumCircuit(num_qubits)
...         for line in active:
...             clifford_function(conjugation, lines[line], ancilla)
...         circuit.compose(conjugation, inplace=True)
...         for line in active:
...             supports = clifford_supports(
...                 Clifford(conjugation), shapes[0], lines[line], ancilla, num_qubits
...             )
...             for slot, angle in rotations[line]:
...                 match supports[slot]:
...                     case qubit, "X":
...                         circuit.rx(angle, qubit)
...                     case qubit, "Y":
...                         circuit.ry(angle, qubit)
...                     case qubit, "Z":
...                         circuit.rz(angle, qubit)
...         circuit.compose(conjugation.inverse(), inplace=True)
...         return circuit
...
...     def diagonal(self, circuit, terms):
...         """Synthesize the diagonal group: a phase, single-qubit Z and paired Rzz."""
...         rzz = {}
...         for label, indices, angle in terms:
...             match label, indices:
...                 case "", _:  # the identity contributes only a global phase
...                     circuit.global_phase -= angle / 2
...                 case "Z", [qubit]:  # a lone vertex operator
...                     circuit.rz(angle, qubit)
...                 case "ZZ", [j, k]:  # interaction, see rzz_layers above
...                     rzz[min(j, k), max(j, k)] = angle
...                 case _:
...                     raise ValueError(f"unexpected Pauli term: {label} on {indices}")
...         rzz_layers(circuit, rzz, self.cols)

สังเกตสองคลาสที่ชื่อคล้ายกันซึ่งเกี่ยวข้องอยู่ LieTrotter ของ Qiskit ที่ใช้เป็น baseline ข้างต้น ทำงานกับ Hamiltonian ที่ แมปแล้ว ซึ่งการจัดกลุ่มหายไปแล้ว ส่วน FermionicLieTrotter คือคู่เทียบแบบเฟอร์มิออน และเป็นตัวที่ยังเห็น flow set ได้

>>> import numpy as np
>>> from qiskit.quantum_info import Statevector
>>>
>>> rng = np.random.default_rng(1234)
>>>
>>> def agrees_up_to_one_phase(rows, cols, samples=3):
...     """Compare both syntheses on random states.
...
...     Returns whether they agree up to a phase, and whether it is the *same* phase
...     for every input state.
...     """
...     lie_trotter = transpile_trotter_step(
...         rows, cols, LieTrotter()
...     ).decompose(reps=6)
...     flow = transpile_trotter_step(
...         rows, cols, FlowSetSynthesis(rows, cols)
...     ).decompose(reps=6)
...     dimension = 2**lie_trotter.num_qubits
...     residuals, phases = [], []
...     for _ in range(samples):
...         vector = rng.normal(size=dimension) + 1j * rng.normal(size=dimension)
...         state = Statevector(vector / np.linalg.norm(vector))
...         a = state.evolve(lie_trotter).data
...         b = state.evolve(flow).data
...         overlap = np.vdot(a, b)
...         phases.append(overlap / abs(overlap))
...         residuals.append(np.linalg.norm(b - a * overlap / abs(overlap)))
...     # the SAME global phase must work for every input state
...     spread = max(abs(phase - phases[0]) for phase in phases)
...     return bool(max(residuals) < 1e-9), bool(spread < 1e-9)
>>>
>>> agrees_up_to_one_phase(rows, cols)

9. ตรวจสอบฟิสิกส์บน stabilizer subspace​

นี่คือจุดยุ่งยากของสองมิติ ใน 1D การเข้ารหัสเป็น isometry และการเปรียบเทียบสเปกตรัมกับ Jordan-Wigner อ้างอิงก็เพียงพอ VC ไม่ใช่ isometry: มันใช้ 2N2N2N qubit สำหรับ NNN mode ดังนั้นปริภูมิมิติ 22N2^{2N}22N บรรจุปริภูมิฟิสิกส์มิติ 2N2^N2N นี่เป็นลักษณะทั่วไปของการเข้ารหัสเฉพาะที่ในสองมิติ (qubit ส่วนเกินถูกจำกัดด้วยสมมาตรที่คอมมิวต์กันเฉพาะที่ หนึ่งต่อ plaquette [2] [3]) และหมายความว่า Hamiltonian ที่เข้ารหัสแทนค่าเฟอร์มิออนได้อย่างซื่อตรงเฉพาะบนปริภูมิลักษณะเฉพาะ +1+1+1 ร่วมของข้อจำกัดเหล่านั้นเท่านั้น

คำเตือน

คำว่า stabilizer ทำสองหน้าที่ในหัวข้อนี้ และสองความหมายไม่เกี่ยวข้องกัน Ref. [1] ใช้มันกับ transfer operator ที่คอมมิวต์กันของ flow set ซึ่งสร้างกรุป stabilizer ที่ Clifford ของขั้นตอนที่ 5 ทำให้เป็นแนวทแยง (เป็นอุปกรณ์ช่วยคอมไพล์ และเป็นความหมายที่ใช้ทุกที่ข้างต้น) ส่วนนี้ใช้ในความหมายของการแก้ไขข้อผิดพลาด: operator ที่ปริภูมิลักษณะเฉพาะ +1+1+1 ของมันคือปริภูมิฟิสิกส์ Ref. [1] ระบุอย่างชัดเจนถึงการชนกันนี้และวางความหมายที่สองไว้ข้าง ๆ ข้อจำกัด plaquette ด้านล่างเป็นสมบัติของการเข้ารหัส VC [2] ไม่ใช่ผลของกรอบ flow set

generator ถูกสร้างที่นี่แทนที่จะยกมา: หนึ่งต่อหนึ่งหน้าสี่เหลี่ยม และแต่ละตัวก็คือลูป operator ของ edge ที่เข้ารหัสแล้วรอบหน้านั้น

[1] ให้ Clifford สำหรับทำให้เป็นแนวทแยงในรูปแบบปิด แต่ Derby-Klassen ใช้ ancilla หนึ่งตัวต่อ plaquette คี่แทนหนึ่งตัวต่อ site ทำให้อัตราส่วน qubit ต่อ mode เป็น 3/23/23/2 แทนที่จะเป็น 222 transfer operator ของมันมีรูปร่าง Pauli ต่างกัน ดังนั้นการพอร์ตจึงเท่ากับเขียนฟังก์ชันการเข้ารหัสของขั้นตอนที่ 3 ใหม่ และหา Clifford สำหรับแต่ละรูปร่างใหม่ ส่วนการจัดกลุ่ม layout และโครงสังเคราะห์ใช้ต่อได้โดยไม่ต้องแตะ

อย่างที่สองคือตัวแลตทิซเอง ทุกอย่างที่นี่สมมติขอบเปิดและเฟอร์มิออนชนิดเดียว ขอบเป็นคาบปิดแต่ละเส้นให้เป็นวงรอบ: ลูกศรทั้งหมดยังคอมมิวต์กัน เพราะแต่ละตัวพบตัวถัดไปแบบหัวชนหาง แต่สองรูปร่าง Clifford ของขั้นตอนที่ 5 สร้างมาสำหรับเส้นที่มีจุดปลาย วงรอบที่มี LLL site มี LLL พันธะต่อทิศ ในขณะที่เส้นมี L−1L - 1L−1 ดังนั้นพันธะที่วนกลับจึงไม่มีที่ในการสร้างและต้องจัดการเอง โมเดลที่มีสปินง่ายกว่า: มันเพิ่มรีจิสเตอร์เป็นสองเท่าและเพิ่ม term อันตรกิริยาบน site ให้กลุ่มแนวทแยง โดยไม่แตะ flow set ไม่ว่าแบบไหนก็ไม่รบกวนข้อโต้แย้งเรื่องความลึกคงที่ แต่ทั้งสองเปลี่ยนการทำบัญชี ซึ่งตามที่ข้อสรุปแรกบอก คือส่วนที่สองมิติทำให้ใหญ่ขึ้น

สำคัญ

ที่นี่ไม่ได้กล่าวถึงการเชื่อมต่อของฮาร์ดแวร์ ทุกวงจรข้างต้นสร้างบนรีจิสเตอร์นามธรรมที่ qubit คู่ใดก็ทำงานร่วมกันได้ และความลึกที่รายงานนับในบริบทนั้น อุปกรณ์จริงมี coupling map ที่จำกัด และการแมปการเข้ารหัสนี้ลงบนอุปกรณ์เป็นปัญหาใหญ่ในตัวมันเอง: รีจิสเตอร์ VC เป็นกราฟ 2N2N2N qubit ที่ Gate ทำงานระหว่าง site กับ ancilla ของมันเอง ระหว่าง site ข้างเคียง และระหว่าง ancilla ข้างเคียง ดังนั้น layout ต้องทำให้ทั้งสามชนิดของคู่อยู่ติดกันพร้อมกัน หากทำไม่ได้ Transpiler จะแทรก Gate SWAP และชั้นที่มันเพิ่มคือสิ่งที่การสร้างแบบความลึกคงที่ซื้อคืนมา Ref. [1] ก็อ้างตัวเลขความลึกภายใต้กราฟการเชื่อมต่อสี่เหลี่ยมที่สมมติไว้ โดยมี CX เป็นตัวพันกันดั้งเดิมเพียงตัวเดียวเช่นกัน การหา layout และกลยุทธ์การจัดเส้นทางที่ดีสำหรับการเข้ารหัสเฉพาะที่บนโทโพโลยีอุปกรณ์หนึ่ง ๆ อยู่นอกขอบเขตของคู่มือนี้
