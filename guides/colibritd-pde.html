ภาพรวม​

ตัวแก้สมการอนุพันธ์ย่อย (PDE) ที่นำเสนอนี้เป็นส่วนหนึ่งของแพลตฟอร์ม Quantum Innovative Computing Kit (QUICK) ของเรา (QUICK-PDE) และบรรจุเป็น Quantum Function ด้วยฟังก์ชัน QUICK-PDE คุณแก้สมการอนุพันธ์ย่อยเฉพาะโดเมนบน IBM Quantum QPUs ได้ ฟังก์ชันนี้อิงจากอัลกอริทึมที่อธิบายไว้ใน บทความอธิบาย H-DES ของ ColibriTD อัลกอริทึมนี้แก้ปัญหา multi-physics ที่ซับซ้อนได้ เริ่มต้นด้วย Computational Fluid Dynamics (CFD) และ Materials Deformation (MD) และตอนนี้รวมถึงการเงินเชิงปริมาณด้วยสมการ Black-Scholes สำหรับออปชันบนสินทรัพย์หนึ่งถึงสามรายการ กรณีการใช้งานอื่น ๆ กำลังจะตามมา

เพื่อจัดการกับสมการอนุพันธ์ โซลูชันทดลองถูก encode เป็นผลรวมเชิงเส้นของฟังก์ชันตั้งฉาก (โดยทั่วไปคือพหุนาม Chebyshev และโดยเฉพาะอย่างยิ่งสูงสุด 2n2^n2n ตัว โดยที่ nnn คือจำนวน qubits ที่ encode ฟังก์ชันของคุณ) ซึ่งถูกกำหนดพารามิเตอร์ด้วยมุมของ Variable Quantum Circuit (VQC) ansatz สร้าง state ที่ encode ฟังก์ชัน ซึ่งถูกประเมินโดย observable ที่การผสมผสานช่วยให้ประเมินฟังก์ชันที่ทุกจุดได้ จากนั้นประเมิน loss function ที่สมการอนุพันธ์ถูก encode ไว้ และปรับแต่งมุมในการวนซ้ำแบบ hybrid ดังที่แสดงต่อไปนี้ โซลูชันทดลองค่อย ๆ เข้าใกล้โซลูชันจริงจนกว่าจะได้ผลลัพธ์ที่น่าพอใจ

นอกจาก hybrid loop นี้ คุณยังต่อ optimizer หลายตัวเข้าด้วยกันได้ ซึ่งมีประโยชน์เมื่อต้องการ optimizer แบบ global เพื่อหาชุดมุมที่ดี แล้วตามด้วย optimizer ที่ละเอียดกว่าเพื่อไล่ตาม gradient ไปยังชุดมุมที่ดีที่สุดในบริเวณใกล้เคียง ในกรณีของ computational fluid dynamics (CFD) ลำดับการ optimize เริ่มต้นให้ผลลัพธ์ที่ดีที่สุด — แต่ในกรณีของ material deformation (MD) แม้ค่าเริ่มต้นจะให้ผลดี คุณก็กำหนดค่าเพิ่มเติมเพื่อประโยชน์เฉพาะปัญหาได้

หมายเหตุว่าสำหรับตัวแปรแต่ละตัวของฟังก์ชัน คุณระบุจำนวน qubits (ซึ่งคุณทดลองปรับเปลี่ยนได้) โดยการซ้อน 10 Circuit เหมือนกันและประเมิน 10 observable เหมือนกันบน qubits ที่ต่างกันตลอด Circuit ใหญ่หนึ่ง Circuit คุณลด noise ภายในกระบวนการ CMA optimization หรือทำการคำนวณ PSR แบบขนานได้ โดยอาศัยวิธี noise learner และลดจำนวน shots ที่ต้องการอย่างมีนัยสำคัญ

Ansatz​

quantum circuit แบบ variational ที่เข้ารหัสแต่ละ function ถูกเลือกด้วยอาร์กิวเมนต์ ansatz:

  • HEA คือ ansatz แบบ hardware-efficient ที่วัดด้วย observable แบบ global เป็นตัวเลือกที่ใช้ได้ทั่วไปที่สุด

  • BPM-LE (Barren Plateau Mitigation, Low Expressivity) คือ ansatz ที่ออกแบบมาเพื่อหลีกเลี่ยง barren plateau วัดด้วย observable แบบ local มีพารามิเตอร์น้อยและ Circuit ตื้น ทำให้ต้นทุนของการ optimize ต่ำ รวมถึงต้นทุนของ gradient แบบ parameter-shift ด้วย

  • BPM-HE (Barren Plateau Mitigation, High Expressivity) ใช้โครงสร้างเดียวกันแต่มีพารามิเตอร์ต่อ Circuit มากกว่า สำหรับฟังก์ชันที่เวอร์ชัน low-expressivity แสดงได้ไม่แม่นยำพอ

จำนวน Qubit ต่อตัวแปรและความลึกของ Circuit ยังคงควบคุมด้วยอาร์กิวเมนต์ nb_qubits และ depth

Optimizer chain และ error metric​

optimizer ถูกเชื่อมต่อกันเป็นรายการของ stage ด้วยอาร์กิวเมนต์ optimizers แต่ละ stage กำหนดวิธีการ จำนวน iteration สูงสุด และจำนวน shot ของตัวเอง เพื่อให้การประเมินที่ถูกและมี noise สำรวจ landscape ก่อน แล้วจำนวน shot เพิ่มขึ้นเมื่อการ optimize ใกล้ลู่เข้า chain ทั่วไปประกอบด้วยส่วนต่อไปนี้

  1. CMAES หนึ่ง stage หรือมากกว่า (แบบ global และไม่ใช้ gradient) ซึ่งระบุบริเวณที่เหมาะสมของปริภูมิคำตอบ แต่ละ stage มี shots, sigma0 และ popsize ของตัวเอง (population size คือจำนวนผู้สมัครที่ประเมินในแต่ละ generation) อาร์กิวเมนต์ sigma0 คือส่วนเบี่ยงเบนมาตรฐานเริ่มต้นของการแจกแจงการค้นหาของ CMA-ES หรือก็คือขนาดก้าวเริ่มต้น ค่าที่มากสำรวจปริภูมิของพารามิเตอร์ Circuit อย่างกว้าง ส่วนค่าที่น้อยค้นหาเฉพาะที่รอบผู้สมัครที่ดีที่สุดที่พบจนถึงตอนนี้ ดังนั้นการลด sigma0 จาก stage หนึ่งไปอีก stage จึงเป็นการเปลี่ยนจากการสำรวจไปสู่การปรับให้ละเอียด

  2. LS-TRF หนึ่ง stage (Least Squares - Trust Region Reflective) ซึ่งสำรวจบริเวณนี้เพื่อปรับมุมสุดท้ายให้ละเอียด หากไม่มี psr LS-TRF จะประมาณ Jacobian ของ cost function ด้วย finite differences หากใช้ psr=True จะคำนวณ Jacobian บน QPU อย่างแม่นยำด้วย parameter-shift rule (PSR) PSR ทำให้เวลาคำนวณเพิ่มขึ้นเพราะต้องใช้ Circuit เพิ่มเติม แต่ให้ความแม่นยำสูงกว่า finite differences

error metric ที่ใช้ในหน้านี้คือ Root Mean Square Error (RMSE) ระหว่างคำตอบกับคำตอบอ้างอิง บนจุดที่สุ่มตัวอย่าง ฟังก์ชันยังรายงาน mean squared error (MSE) และค่าเบี่ยงเบนสัมบูรณ์สูงสุด ซึ่งเป็น metric d2 และ d1 ในหัวข้อ 2.6 ของ เปเปอร์ H-DES

def calculate_function_size(problem: Any, **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") required to run the function."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def _measure(problem: Any, **kwargs: Any) -> dict:
    """Reduce the problem to a dict of numbers that drives your resource usage."""
    args = (
        {**problem, **kwargs}
        if isinstance(problem, dict)
        else {**kwargs, "use_case": problem}
    )

    use_case = str(args.get("use_case") or "").upper()
    if use_case not in _DEFAULT:
        raise ValueError(
            f"cannot size use_case {args.get('use_case')!r}: expected one of {list(_DEFAULT)}"
        )

    mode = (
        "job"
        if args.get("run_local")
        else str(args.get("mode") or "job").lower()
    )
    if mode not in _MODES:
        raise ValueError(
            f"cannot size mode {args.get('mode')!r}: expected one of {list(_MODES)}"
        )

    optimizers = args.get("optimizers")
    if optimizers is None:
        optimizers = _DEFAULT[use_case]["optimizers"]
    if not isinstance(optimizers, (list, tuple)) or not optimizers:
        raise ValueError(
            "optimizers must be a non-empty list of (name, parameters) pairs"
        )
    iterations, shots = 0, 0
    for i, stage in enumerate(optimizers):
        if (
            not isinstance(stage, (list, tuple))
            or len(stage) != 2
            or not isinstance(stage[1], dict)
        ):
            raise ValueError(
                f"optimizers[{i}] must be a (name, parameters) pair"
            )
        options = {str(k).lower(): v for k, v in stage[1].items()}
        shot, max_iter = options.get("shot"), options.get("max_iter")
        if not shot or not max_iter:
            raise ValueError(
                f"optimizers[{i}] must give 'shot' and 'max_iter'"
            )
        iterations += int(max_iter)
        shots = max(shots, int(shot))
    if shots > _MAX_SHOTS:
        raise ValueError(
            f"shots per job ({shots}) exceeds the maximum of {_MAX_SHOTS}"
        )

    nb_qubits = args.get("nb_qubits")
    if nb_qubits is None:
        nb_qubits = _DEFAULT[use_case]["nb_qubits"]
    qubits = max(
        sum(int(q) for q in per_var.values())
        for per_var in nb_qubits.values()
    )

    return {
        "mode": mode,
        "iterations": iterations,
        "shots": shots,
        "qubits": qubits,
    }

def _is_small(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return (
        metrics["mode"] != "session"
        and metrics["iterations"] <= _SMALL["iterations"]
        and metrics["shots"] <= _SMALL["shots"]
        and metrics["qubits"] <= _SMALL["qubits"]
    )

def _is_medium(metrics: dict) -> bool:

        and metrics["iterations"] <= _MEDIUM["iterations"]
        and metrics["shots"] <= _MEDIUM["shots"]
        and metrics["qubits"] <= _MEDIUM["qubits"]
    )

  • generation หนึ่งของ CMAES ประกอบด้วยการประเมิน popsize ครั้ง ดังนั้น iteration ของ CMAES จึงนับเป็น generation

  • Jacobian ต้องใช้ Circuit ของตัวเอง (Circuit ที่ถูก shift พารามิเตอร์) ซึ่งไม่นับเป็นการประเมิน ดังนั้นจำนวน Jacobian จึงเท่ากับจำนวน iteration ของ LS-TRF และจำนวนการประเมินมากกว่าจำนวน iteration เพราะจุดทดลองบางจุดถูกปฏิเสธ

from scipy.stats import norm

def black_scholes_call(t, S, sigma, K, T=1.0):
    tau = T - t
    d1 = (np.log(S / K) + 0.5 * sigma**2 * tau) / (sigma * np.sqrt(tau))
    d2 = d1 - sigma * np.sqrt(tau)
    return S * norm.cdf(d1) - K * norm.cdf(d2)
