การย้ายไปใช้หน่วยทรัพยากร (RUs) ใน IBM Quantum Compute API

ตอนนี้ IBM Quantum® Platform วัดการใช้งานเป็น resource unit (RU) แล้ว RU คือหน่วยที่ IBM Quantum ใช้วัดและเรียกเก็บเงินสำหรับการใช้งานเวิร์กโหลดทั้งหมด ก่อนการเปลี่ยนแปลงนี้ แพลตฟอร์มวัดการใช้งานเป็นเวลา QPU ในหน่วยวินาทีหรือมิลลิวินาที ดูข้อมูลเพิ่มเติมเกี่ยวกับ RU ได้ที่ Resource units

ปัจจุบัน API ส่งคืนฟิลด์สองชุด คือฟิลด์เวลาแบบเดิมและฟิลด์ RU แบบใหม่ การทำงานของระบบคุณยังคงใช้ได้ตามปกติ ในรุ่นถัดไป IBM Quantum จะลบฟิลด์เวลาออก ให้เปลี่ยนระบบของคุณให้อ่านฟิลด์ RU ตั้งแต่ตอนนี้

คู่มือนี้ใช้คำศัพท์ดังนี้:

  • Workload: job, session, batch หรือการรัน function

  • QPU workload: job, session หรือ batch โดย QPU workload รันบน QPU เท่านั้น

  • Function workload: การรัน function โดย function workload สามารถใช้การประมวลผลแบบคลาสสิกและ execution license และอาจใช้ QPU ด้วยก็ได้

  • Session: กลุ่มของ job ที่รันร่วมกันบน QPU เครื่องเดียว

  • Instance: service instance ซึ่งเป็นเจ้าของ workload และมีขีดจำกัดการใช้งาน

  • Plan: service plan ของบัญชี ซึ่งกำหนดขีดจำกัดการใช้งานสำหรับทุก instance ในบัญชี

หมายเหตุ

คู่มือนี้ใช้ OpenAPI spec เวอร์ชัน 0.57.2

ค่าของ header IBM-API-Version ต้องเป็น 2026-04-15 หรือเวอร์ชัน API ที่รองรับที่ใหม่กว่า

ส่วนต่อไปนี้ให้รายละเอียดของแต่ละ endpoint

Jobs​

Endpoint: GET /v1/jobs และ GET /v1/jobs/{id}/metrics

ละเว้นให้อ่านแทน
usage.qpu_charge_time_secondsusage.value

อ็อบเจ็กต์ usage ยังมีฟิลด์เหล่านี้ด้วย:

  • usage.unit: หน่วยของ usage.value ค่าจะเป็น "resource_units" เสมอ

  • usage.status: สถานะการเรียกเก็บเงิน ค่าคือ "pending" หรือ "complete" หากสถานะเป็น "pending" แพลตฟอร์มอาจยังเปลี่ยนค่าได้ อย่าใช้ค่า pending เป็นการใช้งานสุดท้าย

  • usage.details[]: การใช้งานของแต่ละเมตริกการเรียกเก็บเงิน ค่า value ของแต่ละรายการอยู่ในหน่วย RU

Example:

"usage": {
  "qpu_charge_time_seconds": 15,  // old field: disregard
  "value": 0.250005,              // new field: read this
  "unit": "resource_units",
  "status": "complete",
  "details": [
    { "value": 0.250005, "unit": "resource_units", "metric": { "id": "…", "value": 15 } }
  ]
}

ฟิลด์ usage.details[].metric.value ไม่ใช่การใช้งานในหน่วย RU แต่เป็นปริมาณของเมตริกที่แพลตฟอร์มใช้คำนวณ RU โดยแต่ละเมตริกมีหน่วยของตัวเอง เช่น หน่วยของเมตริก QPU คือวินาที หากต้องการดูการใช้งาน ให้อ่าน usage.details[].value

Workloads​

Endpoint: GET /v1/workloads.

แต่ละรายการใน workloads[] มีอ็อบเจ็กต์ usage อ็อบเจ็กต์นี้มีฟิลด์เหมือนกับอ็อบเจ็กต์ usage ของ job

ละเว้นให้อ่านแทน
workloads[].usage.qpu_charge_time_secondsworkloads[].usage.value

หาก workload ยังรันอยู่ usage จะเป็น null

Function workloads​

การใช้งานของ function workload อยู่ในหน่วย RU เช่นเดียวกับ QPU workload โดย function workload สามารถใช้ได้มากกว่าหนึ่งเมตริก:

  • การใช้งาน QPU คิดตามวินาทีของเวลาควอนตัม ดู Execution modes

  • การใช้งานการประมวลผลแบบคลาสสิก คิดตามวินาทีของเวลาคลาสสิก

  • ค่า execution license คิดต่อ workload ตามขนาดของปัญหาที่ส่งให้ function

แพลตฟอร์มแปลงปริมาณของแต่ละเมตริกเป็น RU ดังนั้นค่าการใช้งานทั้งหมดจึงอยู่ในหน่วย RU:

  • usage.value คือการใช้งานของ workload ในหน่วย RU

  • usage.details[].value คือการใช้งานของหนึ่งเมตริก ในหน่วย RU

  • usage.details[].metric.value คือปริมาณของเมตริก ในหน่วยของเมตริกนั้น ไม่ใช่หน่วย RU

หากคุณแสดงหรือรวมค่าการใช้งาน ให้ใช้ usage.value และ usage.details[].value อย่าใช้ usage.details[].metric.value

Sessions​

Endpoint: POST /v1/sessions และ GET /v1/sessions/{id}

ละเว้นให้อ่านแทน
elapsed_time (วินาที)usage.value

อ็อบเจ็กต์ usage ของ session มี unit และ details[] ฟิลด์เหล่านี้ทำงานเหมือนกับในอ็อบเจ็กต์ usage ของ job ยกเว้นฟิลด์ status ซึ่งไม่มีใน session

ฟิลด์ interactive_ttl, max_ttl และ active_ttl ไม่เปลี่ยนแปลง ฟิลด์เหล่านี้เป็นขีดจำกัดเวลา (TTL ย่อมาจาก "time to live") ไม่ใช่การใช้งาน หน่วยยังคงเป็นวินาที

การใช้งานของ Instance​

Endpoint: GET /v1/instances/usage.

ละเว้นให้อ่านแทน
usage_consumed_secondsusage_consumed_ru
usage_limit_secondsusage_limit_ru
usage_allocation_secondsusage_allocation_ru

ฟิลด์ usage_limit_reached, usage_period และ time_available_at ไม่เปลี่ยนแปลง

แผนของบัญชี​

Endpoint: GET /v1/accounts/{id}.

แต่ละรายการใน plans[] มีการเปลี่ยนแปลงดังนี้:

ละเว้นให้อ่านแทน
plans[].usage_limit_secondsplans[].usage_limit_ru
plans[].usage_allocation_secondsplans[].usage_allocation_ru
plans[].unallocated_usage_secondsplans[].unallocated_usage_ru

Service instance ใน Resource Controller API​

IBM Cloud® Resource Controller API เป็น API แยกต่างหาก ใช้สำหรับสร้างและอัปเดต service instance หากคุณสร้างหรืออัปเดต instance ด้วย API นี้ ให้เปลี่ยนพารามิเตอร์ของ instance ด้วย

เมื่อสร้างหรืออัปเดต instance ให้ส่งพารามิเตอร์เหล่านี้ในคำขอ:

อย่าส่งให้ส่งแทนชนิดของพารามิเตอร์ใหม่
instance_limit_secondsinstance_limit_ruNumber หรือ null
usage_allocation_secondsusage_allocation_ruNumber หรือ null

พารามิเตอร์มีความหมายดังนี้:

  • ขีดจำกัดของ instanceการใช้งานสูงสุดของ instance หากคุณไม่ส่งขีดจำกัดบน Open Plan ค่าเริ่มต้นคือค่า RU ที่เทียบเท่า 10 นาที

  • การจัดสรรการใช้งาน: ส่วนแบ่งการใช้งานของ instance fair-share scheduler ใช้ค่านี้เพื่อกำหนดลำดับความสำคัญของ instance ในคิว การจัดสรรไม่มีผลกับ instance แบบ Pay-As-You-Go

เมื่อคุณอ่าน instance อ็อบเจ็กต์ extensions ในการตอบกลับจะมีทั้งฟิลด์เดิมและฟิลด์ใหม่ ให้ละเว้น instance_limit_seconds และ usage_allocation_seconds และอ่าน instance_limit_ru และ usage_allocation_ru แทน

ดูข้อมูลเพิ่มเติมได้ที่ IBM Quantum Compute Service REST API documentation

การวิเคราะห์การใช้งาน​

Endpoint: GET /v1/analytics/usage, GET /v1/analytics/usage_grouped และ GET /v1/analytics/usage_grouped_by_date

ทั้งสาม endpoint มีฟิลด์การใช้งานเหมือนกัน สอง endpoint แบบจัดกลุ่มจะส่งคืนฟิลด์เหล่านี้สำหรับแต่ละกลุ่มหรือแต่ละวันที่

ฟิลด์การใช้งานของ analytics แบบเดิมอยู่ในหน่วยมิลลิวินาที ไม่ใช่วินาที

sessions_usagesessions_usage_ru
avg_sessions_usageavg_sessions_usage_ru
max_sessions_usagemax_sessions_usage_ru
batch_sessions_usagebatch_sessions_usage_ru
avg_batch_sessions_usageavg_batch_sessions_usage_ru
max_batch_sessions_usagemax_batch_sessions_usage_ru
dedicated_sessions_usagededicated_sessions_usage_ru
avg_dedicated_sessions_usageavg_dedicated_sessions_usage_ru
max_dedicated_sessions_usagemax_dedicated_sessions_usage_ru
individual_jobs_usageindividual_jobs_usage_ru
avg_individual_jobs_usageavg_individual_jobs_usage_ru
max_individual_jobs_usagemax_individual_jobs_usage_ru
functions_quantum_usage_msfunctions_quantum_usage_ru

ฟิลด์ function เหล่านี้เป็นฟิลด์ใหม่ ไม่มีฟิลด์เดิมในหน่วยมิลลิวินาที:

  • functions_usage_ru

  • avg_functions_usage_ru

  • max_functions_usage_ru

  • functions_classical_usage_ru

  • functions_license_cost_ru

ยอดรวมใน usage_ru รวมมากกว่ายอดรวมใน usage:

  • usage คือผลรวมของเวลา QPU สำหรับ session, job เดี่ยว และ function

  • usage_ru คือผลรวมของการใช้งานสำหรับ session, job เดี่ยว และ function สำหรับ function ยังรวมการประมวลผลแบบคลาสสิกและค่า license ด้วย

ดังนั้น usage_ru จึงไม่ใช่แค่ usage ที่เปลี่ยนหน่วย

ฟิลด์ queue_time, avg_queue_time และ max_queue_time ไม่เปลี่ยนแปลง ฟิลด์เหล่านี้วัดเวลารอ ไม่ใช่การใช้งาน หน่วยยังคงเป็นมิลลิวินาที

ฟิลด์ที่ไม่เปลี่ยนแปลง​

ฟิลด์เหล่านี้มีค่าเวลา แต่ไม่ได้วัดการใช้งาน IBM Quantum ไม่มีแผนจะแทนที่ฟิลด์เหล่านี้:

  • wait_time_seconds บน backend: เวลารอในคิวโดยประมาณ

  • circuits_execution_time_ns ใน GET /v1/jobs/{id}/metrics: เวลาที่ job รันบน QPU

  • interactive_ttl, max_ttl และ active_ttl บน session

  • queue_time, avg_queue_time และ max_queue_time ใน analytics

  • rep_times และ circuit_duration ในการกำหนดค่า backend

ขั้นตอนการย้าย​

  1. ค้นหาฟิลด์เดิมแต่ละฟิลด์ในโค้ดของคุณ ค้นหา qpu_charge_time_seconds, elapsed_time, ฟิลด์ _seconds ในคู่มือนี้ และฟิลด์ analytics ที่เป็นมิลลิวินาที

  2. เปลี่ยนฟิลด์เดิมแต่ละฟิลด์เป็นฟิลด์ RU ตามตารางในคู่มือนี้

  3. หากคุณสร้างหรืออัปเดต service instance ด้วย Resource Controller API ให้ส่ง instance_limit_ru และ usage_allocation_ru อย่าส่งพารามิเตอร์ _seconds

  4. เปลี่ยนป้ายกำกับใน user interface ของคุณ ให้แสดง "RU" หรือ "resource units" ไม่ใช่ "วินาที" หรือ "นาที" อย่าแปลง RU เป็นเวลา เพราะไม่มีอัตราคงที่ระหว่าง RU กับเวลา

  5. หากคุณอ่าน usage.details[] ให้ใช้ value สำหรับการใช้งานในหน่วย RU อย่าใช้ metric.value เพราะหน่วยของมันคือหน่วยของเมตริก

  6. หาก usage.status เป็น "pending" ให้แสดงค่าเป็นค่าชั่วคราว

  7. หากฟิลด์ RU หายไปหรือเป็น null ให้ใช้ตรรกะเดียวกับที่คุณใช้กับฟิลด์เดิมในปัจจุบัน
