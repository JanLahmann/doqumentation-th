Rimay Quantum Feature Extraction - Qiskit Function โดย Kipu Quantum

ดู API reference

หมายเหตุ

Qiskit Functions เป็นฟีเจอร์เชิงทดลองที่ใช้ได้เฉพาะผู้ใช้ IBM Quantum® Premium Plan, Flex Plan และ On-Prem (ผ่าน IBM Quantum Platform API) Plan เท่านั้น ฟีเจอร์นี้อยู่ในสถานะ preview release และอาจมีการเปลี่ยนแปลง

ภาพรวม​

Rimay เสริม pipeline machine learning แบบคลาสสิกด้วยฟีเจอร์ที่สร้างบนฮาร์ดแวร์ควอนตัม function รับข้อมูลตารางแบบคลาสสิกและคืนชุดฟีเจอร์ที่แปลงด้วยควอนตัม เมื่อระบบควอนตัมประมวลผลข้อมูล จะสร้างฟีเจอร์ที่สมบูรณ์ซึ่งจับความสัมพันธ์แบบไม่เชิงเส้นระหว่าง input ได้ คุณใช้ฟีเจอร์ที่สร้างขึ้นเดี่ยว ๆ หรือรวมกับฟีเจอร์เดิมของคุณเพื่อฝึกโมเดลคลาสสิกใดก็ได้ บนชุดข้อมูลขนาดเล็กถึงกลาง ฟีเจอร์ที่แปลงด้วยควอนตัมสามารถช่วยให้คุณภาพการทำนายดีขึ้นเมื่อเทียบกับ baseline แบบคลาสสิกล้วน

function นี้สร้างมาสำหรับผู้ใช้ต่อไปนี้:

  • ทีม data science ที่มี pipeline machine learning อยู่แล้วบนชุดข้อมูลตารางขนาดเล็กถึงกลาง ซึ่งคุณภาพการทำนายหยุดนิ่ง คุณเพิ่ม Rimay เป็นขั้นตอนประมวลผลก่อนเพิ่มเติมหนึ่งขั้น โดยไม่ต้องสร้าง quantum circuit เอง

  • นักวิจัยที่สำรวจวิธีควอนตัมสำหรับงาน machine learning

คำอธิบาย​

อัลกอริทึมการสกัดฟีเจอร์เชิงควอนตัม [1] รวมหลักการสองอย่างของ quantum machine learning เข้าด้วยกัน อย่างแรกคือ quantum feature maps ซึ่งฝังข้อมูลลงในปริภูมิฮิลเบิร์ตมิติสูง จึงได้การแทนข้อมูลที่แสดงออกได้มากขึ้น อย่างที่สองคือ quantum reservoir computing ซึ่งใช้พลวัตของระบบควอนตัมหลายส่วนเป็นการแปลงแบบไม่เชิงเส้นของอินพุต

Rimay เข้ารหัสค่าฟีเจอร์และข้อมูลร่วมกัน (mutual information) ระหว่างฟีเจอร์ลงในสนามเฉพาะที่และสัมประสิทธิ์การคับเปิลของแฮมิลโทเนียนแบบสปินกลาส พลวัตควอนตัมแบบ counterdiabatic จะพัฒนาระบบไปสู่สถานะพลังงานต่ำ ซึ่งมีส่วนผสมแบบไม่เชิงเส้นของสหสัมพันธ์ในข้อมูลอินพุต Rimay สกัดสหสัมพันธ์เหล่านี้ด้วยการวัดค่าคาดหวังของหนึ่งส่วนและสองส่วน ค่าคาดหวังเหล่านี้คือฟีเจอร์ที่ผ่านการแปลงเชิงควอนตัมซึ่งคุณป้อนเข้าโมเดล machine learning ของคุณ

เวิร์กโฟลว์​

  1. ประมวลผลข้อมูลตารางล่วงหน้าเหมือนที่ทำกับ machine learning แบบคลาสสิก Rimay ต้องใช้ฟีเจอร์ที่เป็นตัวเลข ดังนั้นให้แปลงฟีเจอร์เชิงหมวดหมู่เป็นตัวเลข เช่น ใช้ OneHotEncoder ของ scikit-learn

  2. แบ่งข้อมูลเป็นชุดฝึกและชุดทดสอบ แล้วอัปโหลดทั้งสองชุดไปยังฟังก์ชัน ตามที่แสดงในส่วน ตัวอย่าง

  3. Rimay ใช้ข้อมูลฝึกสร้างแฮมิลโทเนียนที่แทนข้อมูล ฟีเจอร์แต่ละตัวสอดคล้องกับหนึ่ง qubit และชุดฝึกทั้งหมดเป็นตัวกำหนดว่าฟีเจอร์ใด และ qubit ใด จะมีปฏิสัมพันธ์กัน Rimay เก็บโครงสร้างนี้ไว้เพื่อแมปข้อมูลทดสอบและข้อมูลสำหรับ inference ภายหลังด้วยแฮมิลโทเนียนเดียวกัน

  4. สำหรับแต่ละตัวอย่าง ค่าฟีเจอร์จะกำหนดสนามเฉพาะที่ของแฮมิลโทเนียน และข้อมูลร่วมระหว่างฟีเจอร์จะกำหนดสัมประสิทธิ์การคับเปิลของโครงสร้างจากขั้นตอนที่ 3 Rimay แปลงวิวัฒนาการแบบ counterdiabatic ของแฮมิลโทเนียนนี้เป็นดิจิทัลในรูปแบบ circuit แล้วรัน circuit เหล่านั้นบน QPU

  5. Rimay วัดบิตสตริงที่ได้ แล้วคำนวณค่าคาดหวังหนึ่งส่วนและค่าคาดหวังสองส่วนของ qubit ที่คับเปิลกันทางกายภาพ

  6. คุณดาวน์โหลดค่าคาดหวังในรูปแบบที่ป้อนเข้าโมเดลได้โดยตรง หรือนำไปรวมกับฟีเจอร์เดิมของคุณ

หมายเหตุ

เนื่องจากโครงสร้างนี้ จำนวน qubit ที่การรันต้องใช้จึงเท่ากับจำนวนฟีเจอร์ และจำนวน circuit ที่ส่งเท่ากับจำนวนตัวอย่าง

หลังจากฟิตการแมปแล้ว คุณสามารถแมปข้อมูลใหม่ผ่านการแมปนั้นได้ เช่น สำหรับ inference จากนั้น Rimay จะดึงแฮมิลโทเนียนที่สร้างไว้ระหว่างการฟิต แล้วสร้าง circuit สำหรับตัวอย่างใหม่จากมัน

นำ Rimay ไปใช้ใน machine learning pipeline ของคุณ​

เช่นเดียวกับ pipeline แบบคลาสสิก คุณเริ่มจากประมวลผลข้อมูลดิบล่วงหน้า เช่น ทำ one-hot encoding ให้ฟีเจอร์เชิงหมวดหมู่ แล้วแบ่งเป็นชุดฝึกและชุดทดสอบ แทนที่จะป้อนทั้งสองชุดเข้าโมเดลโดยตรง ให้ป้อนเข้า Rimay ก่อน แล้วฝึกโมเดลของคุณด้วยฟีเจอร์ที่ผ่านการแปลงเชิงควอนตัม

เบนช์มาร์ก​

Kipu Quantum ทดสอบ Rimay กับชุดข้อมูล German credit จาก OpenML [2] ซึ่งจัดประเภทผู้ขอสินเชื่อ 1000 ราย เป็นความเสี่ยงด้านเครดิตดีหรือไม่ดี ชุดข้อมูลมีแอตทริบิวต์เชิงหมวดหมู่ 13 รายการและเชิงตัวเลขเจ็ดรายการ การทำ one-hot encoding กับแอตทริบิวต์เชิงหมวดหมู่ได้ฟีเจอร์ตัวเลข 48 ตัว เบนช์มาร์กกันตัวอย่าง 20% ไว้เป็นชุดทดสอบ

เป็นค่าพื้นฐาน มีการฝึกโมเดลคลาสสิกหลายตัวด้วยฟีเจอร์คลาสสิก สำหรับ Rimay มีการฝึก random forest สองแบบ คือด้วยฟีเจอร์ที่ผ่านการแปลงเชิงควอนตัมเพียงอย่างเดียว (Random forest Q) และด้วยฟีเจอร์ที่ผ่านการแปลงเชิงควอนตัมรวมกับฟีเจอร์คลาสสิก (Random forest H ย่อมาจาก hybrid) ตารางแสดงเฉพาะ random forest เพราะทำงานได้ดีที่สุดกับฟีเจอร์ที่ผ่านการแปลงเชิงควอนตัม

ข้อควรระวัง

ชุดทดสอบมีเพียง 200 ตัวอย่าง ดังนั้นการทำนายถูกเพิ่มอีกหนึ่งตัวอย่างจะทำให้ accuracy เปลี่ยนไป 0.005 ให้อ่านความแตกต่างเหล่านี้เป็นแนวโน้มที่ต้องตรวจสอบเพิ่มเติม ไม่ใช่ผลที่มีนัยสำคัญ ความแม่นยำของการทำนายยังอาจขึ้นกับสัญญาณรบกวนจากฮาร์ดแวร์ในฟีเจอร์ที่สกัดได้ ดังนั้นให้ใช้ shot มากพอที่ shot noise จะไม่จำกัดผลลัพธ์

อินพุต​

mode เป็นตัวกำหนดว่าการรันต้องใช้พารามิเตอร์ใดบ้าง สำหรับคำอธิบายของพารามิเตอร์อินพุตทุกตัว ดู API reference

ไฟล์อินพุต​

  • อัปโหลดทุกไฟล์ด้วย catalog.file_upload() ก่อนรันฟังก์ชัน

  • การอัปโหลดจะแทนที่ไฟล์ชื่อเดียวกันที่มีอยู่ก่อน แม้จะเป็นของ job ที่คุณส่งไปแล้วแต่ยังไม่เริ่มก็ตาม หากต้องการรันหลาย job พร้อมกัน ให้ตั้งชื่อไฟล์ของแต่ละ job ไม่ซ้ำกัน เช่น run1_x_train.csv และ run2_x_train.csv

  • ทุกไฟล์เป็นไฟล์ CSV ที่มีแถวส่วนหัว แต่ละคอลัมน์ของไฟล์ฟีเจอร์คือฟีเจอร์หนึ่งตัว และทุกค่าต้องเป็นตัวเลข

  • y_train มีคอลัมน์ตัวเลขเพียงหนึ่งคอลัมน์พอดี โดยมีหนึ่งป้ายกำกับต่อหนึ่งแถวของ x_train ให้แมปป้ายกำกับเชิงหมวดหมู่เป็นตัวเลข เช่น good และ bad เป็น 1 และ 0

  • x_test และ x_inference ต้องมีคอลัมน์เหมือนกับ x_train และเรียงลำดับเดียวกัน

เก็บ mapping_id และ backend_name ไว้

mapping_id เป็นทางเดียวที่จะเข้าถึงการแมปที่การฟิตของคุณสร้างขึ้น และไม่สามารถค้นหาหรือกู้คืนได้ มันให้สิทธิ์ในการใช้การแมปนั้น จึงควรปฏิบัติเหมือนข้อมูลรับรอง และอย่าแชร์ หากทำหาย คุณต้องฟิตการแมปใหม่ ซึ่งต้องรันบนฮาร์ดแวร์ควอนตัมอีกครั้ง และควรบันทึก backend_name ของการฟิตไว้ด้วย เพราะการแมปรันได้บนโปรเซสเซอร์นั้นเท่านั้น

ข้อจำกัด​

  • ฟีเจอร์แต่ละตัวถูกแมปไปยังหนึ่ง qubit ดังนั้นโปรเซสเซอร์ต้องมี qubit อย่างน้อยเท่ากับจำนวนฟีเจอร์ในข้อมูลของคุณ หากมีฟีเจอร์มากกว่านั้น ให้ลดจำนวนลงด้วยเทคนิคการเลือกฟีเจอร์ก่อน

  • ตัวอย่างแต่ละตัวกลายเป็นหนึ่ง circuit และการรันนับตัวอย่างฝึกและทดสอบรวมกัน การรันหนึ่งครั้งมีตัวอย่างได้สูงสุด 15,000 ตัวอย่าง

  • job เดียวขอรันได้สูงสุด 10 ล้านครั้ง ดังนั้นจำนวนตัวอย่างคูณ shots ต้องไม่เกิน 10 ล้าน

  • job ต้องเสร็จภายใน 24 ชั่วโมง รวมเวลาที่ circuit รอในคิวของโปรเซสเซอร์ด้วย job ที่ใช้เวลานานกว่านั้นจะถูกหยุดโดยไม่มีผลลัพธ์ บนโปรเซสเซอร์ที่คิวยาว ให้เก็บชุดข้อมูลขนาดใหญ่ไว้ต่ำกว่าขีดจำกัดเหล่านี้พอสมควร

เอาต์พุต​

job.result() คืนค่าเป็น dictionary ตัวฟีเจอร์ที่ผ่านการแปลงเชิงควอนตัมเองจะถูกเขียนเป็นไฟล์ CSV ที่คุณดาวน์โหลดด้วย catalog.file_download() สำหรับคำอธิบายของทุกคีย์ใน dictionary ดู API reference สำหรับเวลาที่แต่ละเฟสของการรันใช้ ดู เมทาดาทาของการรัน

ไฟล์เอาต์พุตทุกไฟล์มีหนึ่งแถวต่อหนึ่งแถวอินพุต เรียงตามลำดับของไฟล์อินพุต และมีหนึ่งคอลัมน์ต่อฟีเจอร์ที่ผ่านการแปลงเชิงควอนตัมหนึ่งตัว คอลัมน์ที่ชื่อขึ้นต้นด้วย corr_ คือค่าคาดหวังสองส่วน ไฟล์ไม่มีคอลัมน์ป้ายกำกับ ป้ายกำกับของข้อมูลฝึกยังอยู่ในไฟล์ y_train ของคุณ

เมทาดาทาของการรัน​

resource_usage มีหนึ่งรายการสำหรับแต่ละเฟสการทำงานที่การรันผ่าน ได้แก่ "RUNNING: MAPPING", "RUNNING: POST_PROCESSING" และบน QPU มักมี "RUNNING: WAITING_FOR_QPU" ด้วย แต่ละรายการมี CPU_TIME ซึ่งเป็นเวลาจริง (wall-clock) ของเฟสเป็นวินาที และ QPU_TIME ซึ่งเป็นเวลา QPU เป็นวินาที บน QPU เวลา QPU ที่ IBM เรียกเก็บจะบันทึกไว้ใต้ "RUNNING: MAPPING" ซึ่งเป็นเฟสที่ circuit รัน

"RUNNING: WAITING_FOR_QPU" คือเวลาที่ job ของคุณรอในคิวของ IBM การรันดึงเวลานี้จาก timestamp ของ job ที่ IBM ให้มา และไม่นับรวมใน "RUNNING: MAPPING" หาก IBM ไม่รายงาน timestamp เหล่านั้นสำหรับทุก job รายการนี้จะไม่มี และเวลารอจะรวมอยู่ใน "RUNNING: MAPPING"

IBM® คำนวณการใช้งานเสร็จหลังจาก job จบไประยะหนึ่ง การรันจะรอได้นานประมาณหนึ่งนาที การใช้งานที่ยังคำนวณอยู่หลังจากเวลานั้นจะไม่รวมใน QPU_TIME และการใช้งานสุดท้ายจะแสดงบน IBM Quantum Platform หากการรันอ่านข้อมูลการใช้งานจาก IBM ไม่ได้ QPU_TIME จะเป็น None

คำนวณขนาดก่อนส่ง​

รันสิ่งนี้กับอินพุตของคุณเอง มันแค่อ่านอินพุตและไม่ทำอย่างอื่น ไม่มีการส่ง job และไม่มีการจองอะไร คุณจึงเรียกใช้กี่ครั้งก็ได้

ส่งชุดข้อมูลเอง ไม่ใช่ชื่อไฟล์ โดยเรียงลำดับเดียวกับ input_file พร้อมกับ mode ของการรัน ขั้นตอนที่ 2 ของตัวอย่าง แสดงการเรียกใช้

from os import PathLike
from typing import Any, Literal, Sequence, Sized

Size = Literal["S", "M", "L"]

# Upper bounds (inclusive) in samples.
_SMALL = 2_999
_MEDIUM = 9_999

FIT_TRANSFORM, TRANSFORM, DELETE = "fit-transform", "transform", "delete"

# Which positions of input_file hold samples, per mode. The labels in
# y_train submit no circuits of their own, so they are not counted.
SAMPLE_POSITIONS = {FIT_TRANSFORM: (0, 2), TRANSFORM: (0,)}

def calculate_function_size(problem: Sequence[Sized], **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") required to run the function."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def _measure(problem: Sequence[Sized], **kwargs: Any) -> dict:
    """The samples the job submits."""
    return {"samples": count_samples(problem, kwargs.get("mode"))}

def count_samples(problem: Sequence[Sized], mode: Any) -> int:
    """Rows across the data sets of ``problem`` that carry samples."""
    if mode == DELETE:
        return 0
    if mode not in SAMPLE_POSITIONS:
        raise ValueError(f"cannot size mode {mode!r}")
    if _is_name(problem) or (
        isinstance(problem, (list, tuple))
        and any(_is_name(data) for data in problem)
    ):
        raise TypeError(
            "pass the data, not the file name: read each input_file, e.g. with "
            "pandas.read_csv, and pass the data sets in input_file order"
        )
    if not isinstance(problem, (list, tuple)):
        raise TypeError(
            "pass a list of data sets in input_file order, e.g. [x_train, y_train], "
            f"not a single {type(problem).__name__}"
        )
    return sum(
        len(problem[i]) for i in SAMPLE_POSITIONS[mode] if i < len(problem)
    )

def _is_name(value: Any) -> bool:
    """A file name or path rather than data."""
    return isinstance(value, (str, bytes, PathLike))

def _is_small(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return metrics["samples"] <= _SMALL

def _is_medium(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return metrics["samples"] <= _MEDIUM

กรณีการใช้งาน​

ในการจัดประเภทข้อมูลตารางบนชุดข้อมูลขนาดเล็กถึงกลาง Kipu Quantum ได้ใช้การสกัดฟีเจอร์เชิงควอนตัมกับงานต่อไปนี้

  • การจัดประเภทความเสี่ยงด้านเครดิต

  • การจัดประเภทความเป็นพิษของโมเลกุล

นอกจากข้อมูลตาราง neural network ที่ถูกตรึง (frozen) สามารถแปลงรูปภาพเป็นฟีเจอร์ตัวเลข ซึ่งการสกัดฟีเจอร์เชิงควอนตัมจะแมปต่อเป็นฟีเจอร์ที่ผ่านการแปลงเชิงควอนตัม

  • การจัดประเภทภาพถ่ายดาวเทียม [3]
