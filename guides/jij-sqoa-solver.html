SQOA Solver - Qiskit Function โดย JIJ

ดู API reference

หมายเหตุ

Qiskit Functions เป็นฟีเจอร์เชิงทดลองที่ใช้ได้เฉพาะผู้ใช้ IBM Quantum® Premium Plan, Flex Plan และ On-Prem (ผ่าน IBM Quantum Platform API) Plan เท่านั้น ฟีเจอร์นี้อยู่ในสถานะ preview release และอาจมีการเปลี่ยนแปลง

ภาพรวม​

ด้วย SQOA Solver โดย JIJ คุณสามารถแก้ปัญหา combinatorial optimization ขนาดใหญ่บนคอมพิวเตอร์ควอนตัม IBM® ได้ ตัวแก้นี้อิงตาม Sampling-based Quantum Optimization Algorithm with Quantum Relaxation (SQOA-QR) [1] ต่างจากอัลกอริทึมควอนตัมที่ใช้การจับคู่แบบหนึ่งต่อหนึ่งระหว่างตัวแปรตัดสินใจแบบคลาสสิกกับ qubit SQOA Solver สามารถจัดการปัญหา optimization ที่มีตัวแปรมากกว่าจำนวน qubit ที่มีอยู่บนอุปกรณ์ควอนตัมปัจจุบันได้ การออกแบบที่อิงการสุ่มตัวอย่างยังทำให้ไวต่อสัญญาณรบกวนทางกายภาพบนฮาร์ดแวร์ควอนตัมปัจจุบันน้อยลงด้วย คุณสมบัติเหล่านี้ทำให้ SQOA Solver เหมาะกับปัญหา optimization ในช่วงนี้ของการประมวลผลควอนตัม

ตัวแก้นี้จัดการปัญหา Quadratic Unconstrained Binary Optimization (QUBO) ที่ให้มาในรูปสูตรทางคณิตศาสตร์แบบคลาสสิก และแมปสูตรแบบคลาสสิกไปยังบริบทควอนตัมให้อัตโนมัติ คุณยังแปลงปัญหาที่มีข้อจำกัดให้เป็นปัญหาที่ไม่มีข้อจำกัดได้โดยใช้ penalty method

ส่วนต่อไปนี้อธิบาย workflow ของตัวแก้ ผลการ benchmark และตัวอย่างแบบ end-to-end ที่สร้างแบบจำลองปัญหาด้วย qiskit-addon-opt-mapper และอาจใช้ Open Mathematical prograMming eXchange (OMMX) ด้วย OMMX เป็นรูปแบบข้อมูลเปิดและ SDK ที่ช่วยให้แลกเปลี่ยนปัญหา optimization ระหว่างเครื่องมือซอฟต์แวร์ได้ง่ายขึ้น

คำอธิบาย​

SQOA Solver ใช้งาน Sampling-based Quantum Optimization Algorithm with Quantum Relaxation (SQOA-QR) และล้อมด้วยการประมวลผลก่อนและหลังแบบคลาสสิก ส่วนนี้อธิบายเฟรมเวิร์ก SQOA และความแตกต่างจาก Quantum Approximate Optimization Algorithm (QAOA)

ภาพต่อไปนี้แสดงแผนภาพของ workflow ของ SQOA Solver

เฟรมเวิร์ก SQOA​

SQOA เป็นเฟรมเวิร์กที่อิงการสุ่มตัวอย่างสำหรับ combinatorial optimization [1] โดยรวมสองเทคนิคเข้าด้วยกัน คือ Quantum Random Access Optimization (QRAO) [2] ซึ่งเข้ารหัสปัญหาใน quantum relaxation และ sample-based quantum diagonalization (SQD) [3] หรือที่เรียกว่า quantum-selected configuration interaction (QSCI) [4] ซึ่งใช้คอมพิวเตอร์ควอนตัมเพียงเพื่อสุ่มตัวอย่าง bitstring และหา state พลังงานต่ำบนคอมพิวเตอร์คลาสสิก SQOA เป็นเฟรมเวิร์กในความหมายที่ว่ากำหนดการรวมนี้ไว้ แต่ปล่อยรายละเอียดให้แต่ละการใช้งานเลือกเอง เช่น วิธีกำหนดตัวแปรให้กับ qubit และ circuit ใดที่สร้างตัวอย่าง

  • Quantum relaxation ด้วย QRAO QAOA และแนวทางอิง Ising อื่น ๆ แทนตัวแปรไบนารีแต่ละตัวด้วยตัวดำเนินการ ZZZ ของ qubit ของมัน ส่วน QRAO ใช้ตัวดำเนินการ XXX และ YYY ด้วย เมื่อใช้ (3,1) quantum random access code (QRAC) ตัวแปรไบนารีได้สูงสุดสามตัวใช้ qubit เดียวร่วมกัน และแต่ละตัวแปรแทนด้วยตัวดำเนินการ Pauli ที่ต่างกัน

    QUBO จะกลายเป็น relaxed Hamiltonian ที่ต้องการ qubit น้อยกว่า Ising Hamiltonian ตัวแปรที่มีปฏิสัมพันธ์กันใน QUBO ต้องวางไว้บน qubit คนละตัว หากใช้ qubit ร่วมกัน ผลคูณของตัวดำเนินการ Pauli ของพวกมันจะลดรูปเหลือตัวดำเนินการเดียวบน qubit นั้น (เช่น XY=iZXY = iZXY=iZ) และ relaxed Hamiltonian จะไม่แสดงปฏิสัมพันธ์ของพวกมันอีกต่อไป

    ดังนั้นการกำหนดตัวแปรให้กับ qubit จึงเป็นตัวกำหนดทั้งจำนวน qubit และคุณภาพของ relaxation และ SQOA Solver ออกแบบการกำหนดนี้ในขั้นตอนประมวลผลก่อน

  • Sample-based quantum diagonalization (SQD) ขั้นแรกคอมพิวเตอร์ควอนตัมเตรียม quantum state ที่ซ้อนทับกับ state พลังงานต่ำของ relaxed Hamiltonian แล้วสุ่มตัวอย่าง bitstring จากมัน จากนั้นคอมพิวเตอร์คลาสสิกฉาย relaxed Hamiltonian ลงบน subspace ที่ขึงด้วย bitstring ที่สุ่มได้ และทำ diagonalization เพื่อประมาณ ground state

    เนื่องจาก relaxed Hamiltonian ไม่เป็นแนวทแยง การทำ diagonalization จึงรวม bitstring ที่สุ่มได้เป็น superposition ส่วนกับ Ising Hamiltonian แบบทแยง ทุก bitstring เป็น eigenstate อยู่แล้ว และ diagonalization จะเลือกได้เพียงตัวอย่างที่ดีที่สุดเท่านั้น แนวทางเดียวกันนี้เคยถูกใช้กับปัญหาขนาดใหญ่ในเคมีควอนตัม

ground state โดยประมาณที่ได้จาก SQD ไม่สอดคล้องกับคำตอบแบบคลาสสิกของปัญหาเดิมโดยตรง จึงต้องถอดรหัสคำตอบแบบคลาสสิกจากมัน เนื่องจาก state นี้คำนวณบนคอมพิวเตอร์คลาสสิก การถอดรหัสที่เรียกว่า rounding จึงเป็นการประมวลผลหลังแบบคลาสสิก SQOA Solver ใช้เทคนิคถอดรหัสที่ออกแบบมาเพื่อให้ได้คำตอบแบบคลาสสิกที่ดีขึ้นด้วยวิธี heuristic

ตารางต่อไปนี้เปรียบเทียบ SQOA กับ QAOA ซึ่งเป็นแนวทาง variational ทั่วไปสำหรับปัญหาประเภทเดียวกัน

การใช้ QPUประมาณค่าพลังงานของ circuit ที่มีพารามิเตอร์ซ้ำ ๆ ภายในลูป optimization แบบคลาสสิกสุ่มตัวอย่าง bitstring เท่านั้น ไม่มีการฝึกพารามิเตอร์ของ circuit บน QPU
จากตัวอย่างสู่คำตอบเลือก bitstring ที่วัดได้ดีที่สุดทำ diagonalization ของ relaxed Hamiltonian ใน subspace ที่สุ่มได้บนคอมพิวเตอร์คลาสสิก แล้ว round state ที่ได้

รอบ ๆ SQOA-QR นั้น SQOA Solver เพิ่มการประมวลผลแบบคลาสสิก ขั้นประมวลผลก่อนจะตรึงตัวแปรที่หาค่าเหมาะสมที่สุดได้ล่วงหน้า และออกแบบการกำหนดตัวแปรให้กับ qubit ส่วนขั้นประมวลผลหลังจะปรับปรุงคำตอบที่ round แล้วด้วย local search ซึ่งคุณปิดได้ด้วย postprocessing_level=0

เตรียม input ด้วย qiskit-addon-opt-mapper​

คู่มือนี้สร้างแบบจำลองปัญหาด้วยคลาส OptimizationProblem ของ qiskit-addon-opt-mapper SQOA Solver รับปัญหา QUBO เป็น coefficient dictionary ในรูปแบบ tuple-string ที่ฟังก์ชัน optimization ของ IBM ใช้ ดังนั้นทุกตัวอย่างในคู่มือนี้จึงทำตามรูปแบบการเตรียมฝั่ง client เดียวกัน:

  1. เขียนแบบจำลอง สร้าง OptimizationProblem เพิ่มตัวแปรตัดสินใจแบบไบนารี และกำหนด objective และข้อจำกัดใด ๆ

  2. แปลงเป็น QUBO แปลงปัญหาด้วย OptimizationProblemToQubo ซึ่งเพิ่มข้อจำกัดใด ๆ เข้าไปใน objective เป็นเทอม penalty และคืนปัญหา minimization ที่ไม่มีข้อจำกัดซึ่งเทียบเท่ากัน

  3. แปลงเป็น dictionary ส่ง QUBO ให้ฟังก์ชันช่วย to_problem_dict() ที่นิยามไว้ในส่วนถัดไป แล้วส่งผลลัพธ์ให้ solver.run() เป็น problem พร้อมกับ variable_type="binary"

SQOA Solver ทำ minimization กับปัญหาแบบ dictionary เสมอ ซึ่งตรงกับปัญหา minimization ที่ OptimizationProblemToQubo คืนมา ดังนั้นสำหรับปัญหา maximization ค่า objective_value ที่คืนมาจึงเป็นค่าลบของ objective เดิม หากต้องการอ่านผลลัพธ์ในรูปของปัญหาเดิม ให้ประเมินการกำหนดค่าที่คืนมาด้วย OptimizationProblem ตามที่ตัวอย่างแสดง สำหรับรายละเอียดของรูปแบบ dictionary ดู Accepted problem formats ใน API reference

# %pip install qiskit-addon-opt-mapper

ให้นิยามฟังก์ชันช่วยต่อไปนี้ครั้งเดียวแล้วนำกลับมาใช้ในทุกตัวอย่าง ฟังก์ชันนี้แปลง QUBO ที่ OptimizationProblemToQubo คืนมาเป็นรูปแบบ dictionary key ใช้ดัชนีตัวแปรของ QUBO ดังนั้น key ของคำตอบ x_0, x_1 และต่อ ๆ ไปในผลลัพธ์จึงสอดคล้องกับดัชนีเหล่านั้น ทุกตัวแปรจะได้รายการเชิงเส้น แม้สัมประสิทธิ์เป็นศูนย์ เพื่อให้คำตอบที่คืนมาครอบคลุมทุกตัวแปร

from qiskit_addon_opt_mapper import OptimizationProblem
from qiskit_addon_opt_mapper.converters import OptimizationProblemToQubo

def to_problem_dict(qubo: OptimizationProblem) -> dict[str, float]:
    """Convert a QUBO from OptimizationProblemToQubo to the SQOA Solver dictionary format."""
    objective = qubo.objective
    payload = {"()": objective.constant}
    # Keep every variable in the problem, even with a zero linear coefficient.
    payload.update({f"({i},)": 0.0 for i in range(qubo.get_num_vars())})
    for i, coefficient in objective.linear.to_dict().items():
        payload[f"({i},)"] += coefficient
    for (i, j), coefficient in objective.quadratic.to_dict().items():
        # Fold a binary diagonal term x_i * x_i = x_i into the linear term.
        key = f"({i},)" if i == j else f"({i}, {j})"
        payload[key] = payload.get(key, 0.0) + coefficient
    return {key: float(value) for key, value in payload.items()}

1. เขียนแบบจำลอง​

กำหนดตัวแปรไบนารี xv∈{0,1}x_v \in \{0, 1\}xv​∈{0,1} ให้แต่ละจุดยอดของกราฟ G=(V,E)G = (V, E)G=(V,E) เพื่อบอกว่าอยู่ฝั่งใดของการตัด เส้นเชื่อมถูกตัดเมื่อจุดปลายทั้งสองอยู่คนละฝั่ง ดังนั้นขนาดของการตัดคือ:

Cut(x)=∑(u,v)∈E(xu+xv−2xuxv).\mathrm{Cut}(x) = \sum_{(u,v) \in E} \left(x_u + x_v - 2 x_u x_v\right).Cut(x)=(u,v)∈E∑​(xu​+xv​−2xu​xv​).

objective นี้เป็น QUBO ที่ไม่มีข้อจำกัดอยู่แล้ว ดังนั้น OptimizationProblemToQubo จึงเพียงเปลี่ยน maximization เป็น minimization ที่เทียบเท่า และคงตัวแปรไว้เหมือนเดิม คลาสแอปพลิเคชัน Maxcut ใน qiskit_addon_opt_mapper.applications สร้างแบบจำลองเดียวกันได้ด้วย Maxcut(G).to_optimization_problem()

import networkx as nx

G = nx.random_regular_graph(3, 40, seed=42)

linear = {v: 0 for v in G.nodes}
quadratic = {}
for u, v in G.edges:
    linear[u] += 1
    linear[v] += 1
    quadratic[(u, v)] = -2

maxcut = OptimizationProblem("MaxCut")
maxcut.binary_var_list(G.number_of_nodes(), name="x")
maxcut.maximize(linear=linear, quadratic=quadratic)

ตัวอย่างที่ 2: แปลงปัญหาที่มีข้อจำกัดเป็น QUBO​

SQOA Solver รับปัญหาที่ไม่มีข้อจำกัด ตัวอย่างนี้แสดงวิธีแปลงปัญหาที่มีข้อจำกัดเป็น QUBO ด้วย OptimizationProblemToQubo และแมปผลลัพธ์กลับไปยังตัวแปรของปัญหาเดิม

selection = OptimizationProblem("ConstrainedExample")
selection.binary_var_list(2, name="x")
selection.maximize(linear={"x0": 1, "x1": 1})
selection.linear_constraint({"x0": 1, "x1": 1}, "<=", 1, name="at_most_one")

ตัวอย่างที่ 3: ส่ง OMMX instance​

SQOA Solver ยังรับ ommx.v1.Instance จาก SDK OMMX ซึ่งเก็บชื่อตัวแปร subscript และ metadata การแปลงไว้ด้วยกันกับปัญหา เมื่อเทียบกับ dictionary แล้ว input แบบ OMMX มีข้อดีดังนี้:

  • ผลลัพธ์ยังมี ommx.v1.Solution มาตรฐานอยู่ใน solver_info["ommx_solution"] ด้วย

  • objective_value ถูกประเมินตามความหมายของ instance ดังนั้น objective ของปัญหา maximization จึงไม่ถูกเปลี่ยนเป็นค่าลบ

  • สำหรับ instance ที่แปลงในที่เดิมด้วย Instance.to_qubo() ค่า feasible จะถูกประเมินเทียบกับข้อจำกัดเดิม

ตัวอย่างนี้สร้างแบบจำลอง MaxCut จากตัวอย่างที่ 1 ด้วย JijModeling ซึ่งเป็นเครื่องมือสร้างแบบจำลอง mathematical optimization ที่คอมไพล์แบบจำลองเป็น OMMX instance ติดตั้ง JijModeling ซึ่งจะติดตั้งแพ็กเกจ ommx ด้วย:

# %pip install "jijmodeling~=2.8.0"

SQOA Solver แลกเปลี่ยนข้อมูล OMMX เป็นสตริง Base64 แบบมาตรฐานที่มี padding นิยามฟังก์ชันช่วยต่อไปนี้สำหรับการแปลงนี้:

  • to_problem_payload() แปลง ommx.v1.Instance เป็นสตริงที่คุณส่งเป็น problem

  • to_ommx_solution() ถอดรหัส ommx.v1.Solution มาตรฐานจากผลลัพธ์

import base64

from ommx.v1 import Instance, Solution

def to_problem_payload(instance: Instance) -> str:
    """Serialize an OMMX instance into the `problem` string for SQOA Solver."""
    return base64.b64encode(instance.to_bytes()).decode()

def to_ommx_solution(result: dict) -> Solution:
    """Decode the canonical OMMX solution from a SQOA Solver result."""
    payload = result["metadata"]["solver_info"]["ommx_solution"]
    return Solution.from_bytes(base64.b64decode(payload, validate=True))

1. เขียนแบบจำลองด้วย JijModeling​

สูตรปกติแบบ spin ของ MaxCut บนกราฟ G=(V,E)G = (V, E)G=(V,E) กำหนด sv∈{−1,+1}s_v \in \{-1, +1\}sv​∈{−1,+1} ให้แต่ละจุดยอด เส้นเชื่อมถูกตัดเมื่อ susv=−1s_u s_v = -1su​sv​=−1 ดังนั้นขนาดของการตัดคือ:

Cut⁡(s)=∑(u,v)∈E1−susv2.\operatorname{Cut}(s) = \sum_{(u,v) \in E} \frac{1 - s_u s_v}{2}.Cut(s)=(u,v)∈E∑​21−su​sv​​.

JijModeling ไม่มีตัวแปรตัดสินใจแบบ spin โดยตรง และ SQOA Solver รับตัวแปร QUBO แบบไบนารี ดังนั้นให้ประกาศ bv∈{0,1}b_v \in \{0, 1\}bv​∈{0,1} และนิยามนิพจน์ค่า spin sv=1−2bvs_v = 1 - 2b_vsv​=1−2bv​ ภายในแบบจำลอง ด้วยนิพจน์นี้ objective จะคงอยู่ในรูป spin มาตรฐาน และ instance ที่คอมไพล์แล้วยังคงเป็น QUBO แบบไบนารี

import jijmodeling as jm

@jm.Problem.define("MaxCut", sense=jm.ProblemSense.MAXIMIZE)
def maxcut_model(problem: jm.DecoratedProblem):
    V = problem.Natural()  # number of nodes
    E = problem.Graph(dtype=V)  # edge list
    b = problem.BinaryVar(shape=(V,))
    s = 1 - 2 * b  # spin-valued expression

    problem += jm.sum((1 - s[u] * s[v]) / 2 for u, v in E)
