หมายเหตุ

IBM Quantum® Functions เป็นฟีเจอร์เบต้าที่ใช้ได้เฉพาะผู้ใช้ IBM Quantum Premium Plan, Flex Plan และ On-Prem (ผ่าน IBM Quantum Platform API) Plan เท่านั้น ฟีเจอร์เบต้าอาจมีการเปลี่ยนแปลง

ข้อจำกัดในปัจจุบัน

AI-QEM รุ่นปัจจุบันมีข้อจำกัดดังต่อไปนี้:

  • การลดข้อผิดพลาดจำกัดเฉพาะตระกูลโปรเซสเซอร์ Heron LTM วางแผนรองรับ backend เพิ่มเติมในเวอร์ชันถัดไป

  • การลดข้อผิดพลาดถูกใช้แบบเลือกเฉพาะ การลดข้อผิดพลาดจะทำเฉพาะเมื่อค่าสัมบูรณ์ของ expectation value เป็นไปตาม ∣⟨O⟩noisy∣≥0.1|\langle O \rangle_{noisy}| \geq 0.1∣⟨O⟩noisy​∣≥0.1 เพื่อให้ใช้การลดข้อผิดพลาดเฉพาะที่คาดว่าจะให้ประโยชน์อย่างมีนัยสำคัญ

ข้อจำกัดเหล่านี้สะท้อนขอบเขตปัจจุบันของ AI-QEM รุ่นในอนาคตอาจผ่อนคลายข้อจำกัดเหล่านี้เมื่อ LTM เพิ่มการรองรับ workflow, backend และฟีเจอร์เพิ่มเติม

ภาพรวม​

Quantum error mitigation (QEM) ครอบคลุมโปรโตคอลเชิงอัลกอริทึม เช่น zero-noise extrapolation (ZNE) [2] และ probabilistic error cancellation (PEC) [3] ซึ่งออกแบบมาเพื่อลดอคติที่เกิดจาก noise ใน expectation value บนฮาร์ดแวร์ noisy intermediate-scale quantum (NISQ) โดยไม่ต้องใช้ qubit จำนวนมหาศาลแบบ fault tolerance เต็มรูปแบบ วิธีการเหล่านี้สำคัญอย่างยิ่งต่อการได้ผลการจำลองทางฟิสิกส์และผล benchmark ที่เชื่อถือได้จากโปรเซสเซอร์ปัจจุบัน แม้ในช่วงไม่กี่ปีมานี้จะมีการพัฒนาวิธี QEM จำนวนมาก แต่เกือบทั้งหมดมีข้อแลกเปลี่ยนพื้นฐานร่วมกัน คือต้องใช้เวลา QPU มากขึ้นอย่างมากเพื่อให้ได้ความแม่นยำ ข้อจำกัดหลักของวิธีเหล่านี้คือ sampling overhead ที่เพิ่มแบบเอกซ์โปเนนเชียล เพราะการสร้างสัญญาณที่ไม่เอนเอียงจาก circuit ที่มี noise ทำให้ความแปรปรวนทางสถิติของ estimator เพิ่มขึ้นอย่างมาก ดังนั้นการรับมือกับระดับ noise ที่สูงขึ้นจึงต้องใช้ measurement shot มากขึ้นหลายระดับขนาด ซึ่งนำไปสู่เวลารัน QPU ที่นานขึ้นอย่างมากและคอขวดของฮาร์ดแวร์ที่รุนแรง [4, 5, 6]

ด้วย AI-QEM คุณสามารถรัน quantum circuit บน QPU ที่มี noise และได้ expectation value ที่ดีขึ้นเมื่อเทียบกับเทคนิคลดข้อผิดพลาดแบบ AI อื่นๆ โดยไม่มี overhead เวลารัน QPU เพิ่มเติม แนวทางนี้ใช้ deep neural network ที่มีสถาปัตยกรรม graph convolutional network (GCN)-Transformer เครือข่ายนี้ถูกฝึกด้วย feature ที่รวมโครงสร้างของ circuit, topology ของ backend, observable แบบ Pauli และการ calibrate ของ qubit และทำนายตัวประกอบแก้ไข แทนด้วย ζ\zetaζ การหาร expectation value ที่มี noise ด้วย ζ\zetaζ จะได้ expectation value ที่ดีขึ้น การทดลองแสดงว่า AI-QEM ให้ผลลัพธ์ดีกว่าวิธีลดข้อผิดพลาดแบบ AI อื่นๆ โดยเฉพาะกับ circuit ที่มี depth (จำนวนชั้นของ gate) และ width (จำนวน qubit) มาก ทำให้เหมาะกับการทดลองควอนตัมระดับ utility ตารางในส่วนBenchmarks แสดงว่าโมเดลที่ใช้ GCN-Transformer เหนือกว่าโมเดลที่ใช้ random forest (RF) ในช่วง 80 ถึง 150 qubit โดยมี mean absolute error (MAE) เท่ากับ 0.343 MAE คือค่าเฉลี่ย ของผลต่างสัมบูรณ์ระหว่าง expectation value ในอุดมคติกับ expectation value หลังจากโมเดลลดข้อผิดพลาดของผลลัพธ์ฮาร์ดแวร์ที่มี noise โดยเฉลี่ยจากการกำหนดค่า circuit และ observable จำนวนมาก นอกจากนี้ เนื่องจากโมเดลไม่ขึ้นกับ circuit คุณจึงใช้กับ quantum circuit และงานประยุกต์ได้หลากหลายโดยไม่ต้องปรับแต่งเฉพาะ circuit

สำหรับคำอธิบายฉบับเต็มของส่วนประกอบพื้นฐานและการสาธิตระดับ utility ดูบทความ AI-QEM [1]

คำอธิบาย​

ใช้ LTM AI-QEM function เพื่อประมาณ expectation value ของ observable สำหรับ quantum circuit ที่กำหนด หากต้องการใช้ LTM AI-QEM ให้ระบุ quantum circuit ชุดของ observable ที่จะวัด และ QPU function ใช้เวลา QPU เท่ากับ IBM Quantum Estimator primitive และไม่ใช้เวลา QPU เพิ่มเติม

วิธีปกติในการคำนวณ expectation value ของ observable OOO คือแยก observable เป็นผลรวมของ Pauli operator, O=∑iciPiO=\sum_i{c_i}{P_i}O=∑i​ci​Pi​ แล้วคำนวณ expectation value ของแต่ละ Pauli operator, ⟨Pi⟩\langle P_i \rangle⟨Pi​⟩ แยกกัน จากนั้น expectation value ของ observable, ⟨O⟩\langle O \rangle⟨O⟩ ก็คือผลรวมเชิงเส้นแบบเดียวกันของ expectation value ของ Pauli: ⟨O⟩=∑ici⟨Pi⟩{\langle O \rangle}=\sum_i{c_i}{\langle P_i \rangle}⟨O⟩=∑i​ci​⟨Pi​⟩ ถ้าชุดของ Pauli operator สลับที่กันได้ การวัดที่ต้องใช้คำนวณ expectation value ของพวกมันก็ทำพร้อมกันได้ เมื่อคุณรัน circuit ด้วย LTM AI-QEM function ตัว function ใช้ Estimator primitive เพื่อรัน circuit บนฮาร์ดแวร์ตามปกติ โดยทำตามขั้นตอนเดียวกันคือแยก observable เป็น Pauli operator และคำนวณ expectation value ของแต่ละตัวแยกกัน จากนั้น GCN-Transformer ซึ่งเป็นสถาปัตยกรรม deep learning จะทำนายตัวประกอบแก้ไข ζi\zeta_iζi​ สำหรับแต่ละ Pauli operator PiP_iPi​ function ใช้ตัวประกอบแก้ไขนี้เพื่อแก้ expectation value ที่มี noise ของแต่ละ Pauli operator: ⟨Pi⟩mitigated=⟨Pi⟩noisyζi{\langle P_i \rangle}_{mitigated} = \frac{{\langle P_i \rangle}_{noisy}}{\zeta_i}⟨Pi​⟩mitigated​=ζi​⟨Pi​⟩noisy​​ ดังนั้น expectation value ที่ลดข้อผิดพลาดแล้วคือ ⟨O⟩mitigated=∑ici⟨Pi⟩mitigated=∑ici⟨Pi⟩noisyζi{\langle O \rangle}_{mitigated} = \sum_i{c_i}{\langle {P_i} \rangle}_{mitigated} = \sum_i{c_i}{\frac{{\langle P_i \rangle}_{noisy}}{\zeta_i}}⟨O⟩mitigated​=∑i​ci​⟨Pi​⟩mitigated​=∑i​ci​ζi​⟨Pi​⟩noisy​​

workflow สำหรับการใช้ LTM AI-QEM function มีดังนี้:

  1. กำหนด circuit และ observable ของคุณ

  2. รัน LTM AI-QEM function โดยส่งคู่ของ circuit และ observable เป็น primitive unified bloc (PUB)

  3. ดึงผลลัพธ์ ซึ่งมี expectation value ของ observable เทียบกับ quantum circuit ที่สอดคล้องกันในแต่ละ PUB

ตัวอย่างทดสอบจำนวนมากแสดงให้เห็นเชิงประจักษ์ว่า LTM AI-QEM function ช่วยปรับปรุงการประมาณค่า observable function มีคุณสมบัติดังนี้:

  • การทดลองระดับ utility: ตัวอย่างทดสอบแสดงว่า AI-QEM ทำงานได้ดีกว่าวิธีแบบ AI อื่นๆ สำหรับ circuit ที่มี depth และ width มาก ดูผลลัพธ์ในส่วนBenchmarks

  • Primitive: function รองรับ Estimator primitive คุณจึงใช้คำนวณ expectation value ของ observable ใดๆ เทียบกับ quantum circuit ใดๆ ได้

  • Primitive unified bloc (PUB): LTM AI-QEM function รองรับ PUB ทุกประเภท (คือการกำหนดค่า circuit-observable ทุกแบบ) ที่ Estimator primitive รองรับ

เทคนิค AI-QEM เริ่มจากการสร้าง dataset ซึ่งสร้าง random quantum circuit ด้วยการตั้งค่าพารามิเตอร์ต่างๆ สำหรับแต่ละ circuit จะคำนวณทั้ง expectation value ในอุดมคติ (ได้จากการจำลอง) และ expectation value ที่มี noise (ได้จากการรันบนฮาร์ดแวร์) ผลลัพธ์เหล่านี้ พร้อมกับ quantum circuit ที่สอดคล้องกันและข้อมูล backend จะถูกเก็บไว้ใน dataset repository จากนั้นใช้ dataset ฝึกโมเดล machine learning หรือ deep learning ที่ลด noise ในการคำนวณควอนตัมได้ และบันทึกโมเดลที่ฝึกแล้วไว้ใช้ในอนาคต ระหว่างการ inference โมเดลที่ฝึกแล้วรับอินพุตเป็น quantum circuit, expectation value ที่มี noise ซึ่งคำนวณบนฮาร์ดแวร์, observable ที่เกี่ยวข้อง และข้อมูล backend จากนั้นโมเดลประมวลผลอินพุตเหล่านี้เพื่อให้ expectation value ที่ลด noise แล้ว

สำหรับ mirror circuit benchmark ใช้ ansatz RealAmplitudes, TwoLocal และ EfficientSU2 ที่มี 30, 35 และ 40 qubit ตามลำดับ observable ประกอบด้วย Pauli-ZZZ operator ตัวเดียวบน qubit ที่เลือกแบบสุ่ม โดยมี expectation value ในอุดมคติเป็น 1

สำหรับ Clifford circuit benchmark ใช้ circuit 50 และ 100 qubit โดย observable เริ่มต้นเป็น Pauli-ZZZ operator หนึ่งตัวหรือมากกว่าที่วางตำแหน่งแบบสุ่ม การวิวัฒน์ของ operator เพิ่ม Pauli weight ของ observable เหล่านี้ ซึ่งให้ observable ที่ซับซ้อนขึ้นสำหรับ benchmark observable ถูกสร้างให้มี expectation value ในอุดมคติเป็น 1 ซึ่งตรวจสอบอิสระด้วยการจำลอง stabilizer

สำหรับการจำลอง Hamiltonian ของ Ising แบบ tilted-field 2 มิติที่ทำ Trotter (TFI) benchmark ใช้พารามิเตอร์สามช่วง ได้แก่ มุมเล็ก (θX,θZ,θZZ)=(0.1,0.1,0.1)(\theta_X,\theta_Z,\theta_{ZZ})=(0.1,0.1,0.1)(θX​,θZ​,θZZ​)=(0.1,0.1,0.1) ใกล้ Clifford (0.1,0.05,1.5708)(0.1,0.05,1.5708)(0.1,0.05,1.5708) และ chaotic (0.53,0.1,1.0)(0.53,0.1,1.0)(0.53,0.1,1.0) observable คือค่าเฉลี่ยของ magnetization

OM=1M∑iZi,O_M = \frac{1}{M}\sum_i Z_i,OM​=M1​i∑​Zi​,

โดยที่ MMM คือจำนวน qubit ในการจำลอง expectation value ในอุดมคติคำนวณด้วย sparse Pauli dynamics (SPD) ซึ่งเป็นวิธี Pauli propagation และตรวจสอบกับการจำลอง Qiskit statevector สำหรับ circuit ที่มีน้อยกว่า 29 qubit

ทีมสนับสนุน AI-QEM ยินดีรับข้อเสนอแนะและคำขอฟีเจอร์ด้วย หากคุณมีข้อเสนอแนะเพื่อการปรับปรุงหรือความสามารถที่ต้องการเห็นในรุ่นถัดไป ส่งมาได้ที่ quantumfunction.support@ltm.com
