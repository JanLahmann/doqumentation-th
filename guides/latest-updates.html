    • คำนวณ classical expression กลางวงจรและบันทึกผลลัพธ์ไปยังตัวแปรหรือ register ซึ่งสามารถควบคุม quantum gate ที่ตามมาได้ทันที แทนที่จะใช้ inline expression ที่ซ้อนกันลึก คุณสามารถแบ่งการคำนวณออกเป็นขั้นตอนกลางที่มีชื่อ เพื่อให้ classical feedback logic ที่ซับซ้อนอ่านและดูแลรักษาได้ง่ายขึ้น Use case ทั่วไป ได้แก่:

      • Dynamic circuit ที่มีการวัดกลางวงจรและ classical feedback
      • การเตรียม entanglement ระยะไกล

      โปรดทราบว่าก่อนส่งงาน คุณควรตรวจสอบความเข้ากันได้กับ option ของแต่ละ primitive ในเอกสาร: Sampler options | Estimator options | Executor options

Nighthawk มาถึง EU​

Premium และ Flex Plans ตอนนี้มีการเข้าถึงล่วงหน้าสู่ ibm_berlin! เป็น IBM Quantum Nighthawk r1 QPU ตัวแรกใน EU (ภูมิภาค eu-de) และเป็น Nighthawk ตัวที่สองใน global fleet ของเรา รองจาก ibm_miami ในสหรัฐฯ (ภูมิภาค us-east) ibm_berlin มี two-qubit gate ที่เร็วกว่า ibm_miami (68 ns เทียบกับ 138 ns ค่ามัธยฐาน) ในขณะที่ยังคง coherence นำ fleet ที่ใกล้เคียงกัน (T1_11​ ประมาณ ~350 µs)

นับตั้งแต่การ release Nighthawk ได้เปิดใช้งานการวิจัยในระบอบที่การ simulation แบบ classical มีความท้าทายมากขึ้นเรื่อยๆ โดยเฉพาะสถาปัตยกรรมของมันรองรับ workflow ที่มีประสิทธิภาพด้านฮาร์ดแวร์ที่ map ได้อย่างเป็นธรรมชาติบน model แบบ grid (lattice) ดูผลงานล่าสุดจาก Phasecraft และ Volkswagen และผู้ร่วมงานของพวกเขา ที่แสดงให้เห็น simulation ในระดับขนาดบน Nighthawk

โปรดทราบว่า ibm_berlin ปัจจุบันเป็น QPU เชิงสำรวจที่ยังคงได้รับการทดสอบและปรับแต่งเป็นส่วนหนึ่งของวงจรการเรียนรู้อย่างต่อเนื่องของเรา ดังนั้น จึงมีข้อจำกัดชั่วคราวต่อไปนี้:

  • เวลาทำซ้ำเริ่มต้นได้รับการเพิ่มชั่วคราวจาก 250 µs เป็น 4 ms ซึ่งส่งผลต่อเวลา QPU ที่จำเป็นในการรัน workload ผู้ใช้สามารถเลือก repetition time ที่สั้นกว่าด้วยตนเอง แต่ประสิทธิภาพอาจลดลง
  • Dynamic circuit ยังไม่รองรับ และคุณภาพของการวัดกลางวงจรยังมีข้อจำกัด

การเลิกใช้งานที่กำลังจะมาถึง​

เมื่อเราขยายความจุ EU และ rollout processor Nighthawk และ Heron ล่าสุด ibm_brussels และ ibm_strasbourg มีกำหนดการเลิกใช้งานในหรือราววันที่ 30 เมษายน 2026

เมื่อ QPU เหล่านี้ถูกเลิกใช้งาน จะไม่รับงานอีกต่อไป หาก workflow ของคุณมุ่งเป้าที่ ibm_brussels หรือ ibm_strasbourg โปรด migrate ไปยัง QPU ที่ใช้งานอยู่อื่นก่อนวันที่เลิกใช้งานเพื่อใช้ประโยชน์จากระบบล่าสุด สำหรับคำแนะนำในการดึงข้อมูลจากงานที่ผ่านมา ดู เอกสาร

ibm_torino ถูกเลิกใช้งานแล้ว​

คอมพิวเตอร์ควอนตัม ibm_torino ถูกเลิกใช้งานแล้วและจะไม่รับการส่ง workload อีกต่อไป workload ที่อยู่ใน queue บน QPU นี้อาจยังคงได้รับการประมวลผลและส่งคืนผลลัพธ์

หากต้องการดึงข้อมูลงานจาก workload สำคัญที่รันบน QPU นี้ ดู คำแนะนำเหล่านี้

ibm_brussels และ ibm_strasbourg ถูกเลิกใช้งานแล้ว​

ibm_brussels และ ibm_strasbourg ถูกเลิกใช้งานแล้วและจะไม่รับงานอีกต่อไป

การเปลี่ยนแปลงนี้เป็นส่วนหนึ่งของวิวัฒนาการและการขยายตัวอย่างต่อเนื่องของ IBM Quantum fleet ใน EU รวมถึง Nighthawk QPU ibm_berlin ที่เพิ่งออกใหม่ และ Heron r3 QPU ที่อัปเกรดแล้ว ibm_aachen ตอนนี้ global fleet ได้ transition เสร็จสมบูรณ์จาก Eagle ซึ่งเป็น processor family ระดับ utility ตัวแรกของ IBM Quantum ที่เปิดตัวในปี 2021

หาก workflow ของคุณมุ่งเป้าที่ ibm_brussels หรือ ibm_strasbourg โปรด migrate ไปยัง QPU ที่ใช้งานอยู่อื่นเพื่อใช้ประโยชน์จาก hardware ล่าสุด สำหรับคำแนะนำในการดึงข้อมูลจากงานที่ผ่านมา ดู เอกสาร

มีนาคม 2026​

EU ได้รับ Heron r3 ตัวแรก​

การบำรุงรักษาบน ibm_aachen เสร็จสมบูรณ์แล้วและ QPU กลับออนไลน์ในภูมิภาค eu-de แล้ว ibm_aachen ยังได้รับการอัปเกรดเป็น QPU ตัวแรกใน EU ที่มีประสิทธิภาพด้วย processor Heron r3 ล่าสุด เป็น r3 ตัวที่สามใน global fleet ของเรา รองจาก ibm_boston และ ibm_pittsburgh ในสหรัฐฯ

Heron r3 ยังคงส่งมอบ error rate ที่ดีขึ้นและประสิทธิภาพระบบโดยรวมที่เหนือกว่า Heron r2 แสดงให้เห็นการ execute ที่น่าเชื่อถือมากขึ้นและผลลัพธ์ที่ดีกว่าสำหรับ workload ตัวอย่างเช่น บน ibm_aachen เราสังเกตเห็นการเพิ่มขึ้นอย่างมากของ T2T_2T2​ (phase coherence time) จาก 150 µs เป็น 250 µs คุณสามารถดู metric เหล่านี้สำหรับ QPU ทั้งหมดใน shared fleet บนหน้า Compute resources

กุมภาพันธ์ 2026​

ibm_torino จะเลิกใช้งาน​

QPU ibm_torino จะเลิกใช้งานในหรือราว 1 เมษายน 2026 เมื่อ QPU นี้ถูกเลิกใช้งาน จะไม่รับงานอีกต่อไป

หากต้องการดึงข้อมูลงานจากงานสำคัญที่ผ่านมา โปรดดู เอกสาร

การเพิ่ม repetition delay time สูงสุด​

เพื่อให้ผู้ใช้มีความยืดหยุ่นมากขึ้น เราได้ขยายช่วง repetition delay time ที่อนุญาตจาก 20-500 µs เป็น 20-2000 µs บน Heron และ Eagle QPU ของเรา ช่วง delay time ของ Nighthawk QPU ยังคงเป็น 1000-4000 µs ตามที่ประกาศไว้ก่อนหน้า โปรดทราบว่าหากเลือกเพิ่ม repetition delay (rep_delay) จะส่งผลโดยตรงต่อเวลาการ execute และการใช้ capacity แต่อาจปรับปรุง fidelity ของ circuit บางประเภทได้ ค่าเริ่มต้น rep_delay ยังคงไม่เปลี่ยนแปลงบน QPU ทุกตัว

คุณสามารถหาข้อมูลเพิ่มเติมเกี่ยวกับ repetition delay time รวมถึงวิธีการเปลี่ยนแปลงใน Qubit initialization

  • ต่อเนื่องจากโมเมนตัมที่สร้างขึ้นตลอด v2.x series ซึ่งมุ่งเน้นการวาง Qiskit เป็น platform นำสำหรับ hybrid quantum-HPC workflow Qiskit SDK v2.3 มอบการขยาย C API อย่างมีนัยสำคัญพร้อมกับเครื่องมือที่เร็วและยืดหยุ่นกว่าสำหรับการสร้างและปรับ quantum circuit ให้เหมาะสม

    การอัปเดตหลักได้แก่:

    • Custom transpiler pass ใน C - เขียน custom transpiler pass ผ่าน C API ของ Qiskit โดยใช้ object QkDag ใหม่และ object QkTarget ที่ขยายแล้ว ซึ่งช่วยให้ตรวจสอบ แก้ไข และขยายกระบวนการ compilation ได้ทีละขั้นตอน โดยไม่ต้อง rebuild pipeline ของ compiler ทั้งหมด

    • การเลือก hardware layout ที่เร็วขึ้น - การอัปเกรดและการปรับปรุงประสิทธิภาพที่ขับเคลื่อนด้วย Rust สำหรับ VF2Layout และ VF2PostLayout ปรับปรุงความเร็วและความสามารถในการขยายขนาดของการเลือก layout circuit-ต่อ-hardware ลด compilation overhead และปรับปรุง fidelity บน quantum hardware

    • PauliProductMeasurement แบบ multi-qubit ใหม่ - คำสั่ง PauliProductMeasurement ใหม่ช่วยให้การวัดแบบ joint projective ข้าม Qubit หลายตัวในการดำเนินการเดียว ปลดล็อกการ compile ไปยัง Pauli-based computation ซึ่งเป็นการแสดงแทนทั่วไปในการคำนวณควอนตัมแบบ fault-tolerant

    • การปรับปรุงใน early fault-tolerant transpile - การปรับปรุงประสิทธิภาพและฟีเจอร์สำหรับการ transpile ไปยัง early fault-tolerant target โดยเฉพาะ target Clifford+T ช่วยให้ผู้ใช้สร้าง transpile pipeline สำหรับ QPU ในอนาคตได้อย่างมีประสิทธิภาพมากขึ้น

    ความสามารถเหล่านี้ให้ความยืดหยุ่นมากขึ้นแก่นักพัฒนาในการปรับแต่ง quantum circuit optimization และรวมเข้ากับ HPC workflow ที่มีอยู่ เยี่ยมชม blog สำหรับสรุปทางเทคนิคเต็มรูปแบบ

    • Application function ครอบคลุมงานระดับสูงกว่า เช่น การสำรวจ algorithm และ use case เฉพาะโดเมน นักพัฒนาองค์กรและนักวิทยาศาสตร์ข้อมูลอาจไม่มีความรู้พื้นฐาน quantum information science สำหรับทำงานกับ circuit แต่ต้องการนำความรู้ด้านโดเมนของตนมาพัฒนา quantum computing algorithm และแอปพลิเคชัน ด้วย application function ผู้ใช้สามารถป้อน classical input และรับคำตอบเพื่อให้ทดลองนำ quantum เข้าสู่ workflow เฉพาะโดเมนของตนได้ง่ายขึ้น

  • ด้วยการเปิดตัว Qiskit Functions Catalog นักพัฒนา Premium Plan สามารถสำรวจ IBM Circuit function ได้ IBM Circuit function รวม AI-powered extension ล่าสุดสำหรับ Qiskit สำหรับการสังเคราะห์ การปรับให้เหมาะสม และการจัดตาราง circuit รวมถึง advanced error mitigation method เพื่อส่งคืนค่าประมาณที่แม่นยำที่สุดที่เป็นไปได้ด้วย hardware ปัจจุบัน

    ผู้ใช้สามารถซื้อใบอนุญาตสำหรับฟังก์ชันต่อไปนี้ที่ contributed โดยพันธมิตรของเราที่ Q-CTRL, QEDMA และ Algorithmiq

  • Circuit function

    • Q-CTRL กำลัง release circuit function ที่ใช้เทคนิค AI-driven quantum control ซึ่งผู้ใช้สามารถขยายขนาดไปยังปัญหาที่ใหญ่ขึ้นได้สำเร็จ
    • Algorithmiq กำลัง release circuit function ที่ใช้ TEM (tensor-network error mitigation) ซึ่งเป็น error mitigation method สำหรับรับ estimator ด้วย shot ที่น้อยกว่าวิธี PEC (probabilistic error cancellation)
    • QEDMA กำลัง release circuit function ที่ใช้ protocol เฉพาะสำหรับการ characterize QPU operation ที่มี noise อย่างมีประสิทธิภาพและแม่นยำ และใช้ error suppression และ error mitigation ตาม characterization data

  • Application function

    • Q-CTRL กำลัง release optimization solver ที่ผู้ใช้สามารถส่ง graph หรือ objective และรับ solution cost
