IBM Quantum Compute Service

ค้นหาสรุปการเผยแพร่แพ็กเกจล่าสุดและการอัปเดตแพลตฟอร์มจาก IBM Quantum® Compute Service ได้ในหน้านี้

กันยายน 2026​

  • QPU Nighthawk r2 ตัวแรกพร้อมใช้งานแล้ว — Premium, Flex และ Pay-As-You-Go Plans ตอนนี้สามารถเข้าถึง ibm_phoenix ซึ่งเป็น IBM Quantum Nighthawk r2 QPU ตัวแรกและเป็นโปรเซสเซอร์ที่เร็วที่สุดของเราจนถึงตอนนี้ ibm_phoenix เป็นอุปกรณ์ 120-programmable-qubit แบบ square-lattice ที่มีการเชื่อมต่อสูง ซึ่งให้ throughput สูงกว่า Heron ถึง 25 เท่า ในขณะที่ยังคงความเที่ยงตรงเทียบเท่ากัน

    ผลลัพธ์นี้มาจากการรีเซ็ตความเร็วสูงแบบอิสระที่เพิ่งเปิดตัวใหม่ ซึ่งทำให้ programmable qubit ทุกตัวกลับสู่สถานะพื้นได้เร็วขึ้นและสมบูรณ์ยิ่งขึ้น ผลก็คือ repetition delay เริ่มต้นอยู่ที่ 1 µs (จากเดิม 250 µs) ซึ่งดัน throughput ให้สูงกว่า 100,000 Max Circuits Per Second (MCPS) หากต้องการทราบข้อมูลเพิ่มเติมเกี่ยวกับวิธีที่ IBM ติดตามประสิทธิภาพฮาร์ดแวร์ quantum ในมิติของขนาด คุณภาพ และความเร็ว โปรดดูบล็อกนี้

    ความเร็วและการเชื่อมต่อที่เพิ่มขึ้นทำให้สามารถทำงานที่ใช้ประโยชน์ได้มากขึ้นจากความจุเท่าเดิม โดยเวิร์กโหลดที่ใหญ่และหนักที่สุดจะได้ประโยชน์มากที่สุด การทดลองขนาดใหญ่ขึ้น การกวาดพารามิเตอร์ที่กว้างขึ้น และวิธีการที่เคยมีต้นทุนสูงเกินไปในระดับใหญ่ ตอนนี้สามารถรันได้เป็นประจำ

    ibm_phoenix ยังถูกสร้างขึ้นสำหรับยุคถัดไปของงานวิจัย quantum error correction นอกเหนือจากการรีเซ็ตความเร็วสูงแล้ว ยังรองรับ mid-circuit reset และ dynamic circuit สำหรับการควบคุม error correction แบบเรียลไทม์

สิงหาคม 2026​

  • การอัปเดต IBM Quantum Platform — การอัปเดตล่าสุดของ IBM Quantum Platform ทำให้เข้าใจผลลัพธ์งานของคุณได้ง่ายขึ้น ปลดล็อกความสามารถการออกแบบ circuit ใหม่ที่ทรงพลังใน Composer และแจ้งให้คุณทราบเกี่ยวกับขีดจำกัดการใช้งานของคุณอยู่เสมอ — เพื่อให้คุณสามารถมุ่งเน้นไปที่งาน quantum ของคุณได้มากขึ้น

    • ผลลัพธ์งานและเวิร์กโหลด

      • มุมมองผลลัพธ์แบบบิตต่อบิต — วิธีใหม่ในการดูผลลัพธ์การวัดของ Sampler โดยแยกผลลัพธ์ทีละบิตแทนที่จะแยกตามสถานะแบบเต็ม มีประโยชน์เป็นทางเลือกแทนมุมมองผลลัพธ์การวัดเมื่อผลลัพธ์มีสถานะที่แตกต่างกันจำนวนมาก

      • แผนภูมิเวลาของ circuit — แสดงไทม์ไลน์ที่จัดตารางไว้ของการดำเนินการต่างๆ ของ circuit (gate, channel, ระยะเวลา) พร้อมใช้งานสำหรับงาน Sampler และ Executor ต้องมีการเปิดใช้งานการดึงข้อมูลเวลา

      • แผงวินิจฉัยการทำงานระดับ Chunk/span — แผงใหม่บนหน้ารายละเอียดของงานที่แสดงข้อมูลวินิจฉัยการทำงานระดับ chunk และ span ดู Sampler input/output เพื่อทำความเข้าใจความหมายของข้อมูลนี้และวิธีเปิดใช้งานเมื่อส่งงาน

      • ข้อมูลการปรับเทียบอุปกรณ์แบบเห็นได้ทันที — หน้ารายละเอียดของงานตอนนี้แสดงข้อมูลการปรับเทียบอุปกรณ์ ณ เวลาที่ส่งหรือรันงาน ผ่านลิงก์ "View calibration history"

      • การแสดงผลลัพธ์ Executor — หน้ารายละเอียดของงานตอนนี้แสดงผลลัพธ์สำหรับงาน Executor ดูรายละเอียดเพิ่มเติมเกี่ยวกับ Executor ได้ที่คู่มือ Directed execution model (beta)

      • Dynamic circuits ตอนนี้แสดงผลบนหน้ารายละเอียดงานแล้ว — ด้วยการรองรับ OpenQASM 3.0 ใน Composer (ดูรายละเอียดเพิ่มเติมด้านล่าง) วงจรที่เคยแสดงผลไม่ได้ (เช่น วงจรที่ใช้ dynamic circuits) ตอนนี้จะแสดงผลได้อย่างถูกต้องบนหน้ารายละเอียดงาน

      • การปรับปรุงฮิสโตแกรม — โหลดเร็วขึ้น การซูมเข้า/ออกที่ลื่นไหลขึ้น และเครื่องมือเลือกช่วงใหม่สำหรับการโฟกัสในช่วงผลลัพธ์ที่ต้องการ

      • โค้ดสนิปเป็ต qiskit-ibm-runtime ในผลลัพธ์ของงาน — โค้ดพร้อมใช้สำหรับดึงงานตาม ID สำหรับงาน Executor มีสนิปเป็ตเพิ่มเติมที่ช่วยให้คุณทำซ้ำงานนั้นได้

      • ตัวกรองช่วงวันที่แบบกำหนดเอง เพิ่มเข้ามาในตารางเวิร์กโหลด

      • ชื่ออินสแตนซ์และแท็กที่คลิกได้ ในหน้ารายละเอียดเวิร์กโหลด ซึ่งลิงก์ไปยังทรัพยากรที่เกี่ยวข้อง

      ไปที่หน้า Workloads เพื่อดูการปรับปรุงเหล่านี้

    • Composer: รองรับ OpenQASM v3.0

      ตอนนี้ Composer รองรับ OpenQASM v3.0 แล้ว โดยเพิ่ม:

      • ตัวปรับแต่ง Gate — ctrl, inv, pow เป็นต้น

      • ลูป — for และ while

      • ตรรกะเงื่อนไข — if/else

      • คำอธิบายกล่อง (Box annotations) — จัดกลุ่มและติดป้ายกำกับส่วนต่าง ๆ ของ Circuit

      รวมถึง: การแสดงผลที่ลื่นไหลขึ้นสำหรับ Circuit ขนาดใหญ่ และการแก้ไขปัญหาการส่งออก PNG ล้มเหลวสำหรับ Circuit ขนาดใหญ่

    ไปที่ Composer เพื่อสำรวจการอัปเดตใหม่นี้

    • ขีดจำกัดการใช้งานอินสแตนซ์

      • อินสแตนซ์ระดับ Premium และ Open Plan ที่ถึงขีดจำกัดการใช้งานแล้ว ตอนนี้จะแสดงวันที่แน่ชัดที่การเข้าถึงจะกลับมาใช้งานได้ โดยอิงตามช่วงเวลาการใช้งานแบบหมุนเวียน

    ดูข้อมูลเพิ่มเติมได้ที่หน้า Instances

กรกฎาคม 2026​

การเปลี่ยนชื่อ Qiskit Runtime​

  • Qiskit Runtime service ตอนนี้คือ IBM Quantum Compute Service — นี่เป็นเพียงการเปลี่ยนชื่อเท่านั้น ไม่จำเป็นต้องเปลี่ยนแปลงโค้ดหรืออัปเดตแอปพลิเคชันที่มีอยู่ คุณอาจสังเกตเห็นชื่อใหม่นี้ในส่วนติดต่อผู้ใช้และเอกสารประกอบ

    ในอดีต คำว่า Qiskit Runtime ถูกใช้เพื่ออ้างถึงแนวคิดที่เกี่ยวข้องกันแต่แตกต่างกันสามอย่าง

    ผู้ให้บริการฮาร์ดแวร์รายใดก็ตามที่ต้องการให้ผู้ใช้ Qiskit รันเวิร์กโหลดบนคอมพิวเตอร์ควอนตัมของตน จะต้องจัดเตรียมส่วนประกอบเฉพาะของผู้ให้บริการสองส่วน:

    • ส่วนขยาย Qiskit SDK ซึ่งช่วยให้ผู้ใช้ส่งงานไปยังผู้ให้บริการได้ ในกรณีของ IBM คือไลบรารีโอเพนซอร์ส qiskit-ibm-runtime แทนที่จะสื่อสารกับคอมพิวเตอร์ควอนตัมโดยตรง มันจะส่งงานไปยัง cloud API

    • สภาพแวดล้อมการรันไทม์ (runtime execution environment) ซึ่งทำงานอยู่บนคอมพิวเตอร์ควอนตัมเอง ส่วนประกอบนี้เข้าใจ Qiskit primitives แปลงเป็นการทำงานเฉพาะฮาร์ดแวร์ และรันบนฮาร์ดแวร์ควอนตัม ในกรณีของ IBM คือ IBM Qiskit Runtime

    ระหว่างสององค์ประกอบนี้คือองค์ประกอบที่สาม: บริการคลาวด์ที่มีการจัดการซึ่งรับงานจาก SDK qiskit-ibm-runtime และประสานงานการรันงานเหล่านั้น บริการนี้รับผิดชอบความสามารถต่าง ๆ เช่น การยืนยันตัวตน การจัดตารางเวลา การจัดการคิว การกำหนดเส้นทางเวิร์กโหลด การติดตามการใช้งาน ขีดจำกัด และการวิเคราะห์ข้อมูล มันไม่ได้ประมวลผล Qiskit primitives เอง แต่จะส่งเวิร์กโหลดไปยังคอมพิวเตอร์ควอนตัมที่เหมาะสม ซึ่งสภาพแวดล้อมการรันไทม์จะทำการรันจริง

    ในอดีต บริการคลาวด์นี้ก็ถูกเรียกว่า Qiskit Runtime Service เช่นกัน แม้ว่าในทางแนวคิดจะแตกต่างจากตัวรันไทม์เอง การใช้คำว่า Qiskit Runtime ในสองความหมาย — เพื่ออธิบายทั้งสภาพแวดล้อมการรันไทม์และบริการคลาวด์ที่มีการจัดการ — ทำให้สถาปัตยกรรมไม่ชัดเจนและยากที่จะแยกแยะส่วนประกอบโอเพนซอร์สออกจากบริการคลาวด์ที่มีการจัดการ

    การเปลี่ยนชื่อ Qiskit Runtime Service เป็น IBM Quantum Compute Service ช่วยแก้ไขความคลุมเครือนี้ สถาปัตยกรรมที่ได้จะชัดเจนขึ้นมาก:

    • qiskit-ibm-runtime: ส่วนขยาย Qiskit โอเพนซอร์สที่ส่งเวิร์กโหลด

    • IBM Quantum Compute Service: บริการคลาวด์ที่มีการจัดการซึ่งยืนยันตัวตน จัดตารางเวลา จัดการ และกำหนดเส้นทางเวิร์กโหลด

    • IBM Qiskit Runtime (หรือ IBM Qiskit Runtime Execution Environment): สภาพแวดล้อมการรันไทม์ที่ทำงานบนคอมพิวเตอร์ควอนตัมซึ่งประมวลผลและรัน Qiskit primitives

พฤษภาคม 2026​

คำสั่ง Store​

  • รองรับคำสั่ง Store บน IBM® QPU - ตอนนี้คุณสามารถลดความซับซ้อนของการคำนวณแบบคลาสสิกใน Circuit ควอนตัมของคุณด้วยคำสั่ง Store

    • คำนวณนิพจน์คลาสสิกกลาง Circuit และบันทึกผลลัพธ์ลงในตัวแปรหรือรีจิสเตอร์ ซึ่งสามารถควบคุม Gate ควอนตัมถัดไปได้ทันที แทนที่จะเป็นนิพจน์แบบซ้อนกันลึก ๆ คุณสามารถแบ่งการคำนวณออกเป็นขั้นตอนกลางที่มีชื่อ ทำให้ตรรกะการป้อนกลับแบบคลาสสิกที่ซับซ้อนอ่านและดูแลรักษาง่ายขึ้น กรณีการใช้งานทั่วไป ได้แก่:

      • Dynamic circuits ที่มีการวัดกลาง Circuit และการป้อนกลับแบบคลาสสิก

      • การเตรียมการพัวพัน (entanglement) ระยะไกล

      • ตรรกะเงื่อนไขที่ซับซ้อนโดยอิงจากผลการวัด

      หากต้องการใช้คำสั่ง store ก่อนอื่นให้ตรวจสอบว่าคุณกำลังใช้ qiskit-ibm-runtime เวอร์ชันล่าสุด (pip install --upgrade qiskit-ibm-runtime) จากนั้นดูเอกสารประกอบ เพื่อดูข้อมูลเพิ่มเติมและตัวอย่าง

      โปรดทราบว่าก่อนส่งงาน คุณควรตรวจสอบความเข้ากันได้กับตัวเลือกของแต่ละ primitive ในเอกสารประกอบ: Sampler options | Estimator options | Executor options

เมษายน 2026​

บัญชีสำหรับห้องเรียน​

  • บัญชีสำหรับห้องเรียนใหม่: ตอนนี้อาจารย์สามารถขอบัญชีสำหรับห้องเรียน เพื่อจัดการและอำนวยความสะดวกในการเข้าถึงให้กับนักเรียนของตนได้ ด้วยบัญชีสำหรับห้องเรียน นักเรียนสามารถใช้ทรัพยากรของ Open Plan ได้โดยไม่ต้องให้ข้อมูลบัตรเครดิตส่วนตัว

    • ตัวเลือกการส่งออกใหม่ที่มีให้ใช้งานใน IBM Quantum แล้ว: แนะนำความสามารถในการส่งออกใหม่ที่ทำให้ผู้ดูแลระบบบัญชีวิเคราะห์ แชร์ และทำงานกับข้อมูลของตนได้ง่ายขึ้น

      • ใหม่ในหน้า Analytics:

        • ตอนนี้คุณสามารถส่งออกแผนภูมิในรูปแบบ SVG หรือ PNG ได้แล้ว

        • คุณสามารถส่งออกข้อมูล analytics ทั้งหมด รวมถึงข้อมูลเบื้องหลังแผนภูมิ เป็น CSV ได้

        ค้นหาเมนูส่งออกได้ที่มุมขวาบนของการ์ดแต่ละอันในหน้านี้

      • ใหม่ในหน้า Access management:

        • ส่งออกทั้งตาราง Users และตาราง Access Groups ในรูปแบบ CSV

    โปรดทราบว่า ibm_berlin ในขณะนี้เป็น QPU เชิงสำรวจที่ยังอยู่ระหว่างการทดสอบและปรับให้เหมาะสมเป็นส่วนหนึ่งของวงจรการเรียนรู้อย่างต่อเนื่องของเรา ด้วยเหตุนี้ จึงมีข้อจำกัดชั่วคราวดังต่อไปนี้:

    • เวลาการทำซ้ำ (repetition time) เริ่มต้นถูกเพิ่มขึ้นชั่วคราวจาก 250 µs เป็น 4 ms ซึ่งส่งผลต่อเวลา QPU ที่จำเป็นในการรันเวิร์กโหลด ผู้ใช้สามารถเลือก repetition time ที่สั้นลงได้ด้วยตนเอง แต่ประสิทธิภาพอาจลดลง

การเพิ่มค่าสูงสุดของเวลาหน่วงการทำซ้ำ​

เพื่อให้ความยืดหยุ่นมากขึ้นแก่ผู้ใช้ เราได้ขยายช่วงเวลาหน่วงการทำซ้ำ (repetition delay time) ที่อนุญาตจาก 20-500 µs เป็น 20-2000 µs บน QPU Heron และ Eagle ของเรา ช่วงเวลาหน่วงของ Nighthawk QPU ยังคงอยู่ที่ 1000-4000 µs ตามที่ประกาศไว้ก่อนหน้านี้ โปรดทราบว่าหากคุณเลือกที่จะเพิ่ม repetition delay (rep_delay) มันจะส่งผลโดยตรงต่อเวลารันและการใช้ทรัพยากรของคุณ แต่ก็อาจช่วยปรับปรุง fidelity ของ Circuit บางประเภทได้ rep_delay ค่าเริ่มต้นยังคงไม่เปลี่ยนแปลงในทุก QPU

คุณสามารถดูข้อมูลเพิ่มเติมเกี่ยวกับเวลาหน่วงการทำซ้ำ รวมถึงวิธีเปลี่ยนแปลง ได้ที่ Qubit initialization

  • สำหรับรายละเอียดทั้งหมดเกี่ยวกับการเปิดตัวเข้าถึงล่วงหน้าและการปรับปรุงที่กำลังจะมาถึง ดูบล็อกนี้

24 กุมภาพันธ์ 2025​

คลังสินค้าของเรากำลังจะมีการปรับปรุงใหม่ และเราจะปลดระวาง QPU ต่อไปนี้ในหรือประมาณวันที่ 18 เมษายน 2025:

  • ibm_kyiv

  • ibm_sherbrooke อัปเดต: ibm_sherbrooke จะยังคงใช้งานได้ต่ออีกหลายสัปดาห์หลังวันที่ 18 เมษายน 2025

โปรดดึงข้อมูลงานจากงานสำคัญในอดีตก่อนที่ QPU เหล่านี้จะปลดระวาง

3 กุมภาพันธ์ 2025​

  • การควบคุมระดับ Pulse บนโปรเซสเซอร์ IBM Quantum ทั้งหมดถูกลบออกแล้ว นอกจากนี้ โมดูล Pulse มีกำหนดถูกลบออกใน Qiskit SDK v2.0 แทนที่ คุณสามารถใช้ fractional gate ซึ่งตอนนี้ถูกสร้างไว้ใน Instruction Set Architecture (ISA) แล้ว สำหรับรายละเอียดทั้งหมดและความช่วยเหลือในการย้ายโค้ดของคุณ โปรดดูMigrate from Qiskit Pulse to fractional gates

2 กุมภาพันธ์ 2025​

  • เริ่มตั้งแต่วันที่ 2 มิถุนายน 2025 และต่อเนื่องตลอดทั้งปี IBM Quantum จะเริ่มทยอยเปิดตัวฟีเจอร์ใหม่สำหรับdynamic circuitที่จะช่วยให้ใช้งานได้ในระดับ utility scale การปรับปรุงประกอบด้วย:

    • ความเร็วในการรันเพิ่มขึ้น 75 เท่า ด้วยการใช้ Gen3 engine stack

    • การรัน branch แบบขนาน ซึ่งช่วยลดระยะเวลาของ Circuit และเพิ่มคุณภาพของผลลัพธ์

    • การปรับปรุงในการวัดค่ากลาง Circuit (mid-circuit measurement)

    • การผสานรวมที่ดีขึ้นกับ dynamical decoupling

    • การมองเห็นข้อมูลจังหวะเวลาของ Circuit ที่มากขึ้น

  • เพื่อเร่งการเปิดตัว ความสามารถต่อไปนี้จะถูก deprecate และจะไม่ได้รับการรองรับอีกต่อไปในหรือประมาณวันที่ 2 มิถุนายน 2025:

    • โครงสร้าง control flow แบบ while, for, และ switch

    • ความสามารถในการใช้คำสั่ง control flow ภายในเนื้อหาของ branch (นั่นคือ nested control flow)

    • การวัดผลแบบมีเงื่อนไข (Conditional measurements)

7 มกราคม 2025​

  • การเปิดตัว Gen3 engine stack เริ่มต้นวันนี้ engine stack นี้ให้ความเร็วเพิ่มขึ้น 75 เท่าในการรัน การเปิดตัวจะดำเนินการทีละ QPU โดยที่งานบางส่วนบน QPU จะใช้ Gen3 path คุณสามารถบังคับใช้ Gen3 path ได้โดยใช้ตัวเลือกทดลอง gen3-turbo โปรดทราบว่า engine stack นี้ไม่รองรับ fractional gates, pulse gates หรือ dynamic circuits

15 สิงหาคม 2024​

  • วิธีบรรเทาข้อผิดพลาดแบบ Probabilistic error amplification (PEA) พร้อมใช้งานแล้วสำหรับ Estimator V2 ดูรายละเอียดเพิ่มเติมได้ที่ ZneOptions API reference

  • โปรแกรมช่วยเหลือใหม่ noise-learner พร้อมใช้งานแล้ว ช่วยให้สามารถหาลักษณะกระบวนการ noise ที่ส่งผลต่อ gates ใน circuit หนึ่งตัวหรือมากกว่านั้นที่สนใจ โดยอิงตาม Pauli-Lindblad noise model โมเดล noise ที่ได้สามารถส่งไปยัง Estimator ผ่านตัวเลือก layer_noise_model

  • ไม่รองรับ V1 primitives อีกต่อไป

3 กรกฎาคม 2024​

  • endpoint ต่อไปนี้ถูก deprecate และจะถูกลบออกในหรือหลังวันที่ 3 ตุลาคม 2024: GET /stream/jobs และ GET /stream/jobs/{id} การลบนี้มีผลกระทบดังต่อไปนี้:

    • หลังจาก endpoint ถูกลบออก job.stream_results() และ job.interim_results() จะถูกลบออกจาก client qiskit-ibm-runtime

    • เมธอดเพิ่มเติม เช่น job.result() ในปัจจุบันใช้ endpoint ที่ deprecate แล้ว อัปเกรดเป็น qiskit_ibm_runtime 0.25 หรือใหม่กว่าก่อนที่ endpoint จะถูกลบเพื่อหลีกเลี่ยงการหยุดชะงัก
