ตั้งค่า QCSC-Prefect บนคลัสเตอร์ Slurm

คู่มือนี้เตรียม login node ของคลัสเตอร์ Slurm ให้เป็นโฮสต์เวิร์กโฟลว์ของ qcsc-prefect บทแนะนำ qcsc-prefect SQD เริ่มต้นจากผลลัพธ์ของคู่มือนี้

หลังจากทำคู่มือนี้เสร็จ คุณจะมีรายการต่อไปนี้:

รายการที่ไหนเนื้อหา
~/venv/qcsc-hostLogin node ซึ่งเป็นโฮสต์เวิร์กโฟลว์Prefect แพ็กเกจ qcsc-prefect และคำสั่ง qcsc-qrmi
~/venv/qcsc-nodeCompute node ภายใน Slurm jobQRMI worker: QRMI พร้อมคำสั่ง task_runner และ qcsc-prefect-qiskit
qrmi-runtimePrefectblock ที่ระบุ instance และ QPU ของ IBM Quantum® ของคุณ
qrmi_config.jsonLogin node และ compute nodeAPI key ของ IBM Cloud® instance และ backend ของคุณสำหรับ QRMI

รันแต่ละคำสั่งในเทอร์มินัลบน login node เว้นแต่ขั้นตอนจะระบุไว้เป็นอย่างอื่น

สิ่งที่ต้องมีก่อน​

  • คลัสเตอร์ Slurm ที่มี OpenMPI, PMIx และ QRMI SPANK plugin ซึ่งผู้ดูแลคลัสเตอร์ เป็นผู้ติดตั้ง คู่มือต่อไปนี้อธิบายส่วนประกอบเหล่านี้:

    • Quantum resource management interface (QRMI)

    • SPANK plugin สำหรับ QRMI

    • คู่มือผู้ใช้ SPANK plugin

  • home directory และ work directory ที่ login node และ compute node มองเห็นที่ absolute path เดียวกัน

  • การเข้าถึง HTTPS ขาออกไปยัง GitHub, PyPI, IBM Quantum และ Prefect Cloud จาก login node และไปยัง IBM Quantum จาก compute node

  • บัญชี IBM Quantum Platform ที่มี IBM Cloud API key และอย่างน้อยหนึ่ง instance

  • บัญชี Prefect Cloud หรือ Prefect server ที่คุณโฮสต์เอง

  • Git, คอมไพเลอร์ C และ C++, CMake, BLAS, LAPACK และ MPI บนคลัสเตอร์ สำหรับการ build solver ของบทแนะนำ

หมายเหตุ

ตัวอย่างใช้ Slurm partition normal และ compute node c1 และ c2 ให้แทนที่ ด้วยชื่อในคลัสเตอร์ของคุณ

ขั้นตอนที่ 1: ล็อกอินเข้า login node​

# Run in a terminal on your computer.
ssh <user>@<login-node>

ขั้นตอนที่ 2: ติดตั้ง uv​

ติดตั้งตัวจัดการแพ็กเกจ uv และตรวจสอบการติดตั้ง:

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv --version

ขั้นตอนที่ 3: ตั้งค่า path และสร้าง work directory​

คู่มือนี้และบทแนะนำใช้ตัวแปรสภาพแวดล้อมสองตัว:

ตัวแปรตัวอย่างวัตถุประสงค์
QCSC_PREFECT$HOME/qcsc-prefectcheckout ของ qcsc-prefect
QCSC_WORK_DIR/shared/work/qcsc-prefectwork directory ของ solver job และ QRMI job

ทั้งสอง path ต้องอยู่บนพื้นที่เก็บข้อมูลที่ compute node มองเห็นที่ absolute path เดียวกัน ถ้า คลัสเตอร์ของคุณไม่มีไดเรกทอรี /shared ให้เลือก shared path อื่น

ตั้งค่าตัวแปรและสร้าง work directory ตั้งค่าตัวแปรอีกครั้งในทุก shell ใหม่ ก่อนทำตามบทแนะนำ:

export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR=/shared/work/qcsc-prefect
mkdir -p "$QCSC_WORK_DIR"

หากต้องการตั้งค่าตัวแปรในทุก shell ใหม่โดยอัตโนมัติ ให้เพิ่มลงใน ~/.bashrc:

# Optional
echo "export QCSC_PREFECT=$QCSC_PREFECT" >> ~/.bashrc
echo "export QCSC_WORK_DIR=$QCSC_WORK_DIR" >> ~/.bashrc

ขั้นตอนที่ 4: Clone qcsc-prefect​

Clone repository และ check out release tag เช่น v0.3.1:

git clone https://github.com/qiskit-community/qcsc-prefect.git "$QCSC_PREFECT"
cd "$QCSC_PREFECT"
git checkout v0.3.1

ขั้นตอนที่ 5: สร้างสภาพแวดล้อมเวิร์กโฟลว์​

สร้างสภาพแวดล้อมเวิร์กโฟลว์ด้วย Python 3.12 แล้วเปิดใช้งาน:

uv venv ~/venv/qcsc-host -p 3.12
source ~/venv/qcsc-host/bin/activate

ติดตั้งแพ็กเกจ qcsc-prefect ตัวเลือก --no-deps จะคงการ pin เวอร์ชันที่ตรงกันระหว่างแพ็กเกจของ checkout ไว้ บทเรียนนี้ติดตั้งตัว workflow เอง:

cd "$QCSC_PREFECT"
uv pip install --no-deps \
  -e packages/qcsc-prefect-core -e packages/qcsc-prefect-adapters \
  -e packages/qcsc-prefect-blocks -e packages/qcsc-prefect-executor \
  -e 'packages/qcsc-prefect-qiskit[slurm]'

ตรวจสอบว่าคำสั่งต่าง ๆ ใช้งานได้:

which prefect qcsc-qrmi

เปิดใช้งาน ~/venv/qcsc-host ในทุก shell ใหม่บน login node

ขั้นตอนที่ 6: เข้าสู่ระบบ Prefect​

เข้าสู่ระบบ Prefect Cloud เลือก Paste an API key วาง Prefect Cloud API key แล้วเลือก workspace ของคุณ:

prefect cloud login

ตรวจสอบการเชื่อมต่อ ผลลัพธ์จะแสดง PREFECT_API_URL และ workspace ของคุณ:

prefect config view
ทางเลือก: ใช้ Prefect server ของคุณเอง

ข้ามหมายเหตุนี้ได้ถ้าคุณใช้ Prefect Cloud หากต้องการใช้ Prefect server ของคุณเองแทน Prefect Cloud ให้ทำตาม How to run and access a Prefect server on a Slurm login node แล้วตั้งค่าที่อยู่ของ server แทน <server-host>:

# Optional: only for your own Prefect server
prefect config set PREFECT_API_URL=http://<server-host>:4200/api

ขั้นตอนที่ 7: เก็บ credentials ของ IBM Quantum​

รัน qcsc-qrmi login หลังจากเข้าสู่ระบบ Prefect เพราะคำสั่งนี้จะบันทึก block qrmi-runtime:

qcsc-qrmi login

ตอบ prompt ต่าง ๆ:

  1. วาง IBM Cloud API key ของคุณ key จะไม่แสดงบนหน้าจอ

  2. กด Enter เพื่อใช้ทุก instance

  3. ใส่หมายเลขของ instance เริ่มต้น ในตัวอย่างต่อไปนี้คือ 1

  4. ใส่หมายเลขหรือชื่อของ backend เริ่มต้น ในตัวอย่างต่อไปนี้คือ 4 (ibm_kingston)

คำสั่งนี้ยังพิมพ์หมายเหตุเกี่ยวกับ compute node และบรรทัด [qrmi] สำหรับ sqd_blocks.toml ซึ่งตัวอย่างละไว้ (...) คุณไม่จำเป็นต้องใช้บรรทัด [qrmi] เพราะ workflow อ่าน instance และ backend จาก block qrmi-runtime

คำสั่ง qcsc-qrmi มี subcommand ดังต่อไปนี้:

คำสั่งวัตถุประสงค์
qcsc-qrmi loginเก็บ API key, instance และ backend แล้วบันทึก block
qcsc-qrmi refreshค้นหา instance และ backend อีกครั้งด้วย key ที่เก็บไว้
qcsc-qrmi listพิมพ์ instance และ backend โดยไม่แสดง key
qcsc-qrmi checkตรวจสอบว่า instance ของ block ใช้ backend ของมันได้

ติดตั้งไฟล์บน compute node​

SPANK plugin อ่าน qrmi_config.json บนแต่ละ compute node จาก path ใน plugstack.conf ซึ่งมักเป็น /etc/slurm/qrmi_config.json ขอให้ผู้ดูแลคลัสเตอร์ของคุณ ติดตั้ง ~/.qiskit/qrmi_config.json ของคุณที่ path นั้น ติดตั้งอีกครั้งหลังจากทุกครั้งที่รัน qcsc-qrmi login หรือ qcsc-qrmi refresh

ตั้ง Session Mode ของ block qrmi-runtime เป็น batch ไว้ตามเดิม เพราะ SPANK plugin จะขอใช้ QPU ใน batch mode

ขั้นตอนที่ 8: สร้าง environment สำหรับ compute node​

QRMI worker รันบน compute node ใน environment ของมันเอง สร้างจาก checkout เดียวกัน ตัวเลือก --python จะทำให้ ~/venv/qcsc-host ยังคงเปิดใช้งานอยู่:

cd "$QCSC_PREFECT"
uv venv ~/venv/qcsc-node -p 3.12
uv pip install --python ~/venv/qcsc-node/bin/python "qrmi[ibm]"
uv pip install --python ~/venv/qcsc-node/bin/python -e packages/qcsc-prefect-qiskit

แพ็กเกจ qrmi[ibm] ให้คำสั่ง task_runner บทเรียนนี้เพิ่ม SQD compilation hook ลงใน environment นี้ และใช้ ~/venv/qcsc-node/bin/python เป็น python_executable ของ sqd_blocks.toml

ตรวจสอบ instance และ backend ที่เก็บไว้ คำสั่งนี้จะไม่พิมพ์ key:

qcsc-qrmi list
# Output

ตรวจสอบว่า instance เริ่มต้นใช้ backend เริ่มต้นได้:

qcsc-qrmi check
# Output
premium-instance (premium, us-east) can use ibm_kingston.

ตรวจสอบว่า Slurm รันงานบน compute node ทั้งสองได้ รวมถึงเมื่อใช้ PMIx:

srun -N2 hostname
srun -N2 --mpi=pmix hostname
# Output of each command
c1
c2

ตรวจสอบ environment ของ compute node และ work directory บน compute node คำสั่งแรก จะไม่พิมพ์อะไรเลยเมื่อ import สำเร็จ:

srun -N1 ~/venv/qcsc-node/bin/python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker"
srun -N1 ls ~/venv/qcsc-node/bin/task_runner
srun -N1 ls -ld "$QCSC_WORK_DIR"
